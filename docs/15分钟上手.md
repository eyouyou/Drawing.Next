# 15 分钟上手

三级,每级 5 分钟左右,越往后越接近引擎内部。只想在图上加个指标,做完 L1 就够了。

| 级别 | 你要做的事 | 写不写代码 |
|------|-----------|-----------|
| **L1** | 在 Demo 的蓝图 JSON 里加一个节点,主图多出三条均线 | 不写 |
| **L2** | 写一个 C# 类实现两个指标,蓝图按名字引用 | 一个类 + 一行注册 |
| **L3** | 自定义 Trait + Layer,自己决定怎么画 | 一组类(看懂范例即可) |

遇到生词查 [术语表](./术语表.md)。本文用到的代码和 JSON 都在 [`Hevo.Charting.Tests/DocSamples/`](../Hevo.Charting.Tests/DocSamples),由测试 `DocSampleTests` 保证能跑通。

## 准备(一次性)

- Windows + 支持 WPF 的 .NET 8 SDK。
- 首次编译 Demo 会自动下载嵌入式 Python 3.12 + numpy 到仓库根的 `Python312/`(约 30 秒,需要联网;失败可手动跑 `scripts/setup-python.ps1`)。

```bash
dotnet run --project Hevo.Drawing.LowCodeDemo -c Debug
```

窗口打开后切到 **「Dashboard 编辑器」** 页签:左边是三个 cell(`main` 主图 K 线、`volume` 成交量、`strategy` 策略副图)的节点图,右边是 JSON 面板。点 **「运行 Dashboard」** 先看一眼原样。

## L1:蓝图 JSON 加指标(不写代码)

**目标**:主图叠加 SMA20 / 60 / 120 三条均线。指标用的是 Demo 自带的 Python 指标 `pine_triple_ma`(`Hevo.Drawing.LowCodeDemo/PyIndicators/pine_demo.py`)。

1. 点 **「导出 JSON」**,右侧面板出现整个 dashboard 的 JSON。
2. 找到 `"Id": "main"` 的 cell,在它 `"Blueprint"` → `"Features"` 数组末尾追加下面这个节点(注意给前一个节点补逗号):

   ```json
   { "TypeName": "PlotFeature",
     "Properties": {
       "IndicatorName": "pine_triple_ma",
       "Indicator":     "pine_triple_ma"
     },
     "InputBindings": {
       "InputPort":  "m_Closes",
       "YRangePort": "m_YRange"
     }
   }
   ```

   (同一份片段在 [`QuickStart/l1_triple_ma.json`](../Hevo.Charting.Tests/DocSamples/QuickStart/l1_triple_ma.json),测试会把它粘进 Demo 的 dashboard 做 DryRun 校验。)
3. 点 **「导入 JSON」**,再点 **「运行 Dashboard」**。主图上出现红 / 紫 / 青三条均线。

### 刚才发生了什么

- **节点** = 一个 Feature。`TypeName` 是类名,`Properties` 是它的参数。
- **连线靠端口名**:`InputBindings` / `OutputBindings` 里的字符串是黑板上的端口名,同名即连通。`m_Closes` 是主图数据源在 `OutputBindings` 里声明的收盘价列,`m_YRange` 是 `UniversalAutoScaleFeature` 算出来的 Y 轴量程。
- `PlotFeature` 调指标函数(这里是 Python 的 `pine_triple_ma`),按函数声明的 series 自己画出三条线。

### 出错了?

- 「运行 Dashboard」弹 **DryRun 失败**:看提示里的 `BP_` 诊断码,多半是 JSON 少逗号、`TypeName` 拼错或端口名对不上。
- 弹 **`PlotFeature.Indicator 委托未解析`**:Python 没起来(看控制台 `[DemoPythonHost]` 日志),或指标名拼错。
- 想改默认 dashboard:直接编辑 `Hevo.Drawing.LowCodeDemo/Assets/default_kline_dashboard.json` 后重新运行 Demo(它是嵌入资源,需要重新编译)。

## L2:用一个 C# 类实现指标

**目标**:用 C# 写两个指标 —— 单线的 20 日均线、三线的 20 日价格通道 —— 在蓝图里按名字引用。

### 1. 写指标类

在 `Hevo.Drawing.LowCodeDemo` 里新建 `MyIndicators.cs`,内容照抄 [`QuickStart/QuickStartIndicators.cs`](../Hevo.Charting.Tests/DocSamples/QuickStart/QuickStartIndicators.cs),把命名空间改成 `Hevo.Drawing.LowCodeDemo`、类名改成 `MyIndicators`。核心就两个方法:

| 方法 | 签名 | 交给谁 |
|------|------|--------|
| `[BlueprintHandler("qs_sma20")] Sma20` | `void (ReadOnlySpan<double> close, Span<double> result)` | `ComputeFeature`:算出**一根列**,再由 `LineSeriesFeature` 画 |
| `[BlueprintHandler("qs_channel")] Channel20` | `object (ReadOnlyMemory<double> close)`,返回 `{ "upper": double[], "middle": ..., "lower": ... }` | `PlotFeature`:一个节点**自己画多条线** |

签名规则:

- 零分配写法 `void F(ReadOnlySpan<double> 输入..., Span<double> result)`:框架给好输出缓冲,长度 = 输入长度,每个元素都要写;形参名就是蓝图里的输入名(最多 4 个输入)。数据量大、更新快的指标首选。
- 返回新数组 `ReadOnlyMemory<double> F(ReadOnlyMemory<double> close)` 也行,写起来更随意。
- 多条线返回字典,key 对应蓝图里 `Series[].Name`。

> Demo 工程锁 `LangVersion 9`:不要用 `required`、集合表达式 `[]`、file-scoped namespace 等新语法(原因见 [开发准则 §2](../Hevo.Charting/README.md))。

### 2. 注册(一行)

打开 `Hevo.Drawing.LowCodeDemo/DemoPythonHost.cs`,在 `EnsureInitialized` 里 `LoadEnabledIndicators();` 的下一行加:

```csharp
_registry.AutoDiscoverStatic(typeof(MyIndicators));
```

Demo 的蓝图运行时用的就是这个注册表,Python 指标和 C# 指标在里面平起平坐。(这个注册表随 Python 运行时一起创建,Python 起不来时 C# 指标也注册不上,先按 L1「出错了?」排查 Python。)

### 3. 在蓝图里引用

重新运行 Demo → 「Dashboard 编辑器」→「导出 JSON」,把 [`QuickStart/l2_csharp_indicators.json`](../Hevo.Charting.Tests/DocSamples/QuickStart/l2_csharp_indicators.json) 里的三个节点追加到 `main` cell 的 `Features`,「导入 JSON」→「运行 Dashboard」。主图出现橙色 SMA20 和青色价格通道。

三个节点分别是:

1. `ComputeFeature`:`"Compute": "qs_sma20"`,输入 `m_Closes`,输出写到新端口 `m_QsSma20`;
2. `LineSeriesFeature`:读 `m_QsSma20` 画线;
3. `PlotFeature`:`"Indicator": "qs_channel"`,`Series` 数组声明三条线的名字 / 类型 / 颜色 / 线宽;`SeriesOutputs.*` 把三条线也发布成端口,需要的话可以接进 `UniversalAutoScaleFeature` 的 `ValuePorts`,让 Y 轴量程包住它们。

**ComputeFeature 还是 PlotFeature?** 结果要给别的节点用(画线、再算、参与量程)→ `ComputeFeature`;一个指标自带多条线、只为了显示 → `PlotFeature`。

### 手写 Schema 的人

不走蓝图、用 C# 写 Schema 时,同样的方法直接塞进 `new ComputeFeature { Compute = ... }`;手写 Schema 里的轻量指标也可以挂在数据管线上(`.Compute`),两层的取舍见 [00 号文档 §5.2](../Hevo.Charting/00.架构协议与开发规范.md#52-步骤-b计算管线层-vs-feature-层)。

## L3:自定义 Trait + Layer

内置的折线 / 柱 / 散点 / 箭头不够用、要自己决定怎么画时,才需要这一级。范例是布林带(上中下三轨,中轨虚线),代码在 [`DocSamples/Bollinger/`](../Hevo.Charting.Tests/DocSamples/Bollinger):

| 顺序 | 文件 | 你要理解的一件事 |
|------|------|-----------------|
| 1 | `BollingerTraits.cs` | Trait 是给图层的**只读快照**(像组件的 props),纯 `record`,不含逻辑 |
| 2 | `BollingerMath.cs` + 计算接入(`BollingerPipelineState.cs` 或 `BollingerComputeFeature.cs`) | 计算只写黑板,不碰渲染;管线层 / Feature 层两种接入结果一致,默认用 `ComputeFeature` |
| 3 | `BollingerLayer.cs` | Layer 只做"取 Trait → 投影 → 录指令";`partial`,坐标只走 `ProjectToScreen`,点缓冲跨帧复用 |
| 4 | `BollingerFeature.cs` | Feature 在 `OnProject` 顶层 `UsePort` 读黑板,`PublishData` 发 Trait;`AddBollinger` 扩展方法供 Schema 调用 |
| 5 | `BollingerSampleSchema.cs` | 在 `DefineDataFlow` / `DefineFeatures` 里把以上组合起来;`SetBollingerVisible` 演示运行时增删 |

逐条规则和两层计算接入的对比表见 [00 号文档 §5](../Hevo.Charting/00.架构协议与开发规范.md#5-标准图层实现-sop-以布林带-bollingerband-为例)。改完跑:

```bash
dotnet test "Hevo.Charting.Tests/Hevo.Charting.Tests.csproj" --filter "FullyQualifiedName~DocSampleTests"
```
