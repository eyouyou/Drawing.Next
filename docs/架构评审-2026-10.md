# Charting 全面评审(2026-10)

范围:框架全部代码,分 6 块——Hook 体系、渲染、核心调度与交互、数据管线、低代码 / 蓝图、PythonNet + 代码分析 + DevTools。
基准:上游 `72725e2`(Hook 规则清理之后)。Hook 体系后续改动在分支 `claude/vigilant-jepsen-b956ad`(`505b97a`)上。

方法:每块由一个只读评审逐条顺着调用链读代码,不靠猜测;每块再人工抽查 1–2 条最严重的结论,都已核实(标 ✅)。
除 Hook 外各块都**没有编译或实跑复现**,像素、时序类结论是按代码推导的,修之前应先写失败测试。

## 总结论

**没有哪一块需要重新设计。** 主干是对的:黑板事务 + 纪元回收、时钟 + 脏集调度、一帧一把读锁、Phase 排序、像素对齐规则、双缓冲都经得起推敲。
问题集中在三类:

1. **跨锁 / 生命周期**:两处死锁、两处订阅或数据源不随 schema 释放、Transact 热插拔清理不全。
2. **同一规则多处实现、已经走偏**:坐标投影手写、位图后端的像素规则、蓝图里 "JsonElement → 值" 的转换各写一份。
3. **分析器宣称的规则拦不住**:HEVO001 / 002 / 007 按字符串匹配语法,关键情况都漏报。
