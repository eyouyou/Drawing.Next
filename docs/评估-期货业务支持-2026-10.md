# 框架对期货业务的支持评估(2026-10)

目标：判断本框架能不能撑起期货终端的全部图表(参照 FuturesPC 现有功能与 hevo.drawing 已迁的业务层),撑不住的地方在框架里怎么调整。下一步再用 Newhsetup 的全部图表(含图上交易)冲击框架。

- **基准**:WPFDrawing.Next `main` d2f4bd4;业务层 hevo.drawing `master` 9ac9a9c。
- **方法**:静态阅读加逐项对照代码，每条都带出处。没有运行。
- **前提**:按"框架改动开关规则",嵌进现有模块的新行为一律加配置、默认保持原行为;独立模块靠装不装 Feature 控制。

## 结论

底子够用：逐帧判脏、冷热分层、交互层隔离、填充 / 虚线 / 裁剪原语、指针路由器(区域 + 优先级 + 捕获 + Esc)、多 pane 联动和运行期增删副图、双 Y 轴、镜像百分比轴、后台线程推数据，都已经能用。

撑不住的集中在六处，业务层要么绕得很别扭，要么绕不过去:

1. **数据变化没有语义**。黑板只知道"变了",不知道是追加、改末根、前插还是整段替换。视口靠长度差猜，翻页前插时视口在中段会跳;切周期回不到首屏布局;缩放记忆做不了;公式引擎的 FullReset / ReplaceLast / Append 包没地方接;增量指标会重复计入末根。
2. **切换 / 列式存储在业务层**。`SwitchAsync(ctx, ResetPolicy)`、`FetchReason`、列式 K 线存储都是 Foundation 自己写的，框架里没有，不走 Foundation 的屏幕会重踩。
3. **K 线样式只有实心两色**。8 种样式只能做 2–3 种，没有平盘色、不能按昨收比较。空心 / 美国线 / 影线随涨跌色已在分支 `claude/candle-style-variants-4947c0`(0415ba3)写好，一直没合。
4. **交易线和标注缺框架件**。`DraggableLineFeature` 一个 Feature 一条线、标签格式固定、拖动不按最小变动价位取整;没有参考线 / 最新价线 / 价格笼 / 区间阴影;没有宿主无关的右键菜单请求。
5. **文字测量与控件放置**。录制阶段量不了字，高低点标记、价格标签、浮窗避让、文字画线都只能估。
6. **运行期切换**。换肤没有缓存失效和整屏重录入口;对数 / 百分比坐标只能装配时定，运行期换了没人重算，且 `LogCandleMode` 与 `CandleMode` 对齐方式不同(差半根)。

另有一批"写错不报错"的旧问题仍在(私有 HitPort、不 Seed 比例尺就黑屏、两套视口默认值),新屏幕不经 Foundation 就会踩。

## 调整计划

按"先改卡得最多的、同一处的改动放一个窗口"排。每个窗口在 `main` 上做，做完同步 hevo.drawing,Foundation 删掉被框架取代的自写实现。

| 窗口 | 内容 | 验收 |
|---|---|---|
| 1 数据变化与视口 | `DataChange` 贯通黑板 / 快照 / `WatchAsync`;视口按变化处理 + 运行期视口意图;上提 `SwitchAsync` / `FetchReason` / 列式 K 线存储;`ctx.PortVersion`;增量指标按变化推进;刷新与切换分道 | 翻页前插视口不跳(中段也不跳);切周期回首屏且可恢复缩放;tick 改末根只重录热层;麦语言三种包都能接;Foundation 的 KLineSourceBase 改为薄封装 |
| 2 K 线与渲染 | 合入 K 线样式分支并补齐 8 种、平盘色、比较基准;调色板按下标;`BreakOnNaN`;`AddLine` 虚线;Band 序列;`MeasureText`;公开 `PixelSnap`;对数模式修正 + 比例尺可运行期切换;统一换肤入口 + `RequestRedraw` | 像素回归覆盖 8 种样式;换肤后所有图层重录;对数 / 百分比运行期切换十字线不偏 |
| 3 交互与标注 | 参考线 / 最新价线;控件放置与避让;宿主无关的右键菜单请求;按键路由扩展;时间锚点投影;公开自定义命中 + 描边矩形 / 椭圆;首帧图层保证 | Foundation 的 PriceLine / FloatWindow 改用框架件;画线基座可承载 43 种工具 |
| 4 交易线族 | 依"图上交易"盘点结果设计 | 见下一步 |
| 5 时间轴与收尾 | 秒级刻度;日 / 时段分隔线、区间阴影;夜盘测试;静默失效那批(HitPort / Seed / 视口默认值);自动释放选项 | 新屏幕不经 Foundation 也不会黑屏 / 不联动 |

窗口 1 的影响最大，几乎所有屏幕都经过视口和数据源;它对现有屏幕的默认行为必须保持不变(没有 `DataChange` 的发布方按原来的长度差逻辑走)。
