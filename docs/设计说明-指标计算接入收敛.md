# 设计说明:指标计算接入写法收敛

> 状态:**已定方案,已实施**。
> 背景:同一个指标(以布林带为例)原先有三种接入写法:管线 `.Compute`、`ComputeFeature` + 委托、自定义 `ComputeNodeFeature` 子类。现按"两层"收敛,见 [00 号文档 §5.2](../Hevo.Charting/00.架构协议与开发规范.md#52-步骤-b计算管线层-vs-feature-层) 与 `Hevo.Charting.Tests/DocSamples/Bollinger/`。

## 1. 判断

- **管线层 ① `.Compute` 与 Feature 层 ② `ComputeFeature` 不算重合**,两者都保留:
  - ① 的价值:价格与指标在同一次黑板提交里出现,没有"价格新、轨道旧"的中间帧。② 做不到。
  - ② 的价值:蓝图、Python、C# 共用同一个 handler。① 做不到。
- **② 与"自定义 `ComputeNodeFeature` 子类"重合**:
  - 后者唯一的实质理由是"多输出零分配"。
  - 但仓库里 `ComputeFeature` 多输出与自定义子类,除测试 / 示例外**零使用**,这个需求目前不成立。
- **基类原先的名字和位置不对**:
  - 它是 `Features.ComputeFeature` / `IncrementalComputeFeature` 的基类,却放在 `LowCode.Designer.GraphViewer.Wrappers`,核心 Feature 反向依赖设计器包装层的命名空间。
  - `ComputeNodeFeature` 这个名字也让人以为它是"第三种写法"。

## 2. 决定

### 2.1 暂不新增多输出零分配签名

不加 `ComputeIntoOutputs` / `OutputOrder`。出现真实的"多输出 + 大数据量 + 高频"指标时再加。

取证办法(未做,需要时再做):把 `ComputeFeature` 里 DEBUG 下的 `HeavyCallMeter` 迁移提示扩展到多输出(返回字典)路径。现在它只统计单输出"每次返回新数组"的 handler。扩展后,结果 ≥ 10625 个 double 且 1 秒内算了 ≥ 5 次的多输出指标会打日志,有日志就说明需求成立。

### 2.2 `ComputeNodeFeature` → `Hevo.Charting.Features.ComputeFeatureBase`

- 改名并挪到 `Hevo.Charting/Features/ComputeFeatureBase.cs`,不留过渡类型。
- 原 `LinkWrappers.cs` 只剩这一个类,已删除。"Link DSL ↔ 蓝图"注释头随基类搬到新文件。
- 仍为 `public abstract`:`ComputeFeature`、`IncrementalComputeFeature` 派生自它,业务派生 `IncrementalComputeFeature`,进阶场景也需要直接继承它。
- 已确认没有按字符串名查这个类型的地方:
  - `FeatureCategoryRegistry` 用 `Register<T>` 泛型登记、按继承链匹配;
  - DryRun 用 `IsAssignableFrom`;
  - 蓝图 / `ComponentRegistry` 按具体类的短类名 `TypeName` 解析,抽象基类不出现在 JSON 里。
- 已有蓝图不受影响。

### 2.3 文档按"两层"讲

- 默认用 **② Feature 层 `ComputeFeature`**。手写 Schema 里的轻量指标可用 **① 管线层 `.Compute`**。
- **进阶**:现成的不够用时,才自己继承 `ComputeFeatureBase` 写计算 Feature。适用场景:
  - 非 `double` 列或标量输出;
  - 要强类型参数;
  - 要跨调用保留状态(先看 `IncrementalComputeFeature` 够不够用)。
- 示例:
  - `BollingerComputeNode` 保留为进阶示例,注释写明"能用 ComputeFeature 就别写这个";
  - `BollingerComputeFeature` 维持返回字典的版本,并注明有分配。

## 4. 不在本次范围

- 两套缓冲池职责不同,暂不合并:
  - `ColumnPublisher<T>`:单写者、同步;
  - `ResultBufferPool`:后台调用、可 Abandon。
- `ComputeFeature` 没有通用参数通道:C# 靠闭包,蓝图靠把参数写进 handler 名(如 `boll_20_2`)。要在蓝图里改周期时,再单独设计 `Parameters`。
