## 0. 一页结论

**业务 Feature 在 `OnProject` 里声明"我画的东西哪里能点、能拖"(命中区域,跟 Trait 一样随帧发布),框架在按下时按区域做命中和仲裁,赢家拿到整个手势:框架管捕获、丢失捕获、Esc 取消、悬停光标、拖动阈值;回调里只有框架自己的类型。没命中任何区域,走现在的平移 / 框选 / 双击复原,行为一字不改。**

```csharp
// 声明(OnProject 里,跟发布 Trait 同一处)
ctx.Gestures().Publish(GestureRegion.HLine(id: 0, y, left, right)
    .Accepts(GestureAccepts.Drag).Cursor(PointerCursor.SizeNS));

// 响应(Feature 实现一个接口,一个方法)
GestureReply OnGesture(in GestureEvent e)   // e.Phase = Press / Begin / Move / End / Cancel / Click / Hover…
```

跟 `IPointerClaim` 比,五个问题各自怎么解决:

| 9f24282 的问题 | 本方案 |
|---|---|
| ① 只认领 MouseDown,Move / Up / 捕获 / 丢捕获 / Esc 全留给业务 | 框架管整个手势生命周期:Press → Begin → Move* → End,或 Click,或 Cancel(丢捕获 / Esc / 热拔 / 被平移抢走)。业务不碰 WPF 事件 |
| ② 要 `ListFeatures().OfType<ChartInteractionFeature>()` 找实例,找不到静默失效,依赖装配顺序 | 不找任何实例。Feature 发布区域即参与,仲裁器挂在 `ChartCell` 上,有没有 `ChartInteractionFeature` 都工作 |
| ③ 按登记顺序仲裁 | 按命中 + 优先级档位 + 图层层级 + 距离仲裁,登记顺序只是最后一道平局规则 |
| ④ 契约里有 `MouseButtonEventArgs` | 契约只有 `HevoPoint`、`PointerButton`、`PointerModifiers`、`PointerCursor`;WPF 只出现在一个适配器文件里 |
| ⑤ 没有悬停光标、右键 | 区域自带光标;悬停进入 / 离开 / 移动回调;右键按区域分发 |

## 1. 背景与现状

### 1.1 现在的输入是怎么走的

- 框架内**只有** `ChartInteractionFeature` 处理手势(04 号文档 §K "唯一接 WPF 事件的 Feature")。它在 `OnCompose` 里订阅 ChartCell 上的冒泡事件:MouseDown `Features/ChartInteractionFeature.cs:240`、MouseUp `:297`、MouseLeave `:339`、MouseMove `:346`、MouseWheel `:378`、PreviewKeyDown `:390`、Manipulation `:411` / `:426`。
- 订阅走 `this.OnMouse(...)` → `WorkflowWPFEventExtension.OnUIEvent`(`WorkFlow/WorkflowWPFEventExtension.cs:17-47`)→ `element.AddHandler(routedEvent, handler)`(`WorkFlow/WorkflowWatchExtensions.cs:125`),两参数版本,不带 handledEventsToo。
- MouseDown 一进来先做"任意按下都要做的事":拿焦点 `:242`、停惯性 `:248`、武装 hover `:251`;然后三路分流:双击复原 `:254-266` → 框选 `:269-283` → 平移 `:286-293`,平移时 `CaptureMouse` `:293`。**不看是哪个键**,右键拖也会平移。
- hover 命中写 `PointerHitPort`(`:894-946`),下游 Crosshair / Tooltip 读它。
- 另有两处框架内 Feature 自己挂鼠标:`ElementPlotFeatureBase` 的 hover 命中(`Features/ElementPlotFeatureBase.cs:121-163`)和双击(`:166-173`,`ClickCount == 2`,跟图表的双击复原会同时触发);`CrosshairFeature` 只订 Enter / Leave 判断鼠标在不在本 cell(`Features/CrosshairFeature.cs:218-227`)。
- 框架里没有任何地方设置 `Cursor`(全仓 `Features/`、`Core/` 无 `.Cursor =`)。

### 1.2 业务原型(30642aa)做了什么、差在哪

`PointerGestureFeature` 在 ChartCell 上订 `PreviewMouseDown / Move / Up`、`LostMouseCapture`、`PreviewKeyDown`(handledEventsToo),认领时把 Preview 标 `Handled`。WPF 只在 Preview 没被 Handled 时才提升冒泡 MouseDown,图表这次按下根本不发生(原型 `RawMouseFidelityTests` 验证)。三条需求(价格线拖动、点两下画线、测量)都跑通,9 个真实输入测试全过。

原型自己列的限制:

1. 认领的按下停不了惯性(图表只在自己的 MouseDown 里停,`ChartInteractionFeature.cs:248`)。
2. `RequireClickToActivate` 时认领的按下不武装十字光标(`:251`)。
3. 多个业务手势之间先后 = Feature 装配顺序。
4. 每个业务手势 Feature 各挂 5 个路由事件,各自管 `_active`、捕获、Esc、丢捕获——底座类替它们做了,但底座本身就是"每个业务各写一遍"的东西。

### 1.3 IPointerClaim(9f24282)做了什么、为什么不合

在 `ChartInteractionFeature` 的 MouseDown 里、做完拿焦点 / 停惯性 / 武装 hover 之后,按登记顺序问 `IPointerClaim.TryClaim(HevoPoint, MouseButtonEventArgs)`,有人认领就不进分流、不抓鼠标。修好了原型的限制 1、2,但留下了评审指出的五个问题(见 §0 表)。本质是**只在框架的一个 if 里开了个口子**,手势还是业务自己用 WPF 拼出来的。

## 2. 目标与非目标

### 2.1 目标

1. 业务手势能稳定抢在内置平移 / 框选 / 双击复原之前,并且框架负责整个手势的生命周期(捕获、丢失捕获、Esc、热拔、阈值、点击 / 拖动区分)。
2. **声明式**:Feature 在 `OnProject` 里随帧发布命中区域,跟发布 Trait 同一处、同一套"变了才发"的节奏;不找实例、不登记、不依赖装配顺序。
3. **按命中仲裁**:谁在指针下面、谁优先级高、谁画在上层,谁赢。
4. **契约不含 WPF 类型**,为交互层去 WPF 依赖(将来可能迁 Avalonia)铺路。
5. 悬停光标、悬停进入 / 离开、右键、双击都有统一入口。
6. 屏幕 ↔ 值的换算(`ScreenToDomain` / `ScreenToValue`)由框架提供,事件里能用,口径跟命中那一帧一致(G11 第二项)。
7. 事件里写入能唤醒本 Feature(G11 第三项):沿用现有"写自己 UsePort 过的端口"机制,给出约定和一个小 helper,不另造重绘入口。
8. 没有任何区域时,行为与现在**逐字节一致**(同样的事件、同样的锁、同样的写入顺序)。

### 2.2 非目标

- 不做画线框架本身(文档模型、40 种工具、吸附、撤销、持久化)。本方案只给画线框架提供输入底座。
- 不做跨 cell 的手势(从主图拖进副图)。每个 ChartCell 独立仲裁。
- 第一期不让业务区域认领**滚轮**和**触屏 Manipulation**(仍归缩放 / 平移)。
- 不做键盘焦点导航 / 选中对象的键盘编辑(Delete 删画线等)——列为开放问题。
- 不改 `PointerHitPort` 的语义和唯一写者(04 号文档 §K)。
- 第一期不把 `ChartInteractionFeature` 自身的 WPF 订阅搬走(放到第二期,见 §12)。

## 4. API 面

所有新类型放 `Hevo.Charting.Interaction` 命名空间(新目录 `Hevo.Charting/Interaction/`)。框架侧可用 `record struct`(`Hevo.Charting/README.md:30`),但业务侧锁 `LangVersion 9`、不能用 `with`(`README.md:29,38`),所以**对外的值类型一律用普通 `readonly struct` + 工厂方法 / 链式 `WithXxx`**,业务不需要 `with`、`required`、集合表达式。

### 4.2 投影快照 `ChartProjection`(G11 的 ScreenToDomain / ScreenToValue)

把业务原型的 `ChartGeometry` 提进框架,改名 `ChartProjection`。它是一帧的 `(PlotArea, DomainRange, ValueRange, ScaleStrategyTrait)` 快照,值类型、无分配。

```csharp
public readonly struct ChartProjection
{
    public HevoRect PlotArea { get; }
    public RealRange DomainRange { get; }   // Viewport.ActiveRange
    public RealRange ValueRange { get; }    // 调用方给的 Y 量程
    public bool IsValid { get; }

    public double ScreenToDomain(double x);  // 只走 DomainScale.Denormalize(Abstractions/Scale.cs:113)
    public double ScreenToValue(double y);   // 只走 ValueScale.Denormalize
    public float DomainToScreenX(double domain); // 只走 CoordinateExtensions.ProjectDomainToScreen(Core/CartesianCoordinate.cs:151)
    public float ValueToScreenY(double value);   // CoordinateExtensions.ProjectValueToScreen(:174)

    public bool Contains(HevoPoint p);

// OnProject 里取:内部 UsePort(Viewport.ActiveRange) + UsePort(valueRangePort) + Shared().Use<ScaleStrategyTrait>() + PlotArea
public static (ChartProjection Projection, bool IsChanged) UseProjection(this FeatureContext ctx, DataPort<RealRange> valueRangePort);
```

为什么要调用方给 Y 量程:Y 量程是图层作用域的 `YAxisTrait`(`Core/CartesianCoordinate.cs:32`,各 Feature 自己 `UpdateYAxis`,如 `Features/CandleFeature.cs:177`),一张图可以有多根 Y 轴,框架没有"唯一的价格量程"。Feature 画在哪根轴上,就传哪根轴的量程端口。

`UseProjection` 里只有 `UsePort` 和 `Use<T>`,不含 `UseMemo`,放进扩展方法不违反 HEVO008(AGENTS.md "`UsePort` 可以放进分支";`UseMemo` 才要求直接写在 `OnProject`)。实现时要确认分析器不对 `UsePort` 的 helper 报错——见开放问题 Q7。

### 4.4 发布:`ctx.Gestures()`

```csharp
public readonly struct GesturePublisher
{
    public void Publish(GestureRegion region);                       // 单个
    public void Publish(IReadOnlyList<GestureRegion> regions);       // 多个(画线文档变了才 new 一份)
    public void Clear();                                             // 本 Feature 不再有区域

// FeatureContext 上
```

- **语义 = Trait**:按 Feature 作用域存一份"本 Feature 当前的区域表",跟 `ctx.For(layer).PublishData` 一样写进草稿、在 `RenderContext.SubmitSync`(`Core/RenderContext.cs:194`,帧尾 `Core/ChartCell.cs:636`)跟图层 Trait 同一刻提交。于是**命中用的几何 = 屏幕上那一帧画出来的几何**,不会出现"线已经画到新位置、命中还在旧位置"。
- 实现可以直接复用 Trait 机制:框架给每个发布区域的 Feature 挂一个不可见的作用域袋(或者一个 `GestureRegionsTrait : IVisualTrait` record 放 Feature 作用域),对业务只暴露 `ctx.Gestures()`。
- 区域表是"每帧发布的不可变记录",属于 0-GC 规则的豁免项(`00 号文档:139`)。Feature 只在自己脏的时候才投影(`Core/ReactiveSchema.cs:627-637`),所以区域表也只在变的时候重发。
- 发布了区域的 Feature **必须实现 `IGestureHandler`**,Debug 构建下首次 `Publish` 时断言(跟 `AssertProjecting` 同一风格,`Core/ChartFeature.cs:72`)。回调目标就是发布者本身,**不需要任何登记 / 查找**。
- `ctx.Gestures()` 只能在 `OnProject` 帧路径里调(复用 `AssertProjecting`)。

### 4.5 回调:`IGestureHandler`

```csharp
public enum GesturePhase
{
    Press,        // 按下命中本区域;只有这一相的返回值有意义(Accept / Decline)
    Begin,        // 移动越过拖动阈值,拖动正式开始(Accepts 含 Drag)
    Move,         // 拖动中
    End,          // 正常松开
    Cancel,       // 被打断,见 Reason
    Click,        // 未越过阈值就松开(Accepts 含 Click)
    DoubleClick,  // 第二次按下(Accepts 含 DoubleClick)
    ContextClick, // 右键按下并松开(Accepts 含 ContextClick)
    HoverEnter, HoverMove, HoverLeave,   // 没有手势进行时,指针在本 Feature 的最高优先区域上进出 / 移动
    Escape,       // 没有手势进行时按 Esc,且本 Feature 有已发布的 Modal 区域(§6.6)
}

public enum GestureCancelReason { None, Escape, CaptureLost, OwnerRemoved, ChartUnloaded, SupersededByPan, OtherButton }

public enum GestureReply { Accept, Decline }

public readonly struct GestureEvent
{
    public GesturePhase Phase { get; }
    public GestureCancelReason Reason { get; }
    public int RegionId { get; }
    public int RegionPart { get; }
    public PointerInput Input { get; }        // 本次事件
    public HevoPoint PressPosition { get; }   // 本手势按下点
    public ChartProjection Projection { get; } // 最近一次提交的投影(见 §7.2)
    public DataBlackboard Board { get; }
}

public interface IGestureHandler
{
    GestureReply OnGesture(in GestureEvent e);
}

// 写自己的端口并唤醒自己的便捷方法(最小锁作用域,同原型 PointerGestureFeature.Write)
public static class GestureEventExtensions
{
    public static void Write<T>(this in GestureEvent e, DataPort<T> port, T value);
}
```

**为什么是一个方法 + 相位枚举,而不是 Begin / Move / End / Cancel 四个方法**:

- 业务侧 `LangVersion 9` 可以用接口默认方法(C# 8),但默认方法的存在会让"漏写 Cancel"变成静默的;一个 `switch` 漏了某个相位,读代码一眼可见。
- 以后加相位(比如第二期的键盘、触屏)不破坏已有实现。
- `in GestureEvent` 传值类型不分配。

备选是四个方法的抽象基类 `GestureFeature : ChartFeature`(相当于把原型的 `PointerGestureFeature` 收进框架)。缺点是占掉业务 Feature 唯一的基类位置(画线工具宿主可能要继承别的基类)。**推荐接口**,另外在 DocSamples 里给一个基类范例供想要的人抄。见开放问题 Q1。

## 5. 命中模型

### 5.1 谁提供几何、在什么坐标系

- **画东西的 Feature 提供**。它最清楚自己画了什么,也已经在 `OnProject` 里把值投影成了屏幕坐标(给图层用的同一份)。框架不反推图层录制的指令。
- 坐标系:`ChartCell.DrawingCanvas` 的 DIP 坐标,跟内置 hover(`ChartInteractionFeature.cs:348`)、业务原型(`PointerGestureFeature.Position`)、`ElementPlotFeatureBase`(`Features/ElementPlotFeatureBase.cs:125`)同一口径。
- 区域是**屏幕坐标**而不是值坐标:命中只做像素距离判断,不依赖它画在哪根 Y 轴上;视口一变,Feature 因为 `UsePort(ActiveRange)`(在 `UseProjection` 里)被唤醒、重发区域。

### 5.2 容差

- 线类(HLine / VLine / Segment / Polyline)按点到线段距离 ≤ `Tolerance`;默认 4px(跟原型 `PriceLineFeature.HitTolerance` 一致)。面类(Rect / Circle / PlotArea)按包含,`Tolerance` 向外扩。
- 将来接触屏 / 高 DPI 时,框架可以统一放大容差,业务不用改。

### 5.3 z 序与优先级

一次按下或悬停,框架按下面的顺序挑出唯一赢家:

1. **筛**:形状命中;`Button` 匹配;`RequiredModifiers` 是当前修饰键的子集;`Accepts` 里有这次输入可能产生的相位(左键按下需要 Click / Drag / DoubleClick 之一,右键按下需要 ContextClick)。
2. **`Priority` 高者优先**(档位见 §4.3)。
3. 同档位:**所属 Feature 的最高图层层级高者优先**(`ChartLayerType`:Overlay 40 > Interaction 30 > Selection 20 > Main 10,`Core/ChartCell.cs:42-64`),即"画在上面的先命中",对应 zrender 的 z。
4. 同层级:**距离近者优先**(线类按点到线距离,面类算 0)。
5. 再平:同一 Feature 内后发布的优先(后画的在上);不同 Feature 按 `Phase` 再按装配顺序。这是唯一用到顺序的地方,只是平局规则。

被选中的候选收到 `Press`;返回 `Decline` 就按上面的顺序试下一个;全部 Decline 或没有候选 → 兜底(内置平移 / 框选 / 双击复原)。

**跟图层的关系**:区域不属于图层,只借用"本 Feature 挂的图层里最高的 `Level`"做平局。Feature 没有图层时按 `Main` 算。

### 5.4 每次鼠标移动的代价

- **没有任何区域**:仲裁器在 Preview 处理器里看一眼"区域总数 == 0"就返回,不做命中、不标 Handled。这是兼容性的硬要求(§10)。
- **有区域、没在手势中**:悬停命中要做(为了光标和 HoverEnter/Leave)。框架把所有 Feature 的区域在提交时拍平成一个数组并算好包围盒,移动时先比包围盒再算距离。100 条画线 × 3 个部位 = 300 次包围盒比较 + 少量线段距离,微秒级,跟一帧录制比可以忽略。区域数到上千时再上网格索引,第一期不做。
- **手势进行中**:不做命中,只把输入转发给赢家。
- 移动事件里不分配:命中结果是值类型,候选排序用跨帧复用的数组。

### 5.5 多图、联动副图

- 仲裁器**每个 ChartCell 一个**。区域只在发布它的 cell 内有效;捕获只抓本 cell。
- 联动 dashboard 里每个 pane 是独立 schema / 独立 board,共享端口靠镜像桥(`Linked/LinkedChartContext.cs:60-78`)。价格线拖动写自己的价格端口,如果业务把这个端口登记为镜像(`RegisterMirror`,`:86`),别的 pane 自动跟,仲裁器不用知道联动。
- 跨 pane 的手势(在主图按下、拖到副图)不支持(非目标)。副图里的业务手势照常工作,因为仲裁器不依赖 `ChartInteractionFeature`(LinkedPane 会摘掉一部分交互 Feature,见 `Linked/LinkedChartDashboard.cs:14-15`)。

## 6. 仲裁与手势状态机

### 6.1 状态机

```
            按下命中且 Accept
  Idle ─────────────────────────► Pressed ──移动 ≥ 阈值且 Accepts Drag──► Dragging ──松开──► End ─► Idle
   │                                 │  │                                  │
   │                                 │  └─松开(未过阈值)──► Click / DoubleClick ─► Idle
   │                                 └─移动 ≥ 阈值且只接受 Click──► Cancel(SupersededByPan) ─► 内置平移(从按下点开始)
   │                                                                     │
   │       Esc / 丢捕获 / Feature 被卸载 / cell 卸载 / 另一个键按下 ─────────┴─► Cancel(原因) ─► Idle
   │
   └─按下未命中 / 全部 Decline ──► 内置分流(双击复原 → 框选 → 平移),与现在完全一致
```

- **拖动阈值**默认 4 DIP(对齐 WPF `SystemParameters.MinimumHorizontalDragDistance` 的默认值),可在 `InteractionOptions` 上配,不按区域配。
- `Accepts` 只有 `Drag` 的区域(价格线):Press 后框架**立即捕获**;过阈值发 Begin。松开时没过阈值,也发 `Click`(业务可以忽略)而不是 End——这样"按一下没拖"不会被当成一次改价。
- `Begin` 之前不发 `Move`。业务想在按下瞬间就有反馈(高亮),在 `Press` 里写自己的端口。

### 6.2 按下时的 Accept / Decline

Press 返回 `Decline` 表示"区域命中了,但这次不归我"(例:画线已锁定、价格线只读、业务状态不允许)。比"把区域撤掉再等一帧"及时,也不用为动态条件反复重发区域。对应 Flutter 识别器的 reject。

### 6.3 按键与修饰键

- 区域默认只接左键。右键按下命中 `Accepts` 含 `ContextClick` 的区域 → 松开时发 `ContextClick`(业务弹菜单);右键没命中 → 交给兜底。
- **现状提示**:兜底的平移不区分按键,右键 / 中键拖也平移(`ChartInteractionFeature.cs:240-293` 没有按键判断)。本方案不改这一点(兼容);是否改成"只左键平移"列为开放问题 Q5。
- 修饰键在 **按下时** 参与筛选(`RequiredModifiers`),之后每个 `Move` 带当时的修饰键,业务可以做"拖动中按 Shift 锁水平"。
- **跟框选的先后**:框选默认 Shift + 拖(`ChartInteractionFeature.cs:29`)。业务区域先于兜底仲裁,所以 Shift 按在价格线上 = 拖价格线,不是框选。测量手势要求 Ctrl,跟框选不冲突。

### 6.4 双击

- 按下被区域 Accept → **不计入兜底的双击计时**(同 9f24282 的做法,`_lastClickTimeMs` 不更新)。所以在价格线上快速点两下不会复原视口(原型测试 (c) 已经要求这一点)。
- 区域 `Accepts` 含 `DoubleClick`:同一区域在 `DoubleClickResetOptions.MaxInterval` / `MaxMovementPx`(`ChartInteractionFeature.cs:62-72`)内的第二次按下发 `DoubleClick`,第一次照常发 `Click`(不做"等一等看是不是双击"的延迟,跟 WPF / Avalonia 一致)。
- 计数由仲裁器自己做,`PointerInput.ClickCount` 是框架的计数,不读 WPF 的 `ClickCount`——WPF 按系统双击设置算,跟兜底双击复原的参数不同,会出现"图表认为是双击、业务认为不是"。
- 顺带解决 `ElementPlotFeatureBase` 双击跟双击复原同时触发的问题(`:166-173`):第二期把它迁成区域后自然互斥;第一期不动它。

### 6.5 滚轮

第一期**滚轮始终归缩放**,区域不能认领。手势进行中滚轮照样缩放(原型测试 (e) 已验证画线进行到一半缩放不打断),业务用值坐标存状态,缩放后重投影即可。要不要让区域认领滚轮(比如在价格线上滚轮微调价格)列为开放问题 Q6。

### 6.6 Esc 与模态区域

Esc 的处理顺序(都在仲裁器的 PreviewKeyDown 里、先于 `ChartInteractionFeature` 的 PreviewKeyDown `:390`):

1. 有手势进行中 → 赢家收到 `Cancel(Escape)`,释放捕获,Esc 标 Handled。
2. 否则,有已发布的 `Modal` 区域 → 优先级最高的那个 Feature 收到 `Escape`(画线工具退出创建模式);它下一帧撤掉 Modal 区域。Esc 标 Handled。
3. 否则 → 不处理,交给 `ChartInteractionFeature` 的 `DismissOnEscape`(`:395-401`),行为不变。

业务原型为此要按 handledEventsToo 订 PreviewKeyDown(原型限制 2);改成框架统一排序后不再需要。

`Modal` 的另一层含义:Modal 区域通常是 `WholePlot`,优先级 `Modal`,于是创建模式下绘图区里所有按下都归画线工具,图表不平移——但滚轮缩放、键盘方向键照常。

### 6.7 第二个键 / 多指针

手势进行中按下另一个键:第一期发 `Cancel(OtherButton)` 给赢家并结束手势(TradingView 画线中右键 = 取消)。是否改成忽略列为开放问题 Q8。触屏走 Manipulation 通道(`ChartInteractionFeature.cs:411-441`),第一期不经仲裁;但**手势进行中**仲裁器让 Manipulation Delta 失效,免得一边拖价格线一边被手指平移。

### 7.2 仲裁器怎么跟 `ChartInteractionFeature` 说话

第一期仲裁器和 `ChartInteractionFeature` 都在框架里,用一个 **internal** 接口连接,业务看不到:

```csharp
internal interface IPointerFallback
{
    void OnPressClaimed(HevoPoint pos);   // 停惯性 + 武装 hover + 就地投影十字光标
    void BeginPanFrom(HevoPoint pressPos, HevoPoint currentPos); // 只接受点击的区域输给平移时,从按下点接着平移
    void SetGestureActive(bool active, bool hideCrosshair); // 手势期间:Manipulation 失效、MouseLeave 不清、可选清 hit
}
```

`ChartInteractionFeature.OnCompose` 把自己挂到本 cell 的仲裁器上(`RegisterDisposable`,Decompose 自动摘)。**没有 `ChartInteractionFeature` 时仲裁器照常工作**,只是没人停惯性 / 武装 hover(本来也没有这些东西)。这跟 9f24282 方向相反:不是业务去找交互 Feature,而是框架内部互相认识。

`ChartInteractionFeature` 收不到被认领的冒泡 MouseDown(仲裁器在 Preview 里标了 Handled,WPF 不提升,原型 `RawMouseFidelityTests` 已证),所以它的 MouseDown 代码不需要加 `if (claimed)`;它的 MouseUp 本来就只在 `_box.IsActive` / `_isPanning` 时做事(`:299`、`:306`)。改动集中在新增的 `IPointerFallback` 三个方法。

### 7.3 光标

- 仲裁器在悬停命中变化时设 `ChartCell.Cursor`(区域的 `Cursor`;离开所有区域时恢复成 `null`,即继承父元素)。手势进行中用 `DragCursor`。
- `PointerCursor` → `System.Windows.Input.Cursors` 的映射只出现在 WPF 适配器里。
- 业务不再自己写 `Host.Cursor = ...`(原型 `PriceLineFeature.OnHover` 里是这么做的)。

### 7.4 投影快照是哪一帧的

`GestureEvent.Projection` = **发布赢家区域的那个 Feature 最近一次 `UseProjection` 拿到的值**,跟区域一起提交。所以按下时 `ScreenToValue(e.Input.Position.Y)` 跟命中所用的几何同一帧。拖动中 Feature 每写一次端口就重投影一次,下一次 Move 拿到的是新快照。Feature 没调 `UseProjection` 时 `Projection.IsValid == false`。

## 8. 手势里怎么写状态、怎么唤醒自己

规则不变,只是写清楚:

1. **回调不是 `OnProject`**,可以写黑板,也只应该在这里写(`OnProject` 里不写黑板,00 号文档 `:305`)。
2. **写本 Feature 在 `OnProject` 里 `UsePort` 过的端口 = 唤醒本 Feature**:`WriteIfChanged` → `ReactiveSchema.Blackboard_OnPortUpdated`(`Core/ReactiveSchema.cs:993-1006`)查到订阅者 → `RequestUpdate` → 下一帧只投影它、只重录它的图层。业务原型就是这么做的,G11 第三项("事件里写入就能唤醒本 Feature 的私有状态")**不需要新机制**,只需要写进文档并给 `e.Write(port, value)` 这个 helper。
3. 私有状态(悬停高亮、橡皮筋终点)用 Feature 私有的 `DataPort<T>` 字段,不暴露。
4. 多个端口一次写:`using (e.Board.BeginTransaction()) { ... }`(接口评审 G9 的业务约定)。
5. **集合型状态发布新实例**:画线文档、线段列表每次改动 new 一份不可变对象再写(原型 `LineDrawingFeature.OnEnd` 新建数组 + `ForceWrite`),不原地改已发布的(AGENTS.md "往端口发布的列每次一块新缓冲")。
6. 回调里**不能调 Hook**(`UsePort` / `UseMemo` / `ctx.Gestures()`):不在帧路径,Debug 下 `AssertProjecting` 会抛(`Core/ChartFeature.cs:72-77`)。要读当前状态用 `e.Board.Read(...)`(带读锁)或 Feature 自己在 `OnProject` 里记下的"上一帧画出来的值"(原型 `_drawnPrice` 的做法——命中按用户看到的位置判)。

## 9. 线程与锁

- 仲裁器和所有回调都在 **UI 线程**(WPF 输入线程);帧也在 UI 线程(`Core/ChartCell.cs:122`、`:714`)。所以区域表、投影快照、仲裁器状态都是单线程数据,**不加锁**。
- 仲裁器调用业务回调时**不持有黑板锁**。业务自己按最小作用域加锁(00 号文档 `:83`:"`WithBoard` 只绑定黑板,不隐式加锁")。这避免回调里写锁跟 `WatchAsync` 后台写者的锁顺序问题。
- `e.Write` 内部 `AcquireWriteLock` + `WriteIfChanged`,单端口一次一锁。
- 回调抛异常:**不吞**,跟 9f24282 一致往外抛;但仲裁器先在 `finally` 里把自己复位(释放捕获、回到 Idle、恢复光标),并且不再给这个手势发 `Cancel`(避免二次进业务代码)。抛在 Press 里时兜底不启动(跟 9f24282 的理由相同:不在业务半截的手势底下平移)。

## 10. 生命周期

| 事件 | 处理 |
|---|---|
| Feature 首次 `Publish` | 下一次 `SubmitSync` 后生效 |
| Feature `Clear()` 或不再发布 | 下一次提交后失效;正在悬停的区域收到 `HoverLeave`,光标恢复 |
| 手势进行中赢家的区域被撤掉(比如拖动中价格线被业务隐藏) | **手势继续**,直到 End / Cancel。区域只决定"按下归谁",不决定"手势还算不算数";业务想中止就在下一次回调里自己判断(或调开放问题 Q9 的 `CancelGesture`) |
| `Transact` 热拔赢家 Feature | `Feature.Decompose`(`Core/Feature.cs:297`)开头通知仲裁器:手势进行中则先发 `Cancel(OwnerRemoved)`(此时 Feature 还挂着,能写自己的端口回滚)、释放捕获,再清掉它的区域。Decompose 后续照常(`:308` 关生命周期、`:320` `OnDecompose`) |
| `Transact` 热插新 Feature | 首帧投影时发布区域(`Core/ReactiveSchema.cs:424-427` 新 Feature 立刻被推一次黑板) |
| 父 Feature 级联拆子 Feature(`RemoveChildFeature`,`Core/Feature.cs:292`) | 同热拔,逐个子 Feature 处理 |
| 同一实例热拔再插回 | 区域随 `_context.Reset()` 一起清(`Core/ChartFeature.cs:83-94`),重装后首帧重发 |
| `ChartCell` 暂停(Unloaded,00 号文档 §14)/ `Shutdown` | 手势进行中发 `Cancel(ChartUnloaded)`,释放捕获 |
| `ChartInteractionFeature` 被热拔 | 它的 `IPointerFallback` 登记随 `RegisterDisposable` 摘掉;仲裁器继续工作 |

## 11. 三个需求在新 API 下的样子(伪代码)

完整范例实现时放 `Hevo.Charting.Tests/DocSamples/Gesture/`(AGENTS.md:文档只引用文件)。下面只示意形状。

### 11.1 可拖动的水平价格线

```csharp
public sealed class PriceLineFeature : ChartFeature, IGestureHandler
{
    public DataPort<RealRange> ValueRangePort { get; init; } = null!;
    public DataPort<double> PricePort { get; init; } = new DataPort<double>("PriceLine_Price");
    public event Action<double>? DragCompleted;

    private readonly DataPort<bool> _hotPort = new DataPort<bool>("PriceLine_Hot");
    private readonly PriceLineLayer _layer = new PriceLineLayer();
    private double _drawnPrice = double.NaN, _startPrice, _grabOffset, _dragPrice;

    protected override void OnCompose(ChartCell chart, RenderContext ctx, IRenderFlow<DataBlackboard> flow) => AttachLayer(_layer);

    protected override void OnProject(FeatureContext ctx)
    {
        var (proj, projChanged) = ctx.UseProjection(ValueRangePort);
        var (price, priceChanged) = ctx.UsePort(PricePort);
        var (hot, hotChanged) = ctx.UsePort(_hotPort);
        _drawnPrice = price;
        if (!projChanged && !priceChanged && !hotChanged) return;

        if (!proj.IsValid || double.IsNaN(price))
        {
            ctx.For(_layer).PublishData(PriceLineTrait.Hidden);
            ctx.Gestures().Clear();
            return;
        }
        float y = proj.ValueToScreenY(price);
        ctx.For(_layer).PublishData(new PriceLineTrait(true, proj.PlotArea.Left, proj.PlotArea.Right, y, hot));
        ctx.Gestures().Publish(GestureRegion.HLine(0, y, proj.PlotArea.Left, proj.PlotArea.Right)
            .AcceptsGestures(GestureAccepts.Drag)
            .WithCursor(PointerCursor.SizeNS));
    }

    public GestureReply OnGesture(in GestureEvent e)
    {
        switch (e.Phase)
        {
            case GesturePhase.HoverEnter: e.Write(_hotPort, true); break;
            case GesturePhase.HoverLeave: e.Write(_hotPort, false); break;
            case GesturePhase.Press:
                _startPrice = _dragPrice = _drawnPrice;   // OnProject 里记下的"上一帧画出来的价格"(同原型)
                _grabOffset = e.PressPosition.Y - e.Projection.ValueToScreenY(_startPrice);
                break;
            case GesturePhase.Begin:
            case GesturePhase.Move:
                _dragPrice = e.Projection.ScreenToValue(e.Input.Position.Y - _grabOffset);
                e.Write(PricePort, _dragPrice);
                break;
            case GesturePhase.End: DragCompleted?.Invoke(_dragPrice); break;
            case GesturePhase.Cancel: e.Write(PricePort, _startPrice); break;
        }
        return GestureReply.Accept;
    }
}
```

对比原型:没有 `PointerGestureFeature` 基类、没有 `CapturesPointer`、没有 `Host.Cursor`、没有 `_active`、没有 LostMouseCapture / Esc 订阅;`ChartGeometry` 换成框架的 `ChartProjection`。

### 11.2 点两下画线(也支持按住拖)

```csharp
public sealed class LineDrawingFeature : ChartFeature, IGestureHandler
{
    public DataPort<RealRange> ValueRangePort { get; init; } = null!;
    public DataPort<IReadOnlyList<DrawnLine>> LinesPort { get; init; } = ...;

    private readonly DataPort<bool> _armedPort = new DataPort<bool>("LineDrawing_Armed");
    private readonly DataPort<ChartAnchor?> _pendingStartPort = ..., _pendingEndPort = ...;

    /// 工具栏调。要写端口(下一帧发布 Modal 区域),所以接黑板。
    public void Arm(DataBlackboard board) { using (board.AcquireWriteLock()) board.WriteIfChanged(_armedPort, true); }

    protected override void OnProject(FeatureContext ctx)
    {
        var (proj, pc) = ctx.UseProjection(ValueRangePort);
        var (armed, ac) = ctx.UsePort(_armedPort);
        var (lines, lc) = ctx.UsePort(LinesPort);
        var (start, sc) = ctx.UsePort(_pendingStartPort);
        var (end, ec) = ctx.UsePort(_pendingEndPort);
        if (!(pc || ac || lc || sc || ec)) return;

        ctx.For(_layer).PublishData(new LineDrawingTrait(lines ?? NoLines, start, end, proj));
        if (armed)
            ctx.Gestures().Publish(GestureRegion.WholePlot(0)
                .AcceptsGestures(GestureAccepts.Click | GestureAccepts.Drag)
                .WithPriority(GesturePriority.Modal).WithCursor(PointerCursor.Cross).AsModal());
        else
            ctx.Gestures().Clear();   // 画好的线做成可选中 / 可拖时,这里改发每条线的 Segment + 端点 Circle
    }

    public GestureReply OnGesture(in GestureEvent e)
    {
        var p = e.Projection;
        switch (e.Phase)
        {
            case GesturePhase.Click:                       // 点两下画法
                if (_pendingStart == null) SetPending(e, Anchor(p, e.Input.Position));
                else Commit(e, _pendingStart.Value, Anchor(p, e.Input.Position));
                break;
            case GesturePhase.Begin:                       // 按住拖画法:按下点 = 起点
                SetPending(e, Anchor(p, e.PressPosition)); break;
            case GesturePhase.Move:
            case GesturePhase.HoverMove:                   // 两次单击之间拉橡皮筋
                if (_pendingStart != null) e.Write(_pendingEndPort, (ChartAnchor?)Anchor(p, e.Input.Position));
                break;
            case GesturePhase.End:
                Commit(e, _pendingStart!.Value, Anchor(p, e.Input.Position)); break;
            case GesturePhase.Cancel:
            case GesturePhase.Escape:                      // Esc:退出创建模式,丢掉半截线
                Disarm(e); break;
        }
        return GestureReply.Accept;
    }
    // Commit:new 一份线段数组 ForceWrite(LinesPort);清 pending;写 _armedPort=false → 下一帧撤 Modal 区域
}
```

要点:两次单击之间没有"进行中的手势"(指针是抬起的),所以滚轮缩放、方向键照常;Modal 区域保证这期间绘图区的按下都归画线工具,快速点两下也不会触发双击复原(§6.4)。"画线模式要优先于价格线"不再靠装配顺序,靠 `Modal` 档位。

### 11.3 测量(Ctrl + 拖)

```csharp
public sealed class MeasureGestureFeature : ChartFeature, IGestureHandler
{
    public event Action<ChartAnchor, ChartAnchor>? Measured;
    // 发布一次就够:WholePlot 跟着 PlotArea 走,UseProjection 变了才重发
    protected override void OnProject(FeatureContext ctx)
    {
        var (proj, changed) = ctx.UseProjection(ValueRangePort);
        if (!changed) return;
        ctx.Gestures().Publish(GestureRegion.WholePlot(0)
            .AcceptsGestures(GestureAccepts.Drag)
            .RequireModifiers(PointerModifiers.Control)
            .WithCursor(PointerCursor.Default, drag: PointerCursor.Cross));
        // 测量框的 Trait 发布略
    }

    public GestureReply OnGesture(in GestureEvent e)
    {
        switch (e.Phase)
        {
            case GesturePhase.Move: e.Write(_rectPort, MakeRect(e.PressPosition, e.Input.Position)); break;
            case GesturePhase.End:
                Measured?.Invoke(Anchor(e.Projection, e.PressPosition), Anchor(e.Projection, e.Input.Position));
                e.Write(_rectPort, MeasureTrait.Hidden); break;
            case GesturePhase.Cancel: e.Write(_rectPort, MeasureTrait.Hidden); break;
        }
        return GestureReply.Accept;
    }
}
```

不按 Ctrl 时这个区域不进候选(§5.3 第 1 步),普通拖动照常平移。对比 9f24282 的 `MeasureGestureFeature`(`Hevo.Charting.Tests/DocSamples/Gesture/MeasureGestureFeature.cs` @9f24282):没有 `Interaction` 属性、没有 `ListFeatures().OfType<>()`、没有 `CaptureMouse` / `ReleaseMouseCapture`、没有 WPF `Keyboard.Modifiers`。

## 13. 迁移与兼容

### 13.1 兼容性

- **没有任何 Feature 发布区域时**:仲裁器的 Preview 处理器只做一次"区域数 == 0"判断后返回,不标 Handled、不抓鼠标、不设光标。`ChartInteractionFeature` 收到的事件与现在完全相同。Esc:仲裁器在没有手势、没有 Modal 区域时不处理,`DismissOnEscape` 照旧。
- 唯一的无条件变化:`IPointerFallback` 登记(一个字段)。
- 公开 API 只增不改。`ChartInteractionFeature` 的公开属性、`EnableStandard` / `EnableStandardPointer` 签名不变。
- 现有测试不改应该全过;9f24282 里 `NoClaim_*` / `Miss_*` 这组"没有认领者时行为不变"的用例改写成"没有区域时"直接复用(§14)。
- **业务原型与新机制混用**:仲裁器的 Preview 处理器注册在先;它认领时标 Handled,原型的普通 Preview 订阅收不到这次按下。没有区域时原型照常工作。所以迁移按屏幕整体切,不要一个屏幕里两套混用。

### 13.2 从 9f24282 迁移

9f24282 没合并,不存在兼容负担。它的可复用部分:

## 14. 测试计划

鼠标走真实 WPF 输入管线:复用 9f24282 的 `RawMouse`(往屏幕外窗口的 HwndSource 注入原始鼠标报告,拦掉真鼠标消息),`RealMouseInputCollection` 不与其他测试类并行(9f24282 实测并行时约三成概率丢按下)。帧用 `RunFrameNow(PlotMode.Sync)` 手动驱动。

**兼容(没有区域)**——从 9f24282 `NoClaim_*` 搬:拖动平移;按下抓鼠标并清 hit;Shift 拖框选;双击复原;甩动启动惯性、下次按下停;`RequireClickToActivate` 下按下武装 hover;`DismissOnEscape` 的 Esc;外加"没有区域时仲裁器不标 Handled、不改 Cursor"。

**仲裁**:命中区域不平移、不框选、不双击复原;未命中照常平移;优先级高的赢(跟装配顺序相反的两个 Feature);同档位按图层层级;同层级按距离;`Decline` 落到下一个候选、全部 Decline 落到平移;`RequiredModifiers` 不满足时平移;右键命中 `ContextClick` / 右键未命中走兜底。

**状态机**:Press → Begin → Move → End 顺序和坐标;未过阈值松开 → Click 不发 Begin;只接受 Click 的区域过阈值 → `Cancel(SupersededByPan)` 且视口从按下点开始平移(位移不丢 4px);DoubleClick;第二个键按下 → `Cancel(OtherButton)`。

**取消与生命周期**:Esc 取消并回滚;丢捕获(另一个控件抢捕获)取消;拖出图表外仍收 Move / End;`Transact` 热拔进行中的赢家 → 收到 `Cancel(OwnerRemoved)`、捕获释放、之后平移正常;热拔后区域失效;同一实例热拔再插回重新生效;cell `Shutdown` 中途取消;回调抛异常 → 异常外抛、仲裁器复位、之后平移正常。

**与现有行为配合**:认领的按下停惯性(原型 `Caveat_InertiaPan_IsNotStoppedByClaimedPress` 反转为通过);`RequireClickToActivate` 下认领的按下武装并就地显示十字光标;拖动中十字光标跟手;`HideCrosshairWhileActive` 时清 hit;滚轮缩放在手势中照常;方向键照常;Modal 区域时 Esc 先给工具、再按一次才给 `DismissOnEscape`;没有 `ChartInteractionFeature` 的 schema 里区域仍工作。

**光标**:悬停进入设光标、离开恢复;拖动中用 `DragCursor`;区域被撤掉时恢复。

**范例**:三个 DocSamples 各一个端到端用例(拖价格线改价 + 回滚;点两下 / 按住拖各画一条线 + Esc;Ctrl 拖测量 + 不按 Ctrl 平移)。

**投影**:`ChartProjection` 往返(值 → 屏幕 → 值)在 Edge / Centered / 对数比例尺下误差 < 1e-6;`ISnappableScale` 下 `ScreenToDomain` 返回带小数的索引(吸附是业务的事)。

**性能**:100 个区域时一次 MouseMove 的命中耗时(BenchmarkDotNet,放 `Hevo.Charting.Benchmarks`);零区域时 Preview 处理器无分配。

**红线**:`scripts/check-net5.ps1` 重编;DocSamples 在 `LangVersion 9` 下编译(验证业务不需要 `with` / `required`)。
