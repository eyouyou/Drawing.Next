> 状态:**只是方案,没有写任何框架代码。** 评审通过后在下一个框架窗口实现。
> 基线:`origin/main` 61ef76f。文中 `文件:行号` 都指这个提交。`9f24282` 指 `origin/feat/pointer-claim` 上没合并的 `IPointerClaim`;"业务原型"指 hevo.drawing 的 30642aa(`Hevo.Drawing.Foundation/Gestures/*`,结论见该仓库 `docs/G11-手势仲裁原型验证.md`)。

## 0. 三分钟版

**一句话**:按下、拖动、松开,从"每个 Feature 自己订 WPF 事件抢"改成"框架里一个路由器统一裁决这一下点中了谁,再分发给它";谁都没点中,交给现在的平移 / 框选 / 双击复原,行为不变。

**写屏幕的人**:在 `Interactions` 里装 Feature,不写交互代码。

```csharp
canvas.Interactions(i =>
{
    i.EnableStandard(TimePort, xMeta, options);   // 平移缩放十字光标,跟现在一样
    i.AddDraggableLine(OrderPricePort, YRange, new DraggableLineOptions { OnCommitted = p => ModifyOrder(p) });
    i.AddMeasure(YRange);                          // Ctrl + 拖测量
});
```

**写交互 Feature 的人**(框架内置的那几个,加上业务里的画线 Feature):只用两样东西,都是项目里现成的套路。

1. `OnProject` 里声明"我画的东西哪里能点 / 能拖"——写法跟发布 Trait 一样:
   ```csharp
   ctx.Pointer().Publish(new PointerRegion { Shape = PointerShape.HLine(y, left, right), Accepts = PointerAccepts.Drag, Cursor = PointerCursor.SizeNS });
   ```
2. `OnCompose` 里 `Watch` 路由器的手势端口——用法跟十字光标读 `PointerHitPort` 一样:
   ```csharp
   flow.Watch(new object[] { Pointer.GesturePort }, board => { var g = board.Read(Pointer.GesturePort); if (g.IsFor(this)) ... });
   ```

没有新的回调接口,没有 handler,不找任何 Feature 实例,契约里没有 WPF 类型。原来 Feature 自己 `this.OnMouse(...)` 的写法保留不变。

## 1. 现状

### 1.1 输入现在怎么走

- 框架内处理手势的只有 `ChartInteractionFeature`,在 `OnCompose` 里订 ChartCell 上的冒泡事件:MouseDown `Features/ChartInteractionFeature.cs:240`、MouseUp `:297`、MouseLeave `:339`、MouseMove `:346`、MouseWheel `:378`、PreviewKeyDown `:390`、Manipulation `:411` / `:426`。订阅走 `this.OnMouse` → `WorkflowWPFEventExtension.OnUIEvent`(`WorkFlow/WorkflowWPFEventExtension.cs:17-47`)→ 两参数的 `AddHandler`(`WorkFlow/WorkflowWatchExtensions.cs:125`)。
- MouseDown 先做"任意按下都要做的事":拿焦点 `:242`、停惯性 `:248`、武装 hover `:251`;再分流:双击复原 `:254-266` → 框选 `:269-283` → 平移并 `CaptureMouse` `:286-293`。不看按键,右键拖也平移。
- hover 命中写 `PointerHitPort`(`:894-946`),Crosshair / Tooltip 读它。
- `ElementPlotFeatureBase` 自己挂 hover(`Features/ElementPlotFeatureBase.cs:121-163`)和双击(`:166-173`,双击时跟图表的双击复原同时触发)。框架里没有任何地方设置 `Cursor`。

### 1.2 业务原型与 IPointerClaim 各差在哪

- **业务原型**:在 Preview 隧道里认领并标 `Handled`,WPF 就不提升冒泡 MouseDown,图表这次按下根本不发生。可行(9 个真实输入测试全过),但:认领的按下停不了惯性、`RequireClickToActivate` 时不武装十字光标、多个业务手势之间先后 = 装配顺序、每个手势 Feature 都要自己管捕获 / 丢捕获 / Esc / 光标。
- **IPointerClaim(9f24282)**:在 `ChartInteractionFeature` 的 MouseDown 里开口子问"有没有人认领"。修了惯性和武装,但:只管按下,Move / Up / 捕获 / Esc 仍是业务自己的 WPF 代码;业务要 `ListFeatures().OfType<ChartInteractionFeature>()` 找实例,找不到静默失效;按登记顺序仲裁;契约里有 `MouseButtonEventArgs`;没有光标、右键。

## 2. 目标与非目标

**目标**

1. 业务的拖动 / 点击能稳定抢在平移 / 框选 / 双击复原之前;捕获、丢失捕获、Esc、热拔、拖动阈值、点击与拖动的区分、悬停光标全由框架负责。
2. 常见需求(可拖水平线、测量)做成内置 Feature,写屏幕的人只用 builder。
3. 交互 Feature 之间按**点中了谁**仲裁,不按装配顺序。
4. 只用现有的两套机制:声明走"随帧发布"(同 Trait),通知走"端口 + Watch"(同 `PointerHitPort`)。不新增回调接口。
5. 契约不含 WPF 类型,为交互层去 WPF 依赖(将来可能迁 Avalonia)铺路。
6. 框架提供 `ScreenToDomain` / `ScreenToValue`(G11 第二项)。
7. 没有任何区域时,行为与现在完全一致。

**非目标**

- 触屏手势。`ChartCell` 开了 `IsManipulationEnabled`(`Core/ChartCell.cs:415`),触摸不提升成鼠标,到不了区域;触屏仍只有 `ChartInteractionFeature` 的平移和捏合。
- 画线框架本身(40 种工具、文档模型、吸附、撤销、持久化)——它在业务里,用本方案做底座。
- 跨 pane 的手势(主图拖进副图)。
- 第一期不让区域认领滚轮。
- 不改 `PointerHitPort` 的语义和唯一写者(04 号文档 §K)。

## 3. 借鉴了什么

| 来源 | 借鉴 |
|---|---|
| ECharts / zrender | 图元自带 `cursor`、`draggable`;按 z 从上往下命中,描边按线宽容差;**有图元接手就不启动漫游(平移缩放)** |
| Flutter gesture arena | **点击和拖动按移动阈值裁决**:只接受点击的对象在指针移出阈值后输给平移 |
| Avalonia | **丢失捕获是一等的取消原因**;捕获由框架代持;按键 / 修饰键 / 光标的取值对齐它,将来迁移时一对一映射 |
| TradingView 画线 | **优先级档位**:创建模式 > 端点手柄 > 对象 > 图表;**模态**:选了工具后整块绘图区归它,Esc 先退出工具 |

## 4. 写屏幕的人:装 Feature

### 4.1 自动挂上的路由器

`PointerRouterFeature` 由 `ChartReactiveSchema.EnsureBaseFeatures` 强制挂上,跟 `ViewportPortsFeature` 同一个做法(`Core/ChartReactiveSchema.cs:41`、`Features/ViewportPortsFeature.cs:33`):每个 schema 一份,业务不用 Add,也拔不掉;联动副图同样有。它的端口像 `Viewport` 一样注入到每个 `ChartFeature`(参照 `Core/ChartFeature.cs:272-286`),Feature 里直接写 `Pointer.GesturePort`。

这一点解决了 IPointerClaim 的"找不到交互 Feature 就静默失效":路由器一定在,跟有没有 `ChartInteractionFeature` 无关。

### 4.2 内置:可拖水平线 `DraggableLineFeature`

委托价、止损、预警线这类"一条横线,能拖,松手提交"。

```csharp
i.AddDraggableLine(OrderPricePort, YRange, new DraggableLineOptions
{
    OnCommitted = price => ModifyOrder(price),   // 松手;Esc / 丢捕获时自动回滚到按下前的价格,不调用
    // 可选:Style、HotStyle(悬停加粗)、Tolerance(默认 4px)、Label(右侧价格标签)、ReadOnly
});
```

- 价格存在业务给的 `OrderPricePort`;拖动中实时写它(界面上别处也跟着变)。拖动中只想预览、松手才写,见开放问题 Q4。
- 悬停变上下箭头光标,线加粗。

### 4.3 内置:测量 `MeasureFeature`

```csharp
i.AddMeasure(YRange, new MeasureOptions
{
    Modifier = PointerModifiers.Control,           // 默认 Ctrl + 拖
    OnMeasured = (from, to) => ShowStats(from, to) // 可选;from / to 是 (K 线索引, 价格)
});
```

拖动中画测量框和标签(根数、价差、涨跌幅);不按 Ctrl 的拖动照常平移。标签内容见开放问题 Q5。

### 4.4 画线:业务里一个 Feature

40 种画线工具是业务概念,放 hevo.drawing 的 `DrawingInteractionFeature`(接口评审 `docs/接口评审-2026-10.md:252` 的规划),同样一行装上。它用 §5 的两样东西实现。

### 4.5 原来的写法保留

`this.OnMouse(...)` / `OnUIEvent` / `WithBoard` 不改、不废弃,自己订鼠标的 Feature 照常工作。唯一的交互点:**某次按下被区域认领时**,路由器在 Preview 里标 Handled,同一 cell 上普通订阅的冒泡 MouseDown / MouseUp 收不到这一次;MouseMove 不受影响。没有区域时一切照旧。业务原型的 `PointerGestureFeature` 也用 Handled 抢,所以同一个屏幕不要两套混用,迁移按屏幕整体切。

## 5. 写交互 Feature 的人:区域 + 手势端口

所有新类型放 `Hevo.Charting.Interaction`(新目录 `Hevo.Charting/Interaction/`)。业务侧锁 `LangVersion 9`(`Hevo.Charting/README.md:29`),所以给业务构造的类型用 `record class` + 初始化器(C# 9 支持,不需要 `with` 也能写);每次鼠标移动都要写的值用 `readonly struct`,业务只读不构造。

### 5.1 声明区域(OnProject 里)

```csharp
public sealed record PointerRegion
{

    public int Part { get; init; }               // 部位:线身 0 / 起点手柄 1 / 终点手柄 2
    public PointerShape Shape { get; init; }     // 哪里(DrawingCanvas 坐标,发布那一帧的屏幕位置)
    public PointerAccepts Accepts { get; init; } = PointerAccepts.Drag;   // 能干嘛
    public PointerCursor Cursor { get; init; }   // 悬停光标;Default = 不改
```

- **语义同 Trait**:按 Feature 存一份"当前区域表",跟图层 Trait 在同一次 `RenderContext.SubmitSync`(`Core/RenderContext.cs:194`,帧尾 `Core/ChartCell.cs:636`)提交。所以**命中用的位置 = 屏幕上那一帧画的位置**。
- Feature 只在脏的时候投影(`Core/ReactiveSchema.cs:627-637`),区域表也只在变的时候重发;它属于"每帧发布的不可变记录",是 0-GC 规则的豁免项(`00.Hevo.Charting 架构协议与开发规范.md:139`)。
- 只能在 `OnProject` 帧路径里调(复用 `AssertProjecting`,`Core/ChartFeature.cs:72-77`)。
- 形状没有自定义回调:`OnProject` 里不能 new 闭包(00 号文档 `:305`)。斐波那契这类复杂形状拆成多个区域,共用 `Id`。
- 想让某个对象暂时不可点(画线已锁定),就不发布它的区域。

### 5.2 接收事件:Watch 手势端口

路由器每有一步,就往本 cell 的 `Pointer.GesturePort` 写一份 `PointerGesture`:

```csharp
public enum PointerPhase { Press, Begin, Move, End, Cancel, Click, DoubleClick, ContextClick, HoverEnter, HoverMove, HoverLeave, Escape }
public enum PointerCancelReason { None, Escape, CaptureLost, OwnerRemoved, ChartUnloaded, SupersededByPan, OtherButton }

public readonly struct PointerGesture
{
    public long Sequence { get; }            // 每次写入递增,保证连续两次相同点击也会触发 Watch
    public object? Owner { get; }            // 区域所属 Feature
    public int RegionId { get; }
    public int RegionPart { get; }
    public PointerPhase Phase { get; }
    public PointerCancelReason Reason { get; }
    public HevoPoint Position { get; }       // DrawingCanvas 坐标(DIP),跟 hover 命中同一口径(ChartInteractionFeature.cs:348)
    public HevoPoint PressPosition { get; }
    public PointerButton Button { get; }
    public PointerModifiers Modifiers { get; }  // 拖动中按 Shift 也能实时读到
    public bool IsFor(object feature) => ReferenceEquals(Owner, feature);
}
```

```csharp
protected override void OnCompose(ChartCell chart, RenderContext ctx, IRenderFlow<DataBlackboard> flow)
{
    flow.Watch(new object[] { Pointer.GesturePort }, board =>
    {
        var g = board.Read(Pointer.GesturePort);
        if (!g.IsFor(this)) return;
        switch (g.Phase) { /* 见 §8 */ }
    });
}
```

**这条路不会慢一帧,已核实**:同步 `Watch` 挂在黑板的 `OnTransactionCommitted` 上(`WorkFlow/FeatureExtensions.cs:252-267`);非事务写入在写的当下就触发它(`LowCode/DataBlackboard.cs:244-252`)。所以路由器写端口 → 业务回调在同一调用栈、同一 UI 线程里执行完,路由器才继续。黑板锁可重入(`LowCode/DataBlackboard.cs:24`,`SupportsRecursion`),回调里再 `AcquireWriteLock` 写自己的端口没问题。

为什么不用回调接口:04 号文档定的原则是"Feature 之间通信走 DataPort"(§A),十字光标已经是"交互 Feature 写 `PointerHitPort`、别的 Feature 读"。手势照搬,少一个概念;Watch 的生命周期由 Feature 托管(`FeatureExtensions.cs:63-68`),Feature 卸载后不再执行。能不能点只由"发不发布区域"决定,见 §11。

## 6. 路由器怎么裁决

### 6.1 点中了谁

按下(或悬停)时:

1. **筛**:形状命中(线类按距离 ≤ 容差,面类按包含);按键匹配;`RequiredModifiers` 已按下;`Accepts` 允许这次输入。
2. **`Priority` 高的优先**:模态(画线工具已选中)> 手柄 > 对象。
3. 同档:**画在上层的优先**——比较所属 Feature 图层的 `ChartLayerType`(`Core/ChartCell.cs:42-64`),相当于 zrender 的 z。
4. 同层:**离指针近的优先**。
5. 再平:同一 Feature 内后发布的优先;不同 Feature 按 `Phase`、再按装配顺序。顺序只用来打破平局。

没有任何候选 → 兜底:`ChartInteractionFeature` 的双击复原 / 框选 / 平移,跟现在一样。

### 6.2 一次拖动的过程

```
按下命中 ──► Press ──移动 ≥ 阈值──► Begin ──► Move … ──松开──► End
               │
               ├─ 没过阈值就松开 ──► Click(第二次快速点击 ──► DoubleClick)
               ├─ 只接受 Click 的区域被拖过阈值 ──► Cancel(SupersededByPan),平移从按下点接着走
               └─ Esc / 丢失捕获 / Feature 被拔 / cell 卸载 / 按了另一个键 ──► Cancel(原因)
```

- 拖动阈值默认 4 DIP(WPF 默认拖动距离),全局可配。
- 接受 `Drag` 的区域按下时框架就**捕获鼠标**,拖出图表外也能收到 Move / End。
- 双击用框架自己的计数,参数沿用 `DoubleClickResetOptions`(`ChartInteractionFeature.cs:62-72`),不读 WPF 的 `ClickCount`。被认领的按下**不计入**双击复原的计时,所以在价格线上快速点两下不会复原视口。

### 6.3 按键、修饰键、滚轮

- 区域默认只接左键;右键命中 `Accepts` 含 `ContextClick` 的区域 → 松开时发 `ContextClick`(业务弹菜单)。没命中 → 兜底。兜底的平移现在不分按键,本方案不改(Q6)。
- 框选默认 Shift + 拖(`ChartInteractionFeature.cs:29`)。区域先于兜底仲裁,所以 Shift 按在价格线上是拖价格线;测量用 Ctrl,不冲突。
- 滚轮始终归缩放,手势中也照常(原型已验证画线进行到一半缩放不打断)。

### 6.4 Esc 与模态

Esc 的顺序(路由器在 `ChartInteractionFeature` 的 PreviewKeyDown `:390` 之前处理):

1. 有手势进行中 → `Cancel(Escape)`,释放捕获。
2. 否则有已发布的 `Modal` 区域 → 发 `Escape` 给它(画线工具退出创建模式,下一帧撤掉模态区域)。
3. 否则不处理,交给 `DismissOnEscape`(`:395-401`),行为不变。

模态区域一般是 `WholePlot` + `PointerPriority.Modal`:选了画线工具后,绘图区里的按下都归它,图表不平移;滚轮缩放、方向键照常。

### 6.5 光标

路由器在悬停命中变化时设 `ChartCell.Cursor`(离开所有区域时恢复成 `null`);拖动中用 `DragCursor`。`PointerCursor` → WPF `Cursors` 的映射只在一个适配器文件里。业务不再自己写 `Host.Cursor = ...`(原型 `PriceLineFeature.OnHover` 里这么写)。

### 6.6 代价

- **没有区域**:Preview 处理器看一眼"区域数 == 0"就返回,不标 Handled、不设光标、不写端口。
- **有区域、没在拖**:每次移动做一次命中(为了光标和悬停)。区域在提交时拍平并算好包围盒,先比包围盒再算距离;300 个区域是微秒级。
- **拖动中**:不做命中,只写手势端口。端口值是 struct,不分配。所有 Watch 了手势端口的 Feature 都会被叫一次、各自按 `IsFor` 过滤;交互 Feature 就几个,可以忽略。

### 6.7 多图、联动副图

- 路由器每个 schema 一份,区域、捕获、手势端口都只在本 cell 内有效。
- **手势端口不能进联动镜像**(`Linked/LinkedChartContext.cs:60-78` 的镜像表),否则副图会收到主图的拖动。价格线拖动写的是业务自己的价格端口,业务想跨 pane 同步就把那个端口登记镜像(`RegisterMirror`,`:86`)。

### 8.1 可拖水平线(内置 `DraggableLineFeature` 内部)

```csharp
public sealed class DraggableLineFeature : ChartFeature
{
    public DataPort<double> PricePort { get; init; } = null!;
    public DataPort<RealRange> ValueRangePort { get; init; } = null!;
    public DraggableLineOptions Options { get; init; } = new DraggableLineOptions();

    private readonly DataPort<bool> _hotPort = new DataPort<bool>("DraggableLine_Hot");
    private readonly DraggableLineLayer _layer = new DraggableLineLayer();
    private ChartProjection _projection;
    private double _drawnPrice = double.NaN, _startPrice, _grabOffset, _dragPrice;

    protected override void OnCompose(ChartCell chart, RenderContext ctx, IRenderFlow<DataBlackboard> flow)
    {
        AttachLayer(_layer);
        flow.Watch(new object[] { Pointer.GesturePort }, board =>
        {
            var g = board.Read(Pointer.GesturePort);
            if (!g.IsFor(this)) return;
            switch (g.Phase)
            {
                case PointerPhase.HoverEnter: Write(board, _hotPort, true); break;
                case PointerPhase.HoverLeave: Write(board, _hotPort, false); break;
                case PointerPhase.Press:
                    _startPrice = _dragPrice = _drawnPrice;   // 按用户看到的位置
                    _grabOffset = g.PressPosition.Y - _projection.ValueToScreenY(_drawnPrice);
                    break;
                case PointerPhase.Begin:
                case PointerPhase.Move:
                    _dragPrice = _projection.ScreenToValue(g.Position.Y - _grabOffset);
                    Write(board, PricePort, _dragPrice);
                    break;
                case PointerPhase.End: Options.OnCommitted?.Invoke(_dragPrice); break;
                case PointerPhase.Cancel: Write(board, PricePort, _startPrice); break;
            }
        });
    }

    protected override void OnProject(FeatureContext ctx)
    {
        var (proj, pc) = ctx.UseProjection(ValueRangePort);
        var (price, prc) = ctx.UsePort(PricePort);
        var (hot, hc) = ctx.UsePort(_hotPort);
        _projection = proj;
        _drawnPrice = price;
        if (!pc && !prc && !hc) return;

        if (!proj.IsValid || double.IsNaN(price)) { ctx.For(_layer).PublishData(DraggableLineTrait.Hidden); ctx.Pointer().Clear(); return; }
        float y = proj.ValueToScreenY(price);
        ctx.For(_layer).PublishData(new DraggableLineTrait(proj.PlotArea.Left, proj.PlotArea.Right, y, hot));
        ctx.Pointer().Publish(new PointerRegion
        {
            Shape = PointerShape.HLine(y, proj.PlotArea.Left, proj.PlotArea.Right),
            Accepts = PointerAccepts.Drag,
            Cursor = PointerCursor.SizeNS,
            Tolerance = Options.Tolerance,
        });
    }
}
```

对比业务原型:没有底座基类、没有 `CapturesPointer`、没有 `Host.Cursor`、没有 `_active` 标志、没有 LostMouseCapture / Esc 订阅。

## 9. 写状态、唤醒自己

规则不变,写清楚:

1. Watch 回调不是 `OnProject`,可以写黑板,也只应该在这里写(`OnProject` 不写黑板,00 号文档 `:305`)。
2. **写本 Feature 在 `OnProject` 里 `UsePort` 过的端口 = 唤醒本 Feature**(`Core/ReactiveSchema.cs:993-1006` 把它放进脏名单并申请下一帧)。G11 第三项不需要新机制。
3. 私有状态(悬停高亮、橡皮筋)用私有 `DataPort<T>` 字段。
4. 多个端口一次写:`using (board.BeginTransaction())`(接口评审 G9 的约定)。
5. 集合状态每次发布新实例(画线数组 new 一份再写),不原地改已发布的(AGENTS.md)。
6. 回调里不能调 Hook(`UsePort` / `UseMemo` / `ctx.Pointer()`),Debug 下 `AssertProjecting` 会抛。投影和"上一帧画的值"在 `OnProject` 里存成字段(上例的 `_projection`、`_drawnPrice`)。

## 10. 线程与锁

- 路由器、Watch 回调、帧都在 UI 线程(`Core/ChartCell.cs:122`、`:714`),区域表和投影字段不用加锁。
- 回调是在路由器写手势端口的写锁内执行的(§5.2),锁可重入,回调里照常 `AcquireWriteLock`。回调要短,别做重活——持锁期间后台 `WatchAsync` 的提交在等。
- 回调抛异常:不吞,往外抛;路由器在 `finally` 里先复位自己(释放捕获、回到空闲、恢复光标)。按下阶段抛出时不启动兜底平移(同 9f24282 的理由:不在半截的业务手势底下平移)。

## 11. 生命周期

| 情况 | 处理 |
|---|---|
| Feature 首次发布区域 | 下一次 `SubmitSync` 后生效 |
| `Clear()` 或不再发布 | 下一次提交后失效;悬停中的区域收到 `HoverLeave`,光标恢复 |
| 拖动中区域被撤掉 | 拖动继续到 End / Cancel。区域只决定按下归谁 |
| `Transact` 热拔正在拖的 Feature | `Feature.Decompose`(`Core/Feature.cs:297`)开头通知路由器:先写 `Cancel(OwnerRemoved)`——此时 Feature 的 Watch 还活着(生命周期令牌在 `:308` 才结束),能回滚——再释放捕获、清掉它的区域 |
| 热插新 Feature | 首帧投影时发布区域(`Core/ReactiveSchema.cs:424-427` 新 Feature 立刻被推一次黑板) |
| 同一实例拔了再插 | 区域随 `_context.Reset()`(`Core/ChartFeature.cs:83-94`)清掉,重装后首帧重发 |
| cell 暂停(00 号文档 §14)/ `Shutdown` | 拖动中写 `Cancel(ChartUnloaded)`,释放捕获 |
| `ChartInteractionFeature` 被拔 | 路由器照常工作,只是没人停惯性 / 武装 hover(本来也没有) |

**能不能点 = 发不发布区域**:没有"拒绝"这一说。区域发布了,点中就归它;Feature 在 Watch 里不处理,这次按下就是什么都不发生(不会转去平移)。想让对象不可点(画线锁定、撤单中),就不发布它的区域——业务状态一变,`OnProject` 会重跑、撤掉区域。

## 16. 风险与对策(示意代码)

下面的代码是给评审看的形状,不是最终实现;框架内部的类名、字段名实现时可能调整。每段注明它依赖的现有代码。

### R1. 业务回调在黑板写锁里跑

**问题**:路由器写 `GesturePort` 要持写锁,同步 Watch 就在这把锁里执行(§5.2)。内置 Feature 的 `OnCommitted = p => ModifyOrder(p)` 如果也在这里调,业务一旦同步发请求 / 弹框 / 等后台线程,整块黑板被锁住,后台行情写不进来。

**对策**:黑板已有"写锁内登记、最后一层锁退出后同线程执行"的队列(`LowCode/DataBlackboard.cs:115-146`;联动镜像就靠它避免两块板互锁,`Linked/LinkedChartContext.cs:196-225`)。给它加一个公开入口,内置 Feature 的业务回调一律走它。

```csharp
// DataBlackboard:新增公开入口,复用现有 _afterUnlock 队列(:120)。
// 现在的 PostAfterUnlock(IAfterUnlockAction) 是 internal,接口也是 internal(:394)。
public void PostAfterUnlock(Action<DataBlackboard> action)
{
    if (action == null) throw new ArgumentNullException(nameof(action));
    PostAfterUnlock(new DelegateAfterUnlock(action));   // 只能在写锁内调,否则抛(:124-125)
}

private sealed class DelegateAfterUnlock : IAfterUnlockAction
{
    private readonly Action<DataBlackboard> _action;
    public DelegateAfterUnlock(Action<DataBlackboard> action) => _action = action;
    public void Run(DataBlackboard board) => _action(board);
}
```

```csharp
// DraggableLineFeature 的 Watch 里
case PointerPhase.End:
{
    double committed = _dragPrice;
    // 锁外、同一 UI 线程、路由器这次分发结束后执行;业务在里面做什么都不卡黑板
```

```csharp
// 路由器:分发 = 持写锁写一次端口。Watch 在锁内跑完;WriteLockScope.Dispose 退出最后一层锁后
// 再跑登记的锁外回调(DataBlackboard.cs:90-100)。Debug 下顺手抓"回调太慢"。
private void Dispatch(DataBlackboard board, in PointerGesture g)
{
#if DEBUG
    long t0 = Stopwatch.GetTimestamp();
#endif
    using (board.AcquireWriteLock())
        board.ForceWrite(_ports.GesturePort, g);       // Sequence 每次递增,ForceWrite 保证 Watch 一定触发
#if DEBUG
    double ms = (Stopwatch.GetTimestamp() - t0) * 1000.0 / Stopwatch.Frequency;
    if (ms > 4) Debug.WriteLine($"[Pointer] {g.Phase} 的 Watch 回调持写锁 {ms:F1}ms,重活请放 PostAfterUnlock");
#endif
}
```

### R2. 拖价格线和 Y 轴自动量程互相拉扯

**先更正上一轮的说法**:现在的自动量程只吃列(`UniversalAutoScaleFeature.ValuePorts`,`Features/UniversalAutoScaleFeature.cs:80`),一条线的单个价格不在里面,**默认不会拉扯**。只有业务把价格也塞进量程计算(比如"委托线必须一直可见")才会出现。

**投影用最新的,不冻结**。拖动中行情跳动、Y 量程自己在变,用最新投影才能保证线始终在鼠标底下;冻结按下时的投影反而会让线和鼠标错开。

**真要把价格放进量程**:拖动中别动参与量程的那个端口,松手才写。这也顺带回答了 Q4。

```csharp
public sealed record DraggableLineOptions
{
    public Action<double>? OnCommitted { get; init; }
    /// <summary>true(默认)= 拖动中实时写 PricePort;false = 拖动中只动草稿,松手才写 PricePort。
    /// PricePort 参与自动量程、或者下单界面不想被拖动过程刷新时用 false。</summary>
    public bool LiveWrite { get; init; } = true;
    public float Tolerance { get; init; } = 4;
}

// Feature 内部:草稿端口,不拖时是 NaN
private readonly DataPort<double> _draftPort = new DataPort<double>("DraggableLine_Draft");

// Watch
case PointerPhase.Move:
    _dragPrice = _projection.ScreenToValue(g.Position.Y - _grabOffset);
    Write(board, Options.LiveWrite ? PricePort : _draftPort, _dragPrice);
    break;
case PointerPhase.End:
```

### R3. 区域落后一帧,按下"点了没反应"

**问题**:状态刚变(画线刚锁定),区域要到下一帧才撤。这一帧里按下,命中旧区域,按下被占住却没人处理。

### R4. Watch 里写端口层层嵌套

**问题**:回调里写价格端口,会在同一调用栈里再触发别的 Watch;回调里如果去碰鼠标捕获(`ReleaseMouseCapture`),会同步触发 LostMouseCapture,路由器在分发途中被重入。

**对策**:三条。

```csharp
// ① 路由器防重入:分发途中不允许再分发(业务在回调里写了 GesturePort,或回调间接触发了路由器)
private bool _dispatching;
private void Dispatch(DataBlackboard board, in PointerGesture g)
{
    if (_dispatching)
        throw new InvalidOperationException("Pointer.GesturePort 只能由路由器写;Watch 回调里不要写它,也不要碰鼠标捕获。");
    _dispatching = true;
    try { using (board.AcquireWriteLock()) board.ForceWrite(_ports.GesturePort, g); }
    finally { _dispatching = false; }
}

// ② 结束顺序:先回到空闲、再释放捕获、最后分发 End。
//    释放捕获会同步触发 LostMouseCapture,这时状态已是空闲,不会误判成"被打断"(业务原型踩过同一个坑)。
private void OnRelease(in PointerInput input)
{
    var owner = _active;
    _active = null;
    if (_capturing) { _capturing = false; _input.ReleaseCapture(); }
    _cursor.Restore();
    Dispatch(_board, PointerGesture.End(owner, input, _pressPos, NextSeq()));
}

private void OnLostCapture()
{
    if (_active == null) return;          // 自己释放引起的,忽略
    var owner = _active;
    _active = null;
    _capturing = false;
    Dispatch(_board, PointerGesture.Cancel(owner, PointerCancelReason.CaptureLost, NextSeq()));
}
```

```csharp
// ③ 业务一次写多个端口,合成一次通知(接口评审 G9 的约定),嵌套只发生一次
case PointerPhase.Click:
    using (board.BeginTransaction())
    {
        board.WriteIfChanged(_pendingStartPort, (ChartAnchor?)a);
        board.WriteIfChanged(_pendingEndPort, (ChartAnchor?)a);
    }
    break;
```

`GesturePort` 在 `PointerPorts` 上标 `[PortDirection(PortDirection.Output)]`,TopologyInspector 里能看出唯一写者;Debug 下 ① 的断言兜底。
