# 指针路由:区域 → 行为链 → 旁听

> 状态:**已实现**(分支 `claude/builtin-interaction-design-4ca2c9`,基于整合分支 ad371e5)。
> 本文记录指针输入的最终路由模型,以及它替换掉的"兜底处理器"结构。设计讨论的结论在 §6。

## 0. 一句话

ChartCell 上只有一个输入入口(指针路由器的 WPF 适配器)。一次输入依次走 **捕获者 → 区域 → 行为链 → 旁听**;业务做交互只用"发布区域 + 读手势端口",内置的平移 / 缩放 / 十字光标是行为链上的一组小行为,由 `ChartInteractionFeature` 按 `SupportedModes` 装上。

## 1. 参与者

| 类别 | 是谁 | 怎么加入 | 能不能拦 |
|---|---|---|---|
| 区域 | 画线、可拖线、测量、元素悬停 | `OnProject` 里 `ctx.Pointer().Publish(region)` | 能:命中即认领这次手势 |
| 行为 | 内置交互(平移、框选、双击复原、滚轮、键盘、惯性、触屏、十字光标) | `ChartInteractionFeature.OnCompose` 往本 cell 的行为链上装一组 | 能拦后面的行为;拦不了区域 |
| 旁听 | 读端口的人 | `Pointer.GesturePort`、`Pointer.IsPointerOver`、`PointerHitPort` | 不能 |

业务能看到的输入接口只有四样:`ctx.Pointer().Publish`、`flow.WatchPointer`、`ctx.UseProjection`、读端口。直接订 WPF 事件的 `this.OnMouse / OnKey / OnTouch` 标 `[Obsolete]`。

## 2. 一次输入怎么走

```
WPF 事件 ── WpfPointerAdapter(唯一订平台输入的文件)
   │
   ├─ Preview(隧道,子控件之前)
   │     ① 捕获者:有进行中的区域手势 → 给它
   │     ② 区域:按下时裁决(优先级 → 图层 → 距离),命中 → 认领、标 Handled
   │         认领的按下也交给行为链一次(PointerRoute.ClaimedAbove = true):停惯性、武装 hover、就地投影十字光标
   │     Esc:有手势 → Cancel;有模态区域 → Escape;都没有 → 往下
   │
   ├─ 冒泡(子控件之后;子控件标了 Handled 就到不了)
   │     ③ 行为链:按顺序问,任何一个行为返回 true 链到此为止
   │
   └─ ④ 旁听:写 GesturePort(手势每一步)、IsPointerOver(进出)
```

| 输入 | ① 捕获者 | ② 区域 | ③ 行为链 | ④ 旁听 |
|---|---|---|---|---|
| 按下 | 手势中按另一个键 → Cancel | 命中 → 认领 | 双击复原 / 框选 / 平移 | — |
| 移动 | 拖动 → Move,不拦 | 悬停进出、光标 | 平移 / 框选 / 十字光标 | — |
| 松开 | End / Click | — | 结束平移、惯性 | — |
| 滚轮 | 不拦 | 区域不收 | 缩放 | — |
| Esc | 有手势 → Cancel | 有模态 → Escape | DismissOnEscape | — |
| 其他键 | — | — | 导航;Keyboard 模式下任意键停惯性 | — |
| 进入 / 离开 | 拖出图外不算离开 | 悬停离开 | 清十字光标 | IsPointerOver |
| 触屏 | — | 不进区域 | 平移 / 捏合(区域手势中忽略) | — |

只接受点击的区域被拖出阈值:区域输了(`Cancel(SupersededByPan)`),路由器把这次按下原样重放给行为链,跟没点中区域一样走双击 / 框选 / 平移;行为接手抓鼠标就把捕获转给它。

## 3. 行为链

`Hevo.Charting/Interaction/Behaviors/`:

| 类 | 职责 |
|---|---|
| `IPointerBehavior` | `bool OnInput(ref PointerEvent e, in PointerRoute route)`,返回 true = 到此为止 |
| `PointerEvent` / `PointerRoute` | 一次输入(种类、位置、键、滚轮、触屏量);路由上下文(已被认领 / 区域手势进行中 / 藏十字光标) |
| `PointerBehaviorChain` | 本 cell 的链,按所属 Feature 分组;组的先后 = 装配顺序;所属 Feature 挂起时整组跳过;卸载时整组摘掉;Debug 下行为写黑板记在所属 Feature 名下 |
| `ChartInteractionState` | 一组行为共用的状态(指针位置、武装、平移 / 框选中、区域手势中、惯性)和视口算法(平移换算、缩放、命中写 `PointerHitPort`) |
| `InertiaPanRunner` | 惯性;帧时钟由适配器提供(可同时挂多个) |

`ChartInteractionFeature` 装的顺序(即优先级,同原来按下时的分流顺序):

1. `PointerStateBehavior`(总是):任何按下拿焦点、停惯性、武装 hover;移动记位置;路由变化时屏蔽触屏 / 暂停十字光标。从不拦。
2. `DoubleClickResetBehavior`(`DoubleClickReset`)
3. `BoxZoomBehavior`(`BoxZoom`)
4. `PanBehavior`(`Pan`,松手起惯性看 `InertiaPan`)
5. `HoverBehavior`(总是;投影看 `Hover`)
6. `WheelZoomBehavior`(`Zoom`)
7. `KeyboardBehavior`(`Keyboard` 或 `KeyboardZoom`)
8. `TouchBehavior`(总是;平移看 `Pan`、捏合看 `Zoom`)

`ChartInteractionFeature` 的公开 API(类型、属性、默认值)不变,只剩 `OnCompose`(装行为、挂框选图层、Watch ActiveRange)和 `OnProject`(框选矩形搬给图层)。

## 4. 删掉的

- `IPointerBackground`(11 个成员的跨对象接口)和 `PointerRegionStore.Background` 单槽。路由器和行为链之间只剩"交一次输入 + 路由上下文"。
- `ChartInteractionFeature` 里的输入状态机(搬进各行为,算法逐行不改)。
- `CrosshairFeature` 自己订的 MouseEnter / MouseLeave,改读 `Pointer.IsPointerOver`。

## 6. 设计讨论的结论

- **为什么不让 ChartInteractionFeature 回到自己订 WPF 事件**:那样业务交互就有两条路(声明式区域 / 命令式订事件抢 Handled),两条路的先后要靠 WPF 处理器顺序解释,接口不可能统一。
- **为什么是行为链而不是一个大兜底**:参考 SciChart(`ChartModifier` 列表 + `Handled`)、OpenLayers(`Interaction` 集合,`handleEvent` 返回 false 停止)、OxyPlot(元素先 HitTest,控制器后处理)、Mapbox(dragPan / scrollZoom 各自 handler)、Flutter(gesture arena)。共同点:对象先命中先拿;内置导航拆成可单独开关的小部件;一条由框架决定顺序的链;不依赖平台事件处理器顺序。
- **区域在隧道、行为在冒泡**:区域要抢在一切之前(画线);行为让图表内的子控件(widget 里的按钮)先处理,跟 main 一致。
- **行为暂不公开**:业务需求用区域都能覆盖;等画线框架需要"自定义导航"再公开 `IPointerBehavior`。
- **命名**:`Behavior`(不叫 Modifier,避开 `PointerModifiers` 修饰键;不叫 Interaction,避开 `ChartInteractionFeature` / 命名空间)。
- **路由器不参与投影的开关**:不加。为一次空调用在 Feature 基类上加开关不值得,改基线。
