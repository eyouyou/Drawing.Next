# 内置交互归路由器:设计

> 状态:**设计稿,待评审,未实现。** 本文不含实现代码,只有说明 API 形状的片段。
> 基线:整合分支 `claude/framework-window-integration-0b79be` 的 ad371e5(指针路由器一二期、G6、G7、pane 分隔条、黑板第一批已合入)。文中 `文件:行号` 不带提交号的都指 ad371e5;写 `main:行号` 的指 `origin/main` 61ef76f(路由器之前)的 `Hevo.Charting/Features/ChartInteractionFeature.cs`。
> 相关:[手势接口方案](./手势接口方案.md)(定稿)、[变更说明-框架窗口-2026-10](./变更说明-框架窗口-2026-10.md) §7(D1–D6)。

## 0. 三分钟版

**现在**:框架里有两种模型。业务手势是"Feature 用数据声明区域,路由器执行";内置的平移 / 缩放 / 十字光标却是"路由器把事件转给一个 Feature(`IPointerBackground`),Feature 自己跑状态机"。为此有一个 11 个成员的跨对象接口、一个"最后装配的赢"的单槽,还带出了 D1、D2、D3 和 render-probe +1。

**改成**:只剩一种模型——**Feature 用数据声明,路由器这一侧执行**。

- `ChartInteractionFeature` 公开 API 一个不变,但不再有任何输入方法和状态机。它在 `OnCompose` 里交出一份不可变的 `InteractionSettings`(全部选项 + 要写的端口),在 `OnProject` 里只发布框选矩形的 Trait(跟现在一样)。
- 平移、框选、双击复原、滚轮、键盘(含 KeyboardZoom)、惯性、触屏、hover / 十字光标这些行为,原样搬进 `Interaction/Builtin/` 下的 internal 类,由路由器一侧持有。跟区域的配合(认领时停惯性 / 武装 hover / 就地投影,只接受点击的区域被拖走后从按下点平移,手势中藏十字光标)变成子系统内部的直接调用,不再经过 Feature。
- `IPointerBackground`、`PointerRegionStore.Background` 单槽删除。
- 每份声明各自一个行为实例,**WPF 冒泡处理器在 `ChartInteractionFeature.OnCompose` 那一刻挂上**:订阅顺序跟 main 完全一样(D3 消失,`Transact` 重新加入时也重新排到末尾,跟 main 一样)。两个 `ChartInteractionFeature` 各收各的输入,也跟 main 一样(D2 不再是结构问题)。
- D1 复原:Keyboard 模式下任意键停惯性。
- `PointerRouterFeature` 不参与投影:Feature 基类加一个 internal 开关,`ProjectAll` 跳过它,render-probe Resize 回到 12。

顺带修回两处之前没列出来的差异:挂起时内置交互不再响应输入(D7,main 就是这样),Debug 拓扑追踪把内置交互的黑板写入记在 `ChartInteractionFeature` 名下(D8)。

估计 3–3.5 人日。要用户定的见 §12。

### 1.2 后果

1. **两套模型**。业务手势:Feature 发布数据,路由器执行。内置手势:路由器调 Feature 的方法,Feature 执行。后者让 `ChartInteractionFeature` 同时是"配置持有者"和"输入处理器",路由器得知道它的内部状态(`SetGestureActive` 要它屏蔽触屏、离开不清 hit;`BeginPanFrom` 要它进平移态)。
2. **D2:单槽**。`Background = this`(`ChartInteractionFeature.cs:225`)后装配的覆盖先装配的;卸载时只在自己是当前值时清空(`:752`)。main 上两个实例各订各的事件,各自都能用。
3. **D3:订阅顺序**。适配器在 `PointerRouterFeature.OnCompose` 里挂处理器(`PointerRouterFeature.cs:54` → `WpfPointerAdapter.cs:75-83`)。路由器由 `EnsureBaseFeatures` 先于 `DefineFeatures` 加入(`Core/ReactiveSchema.cs:747-753`),Phase 也是 PreLayout(`PointerRouterFeature.cs:26`),所以它是第一个装配的 PreLayout Feature(`ReactiveSchema.cs:758` 按 Phase 稳定排序,`:840-851` 按序装配)。main 上这些处理器在 `ChartInteractionFeature.OnCompose` 里挂(main:240、297、339、346、378、390、411、426),排在更早装配的 Feature 的处理器之后。于是"在它之前装配、在冒泡里标 Handled 的业务处理器能挡住平移"这一点丢了。`Transact` 重新加入时 main 会把处理器重新挂到末尾(已接受差异 2),现在不会。
4. **D1:按键**。适配器只把 Esc / 方向键交给兜底(`WpfPointerAdapter.cs:157`,`key != PointerKey.Other`)。main 在 Keyboard 模式下先 `_inertia.Stop()` 再看是哪个键(main:403-404),任何键都停惯性。
5. **render-probe +1**。`ProjectAll` 在环境 FullPass 时投影每个 Feature(`Core/ReactiveSchema.cs:632-641`),`PointerRouterFeature` 的空 `OnProject` 也算一次,`bars=2000|charts=1|Resize|inc` 的 `Feature重算/帧` 12 → 13(变更说明 §7"计数基线")。
6. **新发现 D7:挂起**。main 的处理器经 `OnUIEvent` → `OwnedBy(this)`(`WorkFlow/WorkflowWPFEventExtension.cs:45-47`,`Core/ChartFeature.cs:319-333`)登记成 Feature 的可暂停订阅,`Feature.Suspend` 会关掉它们的闸门(`Core/Feature.cs:113-120`,`WorkFlow/WorkFlowEngine.cs:86-89`),挂起期间输入被吞掉。现在适配器的处理器是裸 `AddHandler`(`WpfPointerAdapter.cs:72-83`),兜底方法也不看 `IsActive`(`ChartInteractionFeature.cs:803-1022`),挂起的图表照样平移、写黑板。变更说明 §7 把"挂起卸载"列为等价,这一条漏了。
7. **新发现 D8:Debug 拓扑追踪**。main 的处理器在 `TopologyTracer.EnterScope(feature)` 里执行(`WorkflowWPFEventExtension.cs:33`,仅 Debug),拓扑面板能看到 `UserRange` / `PointerHitPort` 是 `ChartInteractionFeature` 写的。现在适配器直接调兜底方法,没有这个作用域。只影响 Debug 工具。

### 1.3 为什么不打补丁

D1 改一行、D2 设 `IsSingleton`、D3 把适配器的冒泡处理器延后挂,各自都能修,但修完结构还是"路由器调 Feature 的方法",接口还在,而且 `IsSingleton` 本身会改变行为(第二个实例把第一个顶掉,main 上是两个都在)。用户要的是结构上干净的方案,所以本文从模型上改。

## 2. 目标与非目标

**目标**

1. 只有一种模型:Feature 只用数据声明(区域在 `OnProject`、内置交互的配置在 `OnCompose`),执行全部在 `Hevo.Charting/Interaction/` 里。
2. `ChartInteractionFeature` 不实现任何 internal 接口、没有输入方法、没有输入状态;公开 API(类型、属性、默认值、`[PortDirection]`)一个不改,蓝图序列化结果不变。
3. 没有区域时,行为与 **main** 逐项一致,包括 D1、D2、D3、D7、D8 和 `Transact` 重新加入的顺序;有区域时,与当前整合分支一致。
4. 行为代码是**搬过来的**:算法、判断顺序、锁的拿法不改。
5. render-probe 回到基线 12,不改 `render-probe-baseline.json`。
6. 删掉 `IPointerBackground` 和 `Background` 单槽。

**非目标**

- 不改区域 / 手势端口的公开契约(`PointerRegion`、`PointerGesture`、`WatchPointer`)和裁决规则。
- 不改 D4(ElementPlot 的区域算"发布过区域")、D6(非 `ChartReactiveSchema` 没有路由器);这两条跟本设计无关,另见 §12。
- 不让 `CrosshairFeature` 停止自己订 MouseEnter / MouseLeave(`Features/CrosshairFeature.cs:226-227`),那是单独的一步。
- 不改兜底平移不分按键(手势方案 Q6)。
- 不做 Avalonia 适配,只是不再挡路。

## 3. 总体结构

```
                 ┌─────────────── Feature(只声明) ────────────────┐
 OnProject:      │ 业务 / 内置交互 Feature:ctx.Pointer().Publish(区域)│
 OnCompose:      │ ChartInteractionFeature:Builtins.Declare(this, 设置, flow) │
                 └──────────────────────┬─────────────────────────┘
                                        │ 只有数据(不可变记录)
 ┌──────────────── Hevo.Charting/Interaction(执行) ───────────────────┐
 │ PointerRegionStore ── 区域表(按 Feature)+ BuiltinInteractionSet(按声明)│
 │ PointerRouter ─────── 区域裁决、手势端口;认领时直接调 Set 的配合方法      │
 │ BuiltinInteractionSet ─ 声明列表(装配顺序);对路由器的配合方法 = 扇出    │
 │ BuiltinInteraction ×N ─ 每份声明一个:平移 / 框选 / 双击 / 滚轮 / 键盘 /   │
 │                         惯性 / 触屏 / hover(从 ChartInteractionFeature 搬来)│
 │ WpfPointerAdapter ──── 唯一碰 WPF 输入的文件:                           │
 │      路由器那一组处理器:路由器装配时挂(PreLayout 第一个)                 │
 │      每个 BuiltinInteraction 一组处理器:Declare 那一刻挂(= main 的位置)   │
 └──────────────────────────────────────────────────────────────────┘
```

两类声明的区别只在时机:区域的几何每帧在变,所以随帧发布;内置交互的配置是 init-only 属性,装配后不会变,所以装配时交一次。理由和备选方案见 §6.1。

### 4.1 `ChartInteractionFeature` 之后的样子

```csharp
public class ChartInteractionFeature : ChartFeature          // 不再实现 IPointerBackground
```

## 6. 关键决定

### 6.1 配置在 `OnCompose` 交出,不在 `OnProject` 发布共享 Trait

**决定**:`ChartInteractionFeature.OnCompose` 调 `Builtins.Declare(this, settings, flow)`;不发布 `InteractionSettingsTrait` 到共享区。

**为什么**(按分量排):

1. **D3 本来就要求在这一刻做事**。处理器的订阅顺序只能由"在谁的装配时刻挂上"决定,这个时刻就是 `ChartInteractionFeature.OnCompose`。哪怕配置走 Trait,也还得在这里挂处理器。既然这一刻必须有一次调用,配置跟着这次调用交出去最直接。
2. **共享区 Trait 拔不掉**。共享 Trait 进 chart 级的实时袋(`Core/RenderContext.cs:191-195`,帧尾 `SubmitSync` 合并,`:211-212`),Feature 卸载不会清它。`Transact` 拔掉 `ChartInteractionFeature` 后,行为侧还会读到旧配置、照样平移。main 上拔掉就不平移了(订阅随 `OwnedBy` 释放)。要补就得在 `Decompose` 里另发一次"空配置",又是一个补丁。
3. **共享区 Trait 天然"后写的赢"**。两个 `ChartInteractionFeature` 往同一个类型的共享 Trait 里写,按投影顺序后写的覆盖前面的,这就是 D2 换个地方再出现一次。
4. **时机差一帧**。`OnProject` 发布要到下一次 `SubmitSync` 才可见;`Transact` 热加入后、下一帧之前的输入会落空。main 上 `OnCompose` 订阅即刻生效。
5. **没有要随帧变的东西**。所有字段来自 init-only 属性或装配期就定的端口(§5),装配后不会变。随帧发布对它们没有意义。

**一致性**:这仍然是"Feature 用数据声明"。区域随帧是因为几何随帧;配置在装配期是因为它在装配期就定了。Feature 交出的只有一个不可变记录和自己的 `flow`(给 Watch 定生命周期和登记顺序),不实现任何回调。

**备选**:按任务原提法在 `OnProject` 发布 `InteractionSettingsTrait`(共享作用域),行为侧在路由器装配时挂处理器、事件时读 Trait。上面 1–4 条都不满足,否掉。

### 6.2 零个、一个、两个 `ChartInteractionFeature`

**规则:每份声明一个独立的 `BuiltinInteraction`,各挂一组处理器,互不知道对方。** 跟 main 上"每个实例各订各的事件"是同一个语义,所以没有"谁赢"的问题,D2 作为结构问题消失。

| 数量 | 行为 | 与 main |
|---|---|---|
| 0 | 没有内置处理器:不平移、不缩放、不写 `PointerHitPort`。区域照常裁决;认领时的配合方法是空扇出 | 同 main(没有 `ChartInteractionFeature` 就没有这些) |
| 1 | 正常 | 同 main |
| 2+ | 每份各自处理同一个事件(两份都开 Pan 就平移两倍,两份都开 Hover 就各写各的 hit 端口);区域认领时每份都停惯性、武装、投影;只接受点击的区域被拖走时按装配顺序每份都 `BeginPanFrom`,任一份接手就把捕获转给平移;区域双击计数取第一份的窗口 | 同 main;区域相关的部分 main 没有,按"跟没被认领的按下一样"处理 |

**不用 `IsSingleton`**:`ReactiveSchema.Add` 遇到同类型会把旧实例拔掉(`Core/ReactiveSchema.cs:464-468`),这是行为变化(main 上第二个不会顶掉第一个);而且它按 `GetType()` 精确比较,子类躲得过去,规则不完整。

**Debug 提示**:同一 cell 出现第二份声明时 `Debug.WriteLine` 一次("两个 ChartInteractionFeature 会各自处理同一次输入"),不抛、不改行为。要不要做,见 §12 Q2。

### 6.3 `Transact` 热拔插

- **拔**:`Feature.Decompose` 第 0 步已经调 `chart.PointerRegions.RemoveOwner(this)`(`Core/Feature.cs:316`),此时它的 Watch 还活着(令牌在 `:327` 才结束)。`RemoveOwner` 先通知路由器(现 `PointerRegionStore.cs:149`),再 `Builtins?.Remove(owner)` → `BuiltinInteraction.Detach()`:解绑八个处理器、停惯性、若自己正抓着鼠标(平移 / 框选中)就放掉、框选状态写回 `Inactive`。然后基类照常摘图层(`Feature.cs:319-323`)、结束令牌(视口 Watch 失效)。
  - 与 main 的差别:main 拔掉后惯性还在跑(D5),平移中拔掉时鼠标捕获一直留在 cell 上(没人释放)。新设计两者都收拾掉。两条都是"拔掉的东西还在动",按修 bug 处理,列入 §12 Q3。
- **加 / 重新加**:`Transact` 对新增 Feature 走 `InternalCompose`(`ReactiveSchema.cs:418`)→ `OnCompose` → `Declare`,处理器在这一刻追加到 cell 处理器列表**末尾**,跟 main 一样;已接受差异 2("Transact 重新加入时,交互处理器不再移到订阅顺序末尾")不再存在。输入立即生效,不等下一帧(§6.1 第 4 条)。
- **同一实例拔了再加**:`Detach` 后旧 `BuiltinInteraction` 丢弃,`Declare` 建新的,状态从初值开始(`_isHoverArmed = !RequireClickToActivate`),同 main 每次 `OnCompose` 重设(main:234)。

### 6.4 Suspend / Resume

- **输入闸门**:`BuiltinInteraction` 每个输入入口先看 `owner.IsActive`(`Core/Feature.cs:111`),为 false 就返回。`ReactiveSchema.Suspend` 级联每个 Feature(`ReactiveSchema.cs:261-264`),所以效果跟 main 的 `PauseGate` 相同:处理器还挂着,事件被吞掉(D7 修回)。
- **惯性**:main 的 `ChartInteractionFeature` 没有 `OnSuspend`,惯性挂起期间继续跑(main:770 的 `CompositionTarget.Rendering` 不受 `PauseGate` 管)。新设计不改:挂起不停惯性。见 §12 Q7。
- **路由器**:`PointerRouterFeature.OnSuspend` → `_router.OnSuspend()`(`PointerRouterFeature.cs:64`、`PointerRouter.cs:336-341`)不变。
- **Resume**:闸门自然打开;`ReactiveSchema.Resume` 末尾 `InvalidateEnvironment`(`:288`)照常。

### 6.6 线程、锁、热路径

- **线程**:WPF 输入、惯性帧(`CompositionTarget.Rendering`)都在 UI 线程,同今天。视口 Watch 跑在提交 `ActiveRange` 的那个线程,同 main:444 和今天的 `:235`,不改(它读 `_lastMousePos` 等字段的线程问题 main 就有,本设计不扩大也不修)。
- **锁**:每个方法的锁按原样搬:hover 一次 `AcquireUpgradeableReadLock` + 一次 `AcquireWriteLock` + `WriteIfChanged(PointerHitPort)`(`:937-943` → `:739-747`);平移、缩放、框选、键盘同理。不新增锁,不新增端口写。
- **hover 热路径**(MouseMove,无区域):路由器 Preview 一次 `OnMove`(看 `Count == 0` 返回,同今天);内置冒泡一次 `OnPointerMove`。比今天多的只有两次字段读(`owner.IsActive`、`_settings`),比 main 少一层 `WorkflowEngine` 包装和 `lock(lockObj)`(`WorkFlowEngine.cs:89`)。零分配:`PointerInput` 是 struct,设置是装配期建好的引用。
- **配置不加锁**:`InteractionSettings` 不可变,`BuiltinInteractionSet` 的列表只在 UI 线程上的装配 / 卸载里改,输入也在 UI 线程,不需要锁。

### 6.7 D3:订阅顺序怎么保证

1. 路由器那组(Preview、LostMouseCapture、路由器的 MouseLeave、Esc)仍在 `PointerRouterFeature.OnCompose` 挂。它们只在有区域 / 手势 / 模态时才标 Handled(`WpfPointerAdapter.cs:118`、`:125`、`:154`),没有区域时对任何人都透明,跟 main 上"不存在"等价。

3. 八个处理器的先后跟 main 的 `OnCompose` 一样:Down、Up、Leave、Move、Wheel、PreviewKeyDown、ManipulationStarting、ManipulationDelta;视口 Watch 在它们之后注册(main:444)。
4. 都是不带 handledEventsToo 的 `AddHandler`:在它之前的处理器(更早装配的 Feature、业务在模板应用前直接挂在 cell 上的)标了 Handled,内置收不到;在它之后的收不到内置标的 Handled(内置只在键盘里标,`ChartInteractionFeature.cs:961-989` 的返回值,同 main:399、407-408)。
5. `Transact` 重新加入 → 追加到末尾(§6.3)。

### 6.8 D1:任意键停惯性

`BuiltinInteraction.OnKeyDown` 按 main 的顺序:

1. Esc 且 `DismissOnEscape` → 解除武装、清 hit、Handled(main:395-401)。
