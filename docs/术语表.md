# 术语表

每个术语一句话。"类比"一列对照前端(React / Redux)或通用概念,只为帮你建立直觉,细节以本项目为准。

## 数据

| 术语 | 一句话 | 类比 |
|------|--------|------|
| **黑板** `DataBlackboard` | 一张图的全部数据状态:端口 → 值的字典,内部用读写锁保护。`OnProject` 里的 `UsePort` 由框架在外层统一加读锁,业务代码不用自己加锁;只有自己在 `OnCompose` 订阅回调或后台线程里读写黑板时才需要加(`AcquireReadLock` / `AcquireWriteLock`) | Redux store |
| **端口** `DataPort<T>` | 黑板上一个强类型的格子,读写都按它寻址;蓝图里按名字连线,同名即连通 | store 里的一个 key(带类型) |
| **列** `ReadOnlyMemory<T>` | 端口里存的一整列数据(如全部收盘价);只在拿到它的那一帧 / 那次回调内有效 | 不可变数组快照 |
| **数据源** `DataSource` / `BufferedDataSource` / `ReactiveDataSource` | 产出一批批业务行(如 K 线)的对象,负责请求、缓存、推送 | 数据请求层 / API client |
| **管线** `Pipe()` / `LinkStream` | 把数据源推来的行拆成列写进黑板;`Map` / `AutoMap` 是字段到端口的映射 | reducer |
| **摄入器** Ingestor | 管线里真正执行"行 → 列"的那一步,系统中唯一认识业务行类型的地方 | reducer 里的一个 case |
| **`[Port]`** | 贴在业务行属性上,生成器据此生成一组端口 | 代码生成的 selector 集合 |
| **`ColumnPublisher<T>` / `ResultBufferPool`** | 往端口发布列时的缓冲池:每次给一块"没人在读"的新缓冲,零分配又不踩正在读的数组 | 不可变更新 + 对象池 |

## 装配与执行

| 术语 | 一句话 | 类比 |
|------|--------|------|
| **Schema** `ReactiveSchema` / `ChartReactiveSchema` | 一张图的定义:`DefineDataFlow` 接数据,`DefineFeatures` 挂功能 | 页面根组件 |
| **Feature** `ChartFeature` | 一个功能单元(一条线、一根轴、十字光标、一个指标计算),自带图层 | 组件 |
| **`OnCompose`** | Feature 装配时跑一次:注册图层、订阅数据、发布静态样式 | 挂载(`useEffect(..., [])`) |
| **`OnProject`** | 每帧(数据或环境变了时)跑:读黑板,把数据翻译成 Trait | render 函数 |
| **`UsePort`** | 在 `OnProject` 里读一个端口并登记依赖,端口变了才会再触发本 Feature | `useSelector` |
| **`UseMemo`** | Feature 内按依赖缓存计算结果 | `useMemo` |
| **Hook 规则** | Hook 只在 `OnProject` 帧路径里调;`UseMemo` 直接写在 `OnProject` 里,不写进 helper / 循环 / lambda / 本地函数(`HEVO008`,Debug 构建下运行时也会拦)。`UsePort` 可以放进分支,没读的帧不更新版本 | React Hooks 规则(但不要求固定顺序) |
| **`FeaturePhase`** | Feature 每帧的执行顺序(`PreLayout` → `Layout` → `Scale` → `Series` → `Interaction`,计算节点(`ComputeFeatureBase` 派生)默认 Phase 为 50,在 `Layout`(0)之后、`Scale`(100)之前),不靠 `Add` 的先后 | 渲染顺序 / 生命周期阶段 |
| **四段 builder** `Environment / Axes / Series / Interactions` | Schema 里按领域分组挂 Feature 的 DSL,如 `canvas.Series(s => s.AddLine(...))` | 声明式组件树 |
| **`Transact`** | 运行时增删 Feature 的事务:摘挂订阅、补发数据一次完成,不出撕裂帧 | 批量更新(`batch`) |
| **`Seed`** | 装配时往共享上下文放一份初始 Trait(如比例尺策略) | Context Provider 的初始值 |
| **`WatchAsync` / `Watch`** | 端口变化时触发的回调;`WatchAsync` 在线程池跑,用于指标计算 | store 订阅 + 副作用(后台线程) |
| **`IWorkflow<T>`** | 自研的轻量响应式流(替代 System.Reactive) | Observable |
| **Aspect** | 包在 Feature 外的物理容器,往 WPF 视觉树里插装饰(边框、图例) | 高阶组件 / 装饰器 |

## 渲染

| 术语 | 一句话 | 类比 |
|------|--------|------|
| **Trait** `IVisualTrait` | Feature 交给图层的只读快照(数据、样式、坐标轴范围),纯 `record` | 视图 props |
| **Layer** `ChartLayer` | 只做"取 Trait → 投影 → 录指令"的无状态绘制器,必须 `partial` | 纯函数组件里的 draw 部分 / canvas 子层 |
| **`IConsumes<T>`** | 声明 Layer 读哪些 Trait;由生成器扫描 `OnUpdate` 自动生成,不手写 | props 类型声明 |
| **`IDrawingSink`** | Layer 录制绘制指令的接口(画线、矩形、文字),与具体后端无关 | Canvas 2D context |
| **`RenderMode`** | 图层怎么上屏:`Software`(WPF 矢量)/ `Bitmap`(框架光栅化成位图) | 渲染后端开关 |
| **`ScaleStrategyTrait` / `IScale`** | 逻辑值 ↔ 屏幕比例的映射(自变量 `DomainScale`、因变量 `ValueScale`);坐标只能经它投影 | d3 scale |
| **Viewport** `ViewportPorts` | X 方向当前可见的索引区间等一组端口,挂在 `ChartCell` 上 | 滚动窗口 / 可视区域 |
| **AutoScale** `UniversalAutoScaleFeature` | 按可见区间算出 Y 轴量程,写进量程端口 | 自适应坐标轴 |
| **`FieldMeta`** | 字段的名称 / 颜色 / 格式的唯一来源,图例、Tooltip、Header 共用 | 字段元数据 / i18n 配置 |
| **`ChartCell` / `ChartHost`** | 承载一张图的 WPF 控件 / 把 Schema 嵌进 XAML 的宿主控件 | 挂载点(`root.render`) |

## 低代码

| 术语 | 一句话 | 类比 |
|------|--------|------|
| **蓝图** `ChartBlueprint` | 用 JSON 描述的一张图:数据源 + Feature 节点 + 端口连线 | JSON 版组件树 |
| **Dashboard** | 多张蓝图(cell)按主图 / 副图联动排在一起 | 多面板页面 |
| **`ComponentRegistry`** | 蓝图 `TypeName` → C# 类型的注册表 | 组件注册表 |
| **`[BlueprintHandler]` / `BlueprintHandlerRegistry`** | 给 C# / Python 方法起名,蓝图按名字引用 | 命名回调注册表 |
| **`ComputeFeature`** | 蓝图里的计算节点:输入列 → 委托 → 输出列 | 派生状态 selector |
| **`PlotFeature`** | 一个委托返回多条序列并自己画出来的节点 | 自带渲染的复合组件 |
| **`ComputeFeatureBase`** | 计算 Feature 的基类(`ComputeFeature` / `IncrementalComputeFeature` 都派生自它);进阶:现成的不够用时才自己继承 | 自定义 hook 的底座 |
| **DryRun** | 运行前对蓝图做的静态检查,问题以 `BP_*` 诊断码报出 | lint / 类型检查 |
| **`HEVO001`、`HEVO002`、`HEVO007`、`HEVO008`** | Roslyn 分析器在编译期拦截的架构红线(跨帧缓存端口数据、`OnProject` 里写黑板、`UseMemo` 只能直接写在 `OnProject` 等) | ESLint 规则 |
