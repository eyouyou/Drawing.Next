# 变更说明:核心与 WPF 宿主拆分(2026-10)

引擎拆成两个程序集,为后续接 Avalonia 等宿主留口子。**业务行为不变**,但有几处签名要跟着改(机械替换,编译错误会逐条指出)。

## 拆成什么样

| 程序集 | 内容 | 依赖 |
|---|---|---|
| `Hevo.Charting.Core` | Feature / Layer / Schema / 黑板 / 帧管线(`ChartEngine`)/ 指针路由 / 低代码蓝图运行时 / 样式与坐标类型 | 只有 BCL,不引任何 UI 框架 |
| `Hevo.Charting` | WPF 宿主:`ChartCell` 控件、WPF 渲染器与位图后端、Tooltip 等控件类图层、`WpfPointerAdapter`、联动看板、Designer | Core + WPF |
| `Hevo.Charting.Skia` | DrawCmd → SKCanvas 翻译层(实验性) | Core + SkiaSharp |
| `Hevo.Charting.Skia.Wpf` | Skia 的 WPF 合成面 / `SkiaRenderBackend`(实验性) | Skia + Hevo.Charting |
| `Hevo.Charting.Avalonia` | Avalonia 宿主:`AvaloniaChartCell`、联动看板、头部、蓝图 / dashboard 启动器、蓝图编辑器、调试菜单(见 `Hevo.Charting.Avalonia/README.md`) | Core + Skia + Avalonia 12 |
| `Hevo.Charting.Samples` | 两个宿主示例共用的模拟数据源、手写 K 线 schema、示例看板蓝图 JSON | Core |

业务工程照旧只引用 `Hevo.Charting`(会连带引用 Core)。命名空间都没变,`using` 不用改。

## 业务要改的

| 旧写法 | 新写法 | 说明 |
|---|---|---|
| `protected override void OnCompose(ChartCell chart, ...)` | `OnCompose(IChartCell chart, ...)` | 同样适用于 `OnComputeCompose` / `DefineDataFlow` / `InjectDebugMenus`。Feature 拿到的是平台无关的 `IChartCell`;要 WPF 成员(路由事件、`Dispatcher`、`ContextMenu`)时转 `(ChartCell)chart` |
| `public override UIElement Decorate(UIElement inner)` | 类上加 `IWpfDecorator`,方法去掉 `override` | 外壳 UI 是宿主概念,核心的切面不再有 `Decorate` 虚方法。Avalonia 下对应 `IAvaloniaDecorator`(`Control Decorate(Control inner)`);一份 schema 两边都要外壳见下文「双宿主外壳 Feature」 |
| `new HevoSolidBrush(Colors.Red)`、`LineStyle.Create(Color.FromRgb(...))` 等 | `HevoColors.Red`、`HevoColor.FromRgb(...)` | 样式、Trait、`FieldMeta` 的颜色统一成 `HevoColor`;命名色和色值跟 WPF `Colors` 一一对应。手上已有 WPF `Color` 时用 `color.ToHevo()`,反过来 `hevoColor.ToWpf()` |
| `HevoLinearGradientBrush(Color, Color, Point, Point)` | `(HevoColor, HevoColor, HevoPoint, HevoPoint)` | 同上 |
| `BoxZoomOptions.ActivationModifier = ModifierKeys.X` | `Activation = PointerModifiers.X` | 旧的 `[Obsolete]` 兼容属性已删 |
| `HevoThread.SwitchToUI(dispatcher)` | `WpfThread.SwitchToUI(dispatcher)` | 回 WPF UI 线程的切换挪到 WPF 宿主 |
| `ViewportPorts.GetAttached(DependencyObject)` / `SchemaContext.SetAttached(...)` / `ChartLifecycle.ActiveSessionProperty` | 参数改为 `IChartCell`;附加属性没了,值存在 cell 的引擎上 | 传 `ChartCell` 的调用不用改 |
| `IncrementalRenderProbe.FrameRendered`(`Action<ChartCell>`) | `Action<IChartCell>` | 诊断钩子 |
| `Workflow.OnUIEvent` / `OnRoutedEvent`(element 级) | 已删 | 没有调用方。图表交互用指针区域 `ctx.Pointer().Publish(...)` + `flow.WatchPointer(this, handler)` |
| `this.OnMouse(...)` / `OnKey` / `OnDrag` / `OnTouch` / Feature 级 `OnUIEvent`(`WorkflowWPFEventExtension`) | 已删 | 同上,改用指针抽象;确需原生 WPF 事件时 `((ChartCell)chart).AddHandler(...)` 并在 Decompose 时摘掉 |
| `DashboardLaunchOptions.Owner`(`Window?`) | `object?` | 选项类挪进核心(两个宿主的启动器共用);赋值 `Owner = window` 不用改,读出来用时转 `(Window)` |
| `GraphEditorSchema.Interaction` 的成员 | 不变 | 交互逻辑挪进核心 `GraphInteractionFeatureBase`,WPF 的 `GraphInteractionFeature` 只剩事件接线;`NodeEditRequested` / `FitToContent` / `ComputeFitTransform` 照旧 |

`WidgetBuffer.UpdateLayout(Rect, vm)` 照常可用(WPF 侧补了扩展方法);核心版本收 `HevoRect`。

## 不变的

- `new ChartCell { Template = schema }`、`ChartHost`、XAML 用法不变。`ChartCell.Template` 现在的类型是 `ChartSchema`(内部再包成 WPF 的 `ControlTemplate`),同一个 schema 重复赋值不会重装。
- 蓝图 JSON:`HevoColor` 和 WPF 的 `Color` 属性都照旧写成 `"#RRGGBB"` / `"#AARRGGBB"`。
- 资源文本(`HevoResourceString`)照旧查 Application 资源字典:WPF 宿主在程序集加载时把解析器登记到自己的 `ChartHostServices`(见下)。业务经 `HevoStrings.Register` / `WpfRenderRegistry.RegisterString` 登记的全局解析仍然优先。
- `BlueprintLauncher.DryRun` / `DashboardLauncher` / `GraphViewerBootstrap` 的调用方式不变;校验、dashboard 装配、Designer 初始化挪进了核心(`BlueprintPreflight` / `DashboardAssembler` / 核心里的 `GraphViewerBootstrap`),WPF 版是薄壳。
- 帧调度(按需挂 `CompositionTarget.Rendering`、帧尾拔除)、图层 Z 序与静态 / 交互两块画布、位图模式、像素对齐,都是原来的代码搬进 `ChartEngine` / WPF `ChartCell`,逻辑没改。

## 机械迁移

改签名可以用脚本批量做(`OnCompose(ChartCell` → `IChartCell`、`override UIElement Decorate` → 实现 `IWpfDecorator`),剩下的颜色按编译错误逐行把 `Colors.` / `Color.From` 换成 `HevoColors.` / `HevoColor.From`。

## 宿主平台实现按宿主区分(WPF 与 Avalonia 可同进程共存)

核心里要宿主提供的东西(悬浮窗图层、顶部信息栏、资源文本解析、调试菜单、外壳 Feature 的宿主实现、宿主专属的蓝图组件名)
原来是几个全局静态槽位,后加载的宿主会覆盖先加载的。现在每个宿主一份 `ChartHostServices`(`WpfChartHost.Services` /
`AvaloniaChartHost.Services`),cell 经 `IChartCellHost.Services` 带出自己那份,核心按 cell 取:

| 用到的地方 | 怎么找宿主 |
|---|---|
| `TooltipWidgetFeature`、调试菜单、`LineSeriesFeature` 的图例名 | 当前 cell 的宿主 |
| `env.SetupUniversalHeader(hitPort)`、`canvas.AddHostFeature<T>()` | 装配期 schema 已挂到的 cell 的宿主;没挂上且进程里只有一种宿主时取它 |
| 蓝图 JSON 的组件名(`ComponentRegistry.Resolve(name, host)`) | 挂到 cell 上装配时先查该宿主的别名,再查全局表 —— 所以 `"UniversalHeaderFeature"` 在 WPF cell 上是 WPF 头部、在 Avalonia cell 上是 Avalonia 头部 |
| `ComponentRegistry.Resolve(name)`(没给宿主) | 全局表优先(WPF 进程里结果跟以前一样),找不到再按宿主登记顺序查宿主别名 |
| `HevoStrings.Resolve(text)`(没给宿主) | 全局登记优先,再按宿主登记顺序找第一个能解析的 |

WPF 单宿主进程里结果跟以前完全一样。`Hevo.Charting.Tests/HostCoexistenceTests` 把 Avalonia 宿主程序集加载进 WPF 测试进程,锁住两边互不覆盖。

### 双宿主外壳 Feature

外壳 UI(标题栏、图例条)是宿主控件,一个 Feature 类没法同时是 WPF 和 Avalonia 的装饰器。写法跟 `UniversalHeaderFeatureBase` 一样拆三段:

1. 共享库(只引 Core):`abstract class MyTitleBarBase : ChartFeature, IHostDecorator`,放取数 / 格式化等平台无关逻辑;
2. WPF 库:`MyTitleBar : MyTitleBarBase, IWpfDecorator`,启动时 `WpfChartHost.Services.RegisterFeature<MyTitleBarBase, MyTitleBar>()`;
3. Avalonia 库:`MyAvaloniaTitleBar : MyTitleBarBase, IAvaloniaDecorator`,启动时 `AvaloniaChartHost.Services.RegisterFeature<MyTitleBarBase, MyAvaloniaTitleBar>()`。

schema 里写 `canvas.AddHostFeature<MyTitleBarBase>(f => f.Title = "...")`,挂到哪个宿主就建哪个宿主的子类;宿主没登记时不加(返回 null)。
`RegisterFeature` 顺带把基类名登记成该宿主的蓝图组件名,蓝图 JSON 写 `"MyTitleBarBase"` 两边都能用。范例见 `Hevo.Charting.Avalonia.Tests/AvaloniaHostParityTests.cs`。

## 新宿主怎么接

实现 `IChartCell`(给 Feature 用)和核心的 `IChartCellHost`(挂每帧回调、图层上屏对象增删、上屏、指针输入、`Post` / `WhenLoaded`),持有一个 `ChartEngine`。`IChartCellHost.Services` 返回本宿主的 `ChartHostServices`:控件类图层(Tooltip)、顶部信息栏(`SetupUniversalHeader` 建的头部,取数逻辑在核心基类 `UniversalHeaderFeatureBase`)、资源文本、调试菜单都登记在上面,程序集加载时 `ChartHostServices.Register` 一次。渲染用 `Hevo.Charting.Skia` 的 `SkiaChartRenderer` 直接画到宿主给的 `SKCanvas` 上,资源解析实现 `ISkiaHostResources`。Avalonia 宿主(`Hevo.Charting.Avalonia`,含联动看板)是第二份完整实现;WPF 的实现是现成参照:`Hevo.Charting/Core/ChartCell.cs`、`WpfHostRegistration.cs`、`Hevo.Charting.Skia.Wpf/WpfSkiaResources.cs`。
