# 04. 交互层架构

> 范围：鼠标 / 键盘 / 滚轮事件 → 视口数学变化 + 命中状态广播。
> 读这份文档之前应先理解 [00.架构协议与开发规范](00.架构协议与开发规范.md) 中的 Feature/Trait/DataPort 模型。

---

## A. 一句话总览

```
WPF 事件 → 指针路由器(区域 → 行为链)
   ↓
ChartInteractionFeature 装的行为 ────────── 手势翻译
   ↓ 写                                    ↑ 读 port
Viewport.UserRange   PointerHitPort        AvailabilityPort
   ↓ Watch              ↓ Watch              ↑ 写（board 锁内）
ViewportManagerFeature  Crosshair/Tooltip   DataPagingFeature (PreLayout, 可选挂载)
   ↓ 写                                       ↓ Watch ActiveRange
Viewport.ActiveRange (clamp 后的真理) ────→ CheckBoundaries → OnRequireDataAsync
```

**两个独立的 PreLayout Feature，单一职责：**
- `ChartInteractionFeature` — 按 `SupportedModes` 往行为链上装内置交互,行为把手势降维成黑板写入(输入由指针路由器分发,见 C 节)
- `DataPagingFeature` — 视口变化触发分页 fetch，维护墙状态，写入 `AvailabilityPort`

其他 Feature 一律不直接监听 WPF 事件:要点、要拖就发布指针区域(M 节),其余通过订阅黑板被动反应。

**框架的两个正交机制**：
- **Feature 同步机制** = `DataPort` + DataBlackboard 锁
  - 用途：Feature 间的运行态通信（"对方状态变了我要响应"）
  - 例：`PointerHitPort`、`AvailabilityPort`、`Viewport.UserRange/ActiveRange`
- **渲染层数据共享** = `Trait`（Shared / layer 作用域）
  - 用途：数据 / 样式 / 几何度量向渲染层传递
  - 例：`AxisLayoutRegistryTrait`、`ScaleStrategyTrait`、`ViewportSpanLimitsTrait`、`BarDataTrait`、layer 范围的 `XAxisTrait` 等
  - 交互图层(十字光标、框选)的状态 Trait(`InteractionTrait`、`BoxZoomTrait`)都发到本层;哪些是共享的见 06 号文档 §5.4。发错作用域图层读到 null,不报错也不画

两套机制解决不同问题，**不是"哪种更好"的关系**。同一个 Feature 通常两套都用：通过 Port 被通知/通知别人，通过 Trait 共享渲染数据。

## B. 概念分层

| 层 | 关注 | 代表组件 | 是否应被业务直接换 |
|---|---|---|---|
| **手势层** | 输入 → 抽象意图（"用户拖了 12 像素"） | 指针路由器 + 行为链（`ChartInteractionFeature` 装的那组行为） | ❌ 仅框架级 |
| **策略层** | 抽象意图 → 视口几何决策 | `IZoomStrategy`，未来可能加 `IPanStrategy` | ✅ 业务可换 |
| **几何层** | 锚点缩放等纯函数 | `ZoomMath` 静态工具集 | ✅ 策略可借用 |
| **视图层** | 视口合法状态守卫（boundary / span 限制） | `ViewportManagerFeature` + `ViewportSpanLimitsTrait` | ⚙️ 业务通过 `SetupViewport` 配置 |
| **分页层** | 视口越过 SafeBuffer → 触发后端 fetch；维护墙状态 | `DataPagingFeature` + `DataAvailability` (DataPort) + `DataFetchOptions` | ⚙️ 业务通过 `OnRequireDataAsync` 启用 |
| **下游层** | 消费交互广播 | `CrosshairFeature` / `TooltipWidgetFeature` / 业务自定义 | ✅ 业务可加 |

## C. ChartInteractionFeature：装行为链

### C.1 一次输入怎么走

ChartCell 上唯一订平台输入的是指针路由器的适配器（`Interaction/WpfPointerAdapter.cs`）。一次输入依次走：

```
① 捕获者      有进行中的区域手势(拖线中)→ 先给它
② 区域        按下时按优先级 → 图层 → 距离裁决(M 节);命中就认领,后面收不到这次按下
③ 行为链      没被拿走的输入按顺序交给行为;任何一个行为返回"处理了",链到此为止
④ 旁听        手势端口、IsPointerOver 端口,谁关心谁读
```

① ② 在 Preview(隧道)阶段做,抢在图表里的子控件之前;③ 在冒泡阶段做,widget 模板里的按钮先处理、标了 Handled 的，行为链收不到，图表不平移。键盘没有位置，不走命中：路由器先看 Esc（取消手势 / 发给模态区域），其余所有键交给行为链。被区域认领的按下行为链也会收到（标明"已被认领"），只做停惯性、武装 hover、就地投影十字光标这类"任何按下都要做的事"。

`ChartInteractionFeature` 本身不订任何平台事件，`OnCompose` 里按 `SupportedModes` 往本图表的行为链上装一组行为，顺序即优先级：

| # | 行为（`Interaction/Behaviors/`） | 装的条件 | 管什么 |
|---|---|---|---|
| 1 | `PointerStateBehavior` | 总是 | 任何按下：拿焦点、停惯性、武装 hover；移动：记指针位置；区域手势开始 / 结束：触屏屏蔽、十字光标暂停 / 恢复。从不拦 |
| 2 | `DoubleClickResetBehavior` | `DoubleClickReset` | 两次按下在 `MaxInterval` / `MaxMovementPx` 内 → 复原视口 |
| 3 | `BoxZoomBehavior` | `BoxZoom` | 按着 `Activation`（默认 Shift）拖 → 选框，松手设视口 |
| 4 | `PanBehavior` | `Pan` | 按下即平移（不分按键）；松手按速度起惯性（`InertiaPan`），没起惯性就地投影十字光标 |
| 5 | `HoverBehavior` | 总是 | 移动投影 `PointerHitPort`（`Hover` 开、已武装、没被藏）；离开清 hit；Esc + `DismissOnEscape` 解除武装；视口变了重投 |
| 6 | `WheelZoomBehavior` | `Zoom` | 滚轮缩放（`ZoomStrategy`），区域手势中照常 |
| 7 | `KeyboardBehavior` | `Keyboard` 或 `KeyboardZoom` | ↑/↓ 缩放一档（`KeyboardZoom`）；`Keyboard` 开时任意键停惯性，←/→ 移十字光标 |
| 8 | `TouchBehavior` | 总是 | 触屏横移平移（`Pan`）、捏合缩放（`Zoom`）；两样都没开不接管 |

同一张图装了两个 `ChartInteractionFeature`：两组行为按装配顺序排在链上，第一组拦下的（平移、缩放）第二组收不到，不拦的（十字光标）两组都做。`Transact` 拔掉时整组摘掉：停惯性、放掉平移 / 框选抓着的鼠标、清选框。所属 Feature 挂起时整组跳过（输入被吞掉）。

### C.2 共享状态

一组行为共用一个 `ChartInteractionState`（`Interaction/Behaviors/ChartInteractionState.cs`）：最后的指针位置、hover 是否武装、在平移 / 框选中、区域手势是否进行中、惯性（`InertiaPanRunner`，帧时钟由适配器提供）。平移换算、缩放、指针命中写 `PointerHitPort` 的算法也在这里，行为调用它。

> **铁律**：所有写入黑板的写操作都在 `using (board.WriteScope())` 内；读取在 `UpdateScope` 内。

### C.3 输出口（黑板）

| Port / Trait | 类型 | 写入路径 |
|---|---|---|
| `Viewport.UserRange` | `RealRange` | Pan / Zoom / Keyboard / **BoxZoom 结算** / **InertiaPan 每帧** / **DoubleClickReset** / **Manipulation Pinch+Pan** |
| `PointerHitPort`（业务可配） | `PointerHitState?` | Hover / Keyboard 命中后；MouseDown / Leave / BoxZoom 启动 / Manipulation 开始时清空 |
| 框选状态端口（私有） | `BoxZoomTrait` | `BoxZoomBehavior` 按下 / 移动 / 松开时写入；`ChartInteractionFeature.OnProject` 透传给 `BoxZoomLayer` |

写入 `UserRange` 后，由 `ViewportManagerFeature.Watch(UserRange)` 接管：clamp 至合法范围 → 写入 `Viewport.ActiveRange`。其他 Feature 一律读 `ActiveRange`，不读 `UserRange`。

## D. 三条手势的清晰职责

### D.1 Pan（拖拽平移）

```
ΔPx → 物理位移
expandedSpan = scale.Denormalize(1) - scale.Denormalize(0)   // 兼容 Edge / Centered scale
ΔLogical = ΔPx / plotWidth × expandedSpan
new UserRange = baseRange − ΔLogical                          // 仅平移，不改 span
```

- **不读 limits**、**不调策略** —— Pan 不改变 Span，不需要 clamp Span
- `ISnappableScale` 模式下走 `Math.Truncate` ratcheting：避免 Round 透支导致 pan 卡死
- 越界由 `ViewportManagerFeature` 的 `OverscrollPolicy` 决定（Hard 钳回 / Overscroll 留白）

### D.2 Zoom（滚轮缩放）

```
zoomFactor   = (1 − sensitivity)^steps
rawTargetSpan = baseSpan × zoomFactor                          // 不 clamp
limits        = (MinSpan, maxIndex × MaxSpanMultiplier)        // 解析自 ViewportSpanLimitsTrait
ZoomContext   = (baseRange, rawTargetSpan, mouseRelX, hitState, logicalLength, limits, domainScale)
                                                                ↓
            IZoomStrategy.Calculate(in ctx)                    // 策略**自行** clamp + 锚定 + 自定义
                                                                ↓
            ISnappableScale snap (后处理，所有策略共享)
                                                                ↓
            写 UserRange → ViewportManager 兜底
```

**重点**：交互层产意图、策略层做几何与 clamp、视图层兜底越界。三层不重叠、不抢权。

### D.3 Keyboard（方向键）

```
targetIndex = currentHit.Index ± 1
clamp 到 [offset, offset + validCount - 1]
若越出当前 baseRange → 平移视口（写 UserRange）
正向投影 targetIndex → 物理 X，复用 UpdatePointerStateFromMouse
```

- 唯一会**同时**写 `UserRange` 和 `PointerHitPort` 的路径
- `Hit.Index` 是世界坐标，键盘移动在分页业务也保持稳定（Slicer 已删，世界索引 == 数组下标）

## E. 策略层：IZoomStrategy 与 ZoomContext

### E.1 契约

```csharp
public readonly record struct ZoomContext(
    RealRange BaseRange,        // 缩放发生前视口
    double RawTargetSpan,       // 用户意图（未 clamp）
    double MouseRelativeX,      // [0,1] 内表示在 plot 区；超出表示鼠标在 plot 外
    PointerHitState? HitState,  // 命中状态（可用于命中锚定 / 事件加权）
    int LogicalLength,          // 数据总长度
    SpanLimits Limits,          // 合法 Span 范围（已结合 LogicalLength resolve）
    IScale? DomainScale,        // 时间↔索引转换；ISnappableScale 量化
    bool LeftDataExhausted,     // 左侧无更多历史可加载（来自 ChartInteractionFeature 的左墙锁状态）
    bool RightDataExhausted     // 右侧无更多新数据可加载（罕见，仅静态数据集）
);

public interface IZoomStrategy
{
    RealRange Calculate(in ZoomContext ctx);
}
```

### E.2 策略可掌控的几何决策

策略**全权决定**：
- 是否 clamp Span（应当用 `ZoomMath.ClampSpan(ctx.RawTargetSpan, ctx.Limits)`）
- 锚点位置（鼠标 / 命中点 / 右缘 / 自定义）
- 两端是否对称（也可一端固定）
- 是否完全忽略 `RawTargetSpan` 自定义 span（如 FixedWindow 预设）

### E.3 内置策略

| 策略 | 用途 | 关键输入 |
|---|---|---|
| `MouseAnchorZoomStrategy` | 鼠标锚点（普通桌面） | MouseRelativeX |
| `RightEdgeZoomStrategy` | 右缘钉死（盯盘 / 最新数据始终可见） | BaseRange.Max |
| `LeftEdgeZoomStrategy` | 左缘钉死（自上市以来 / 回测起点参照） | BaseRange.Min |
| `SmartAdaptiveZoomStrategy`（默认） | 鼠标在 plot 内→鼠标锚；外→右缘 | MouseRelativeX |
| `CrosshairAnchorZoomStrategy` | 十字光标命中的 bar 不动；无命中退回鼠标 / 右缘 | **HitState.LogicalIndex** |
| `DirectionalZoomStrategy` | 放大用鼠标锚（要精度）/ 缩小用右缘（要纵览） | RawTargetSpan vs BaseRange.Span |
| `FixedWindowZoomStrategy` | Kiosk 模式：忽略 RawTargetSpan，恒定显示 N 根 | LogicalLength + 配置 `WindowBars` / `Alignment` |
| `HistoryAwareZoomStrategy` | 分页中走 `DuringPaging`（默认右缘钉死）；左墙撞死后切左缘锚定 | **LeftDataExhausted** + 配置 `DuringPaging` |

注：由于 `RightEdgeZoomStrategy` 锚点为 1.0、`LeftEdgeZoomStrategy` 锚点为 0.0，二者已分别对应"右端固定/左端固定"的非对称缩放，无需额外的 `AsymmetricRightFix` / `AsymmetricLeftFix`。整数 bar 对齐由 `HandleZoom` 在 `ISnappableScale` 下统一后处理，策略层不必单独提供。

### E.4 ZoomMath 几何工具集

| API | 用途 |
|---|---|
| `AnchoredZoom(baseRange, targetSpan, anchor)` | 相对锚点缩放（anchor∈[0,1]） |
| `HitAnchoredZoom(baseRange, targetSpan, logicalIndex)` | 保持指定逻辑索引视觉位置不变 |
| `ClampSpan(rawSpan, limits)` | 将原始 Span 夹紧到合法范围 |

策略**可选**借用，也**可以完全不用**自由构造 `RealRange`。

## F. 视图层：ViewportManagerFeature 与 limits

### F.1 字段配置（业务通过 `SetupViewport` 配置）

| 字段 | 默认 | 含义 |
|---|---|---|
| `Alignment` | `RightEdge` | 数据/视口变化时贴哪边 |
| `MinVisibleCount` | 3 | 最小可缩放至几根（决定 MinSpan） |
| `DefaultVisibleCount` | null | 首屏显示几根（null=全部）；分页业务必传 |
| `MaxSpanMultiplier` | 1.5 | 最大可缩放至数据量几倍（决定 MaxSpan） |
| `OverscrollMin` / `OverscrollMax` | `Hard` | 用户拖到边界外的策略 |

### F.2 双 clamp 拆分

```
ViewportManagerFeature.Watch(UserRange):
    ┌─ Span clamp (L97)         ← Zoom 策略已 clamp 时为 no-op；Pan 永远 no-op；保险作用
    └─ Boundary clamp (L105+)   ← 权威：Pan 路径越界由它决定，所有 Overscroll 策略在此应用
        ↓
    写 ActiveRange
```

| Clamp | 触发场景 | 权威性 |
|---|---|---|
| **Span clamp**（L97） | Zoom 时若策略未 clamp / limits 运行时变更 / 外部异常 | 保险 |
| **Boundary clamp**（L105-123） | Pan 拖到数据边界外 | **权威** —— Pan 路径唯一约束源 |

### F.3 Trait IPC：`ViewportSpanLimitsTrait`

```csharp
public record ViewportSpanLimitsTrait(double MinSpan, double MaxSpanMultiplier) : IVisualTrait;
```

- **生产者**：`ViewportManagerFeature.OnCompose`
- **消费者**：`ChartInteractionFeature.HandleZoom`（构造 `ZoomContext.Limits`）
- **不被** `ViewportManagerFeature` 自己 Watch 消费：内部 clamp 直接读字段，避免引入"读自己 publish 的 trait"的间接性

## G. 下游消费者：被动响应模型

### G.1 命中广播 → `CrosshairFeature` / `TooltipWidgetFeature`

```
PointerHitPort (DataPort<PointerHitState?>)
    ↓ UsePort
CrosshairFeature       绘制十字线 + 交点圆点 + 标签
TooltipWidgetFeature   绘制悬浮 Tooltip
业务自定义 Feature      读 hit.Hit.LogicalIndex 取自家 series 数据
```

`PointerHitPort` 由业务通过 `InteractionOptions.HitPort` 注入（多个 chart 共享 hit 时常用）；不传则 `EnableStandard` 内部生成默认实例。

### G.2 视口变更 → 业务 Feature 自由订阅

任何 Feature 通过 `ctx.UsePort(Viewport.ActiveRange)` 即可参与重投影；交互层不感知它们。

### G.3 数据分页钩子（DataPagingFeature）

分页是**独立的 Feature**，与交互层正交。业务通过 `InteractionOptions.OnRequireDataAsync` 启用即自动挂载。

```csharp
public Func<int, int, Task<bool>>? OnRequireDataAsync { get; init; }
//                  anchor  size  -> hasMore
```

- 自己挂 `Watch(Viewport.ActiveRange)`，命中 SafeBuffer 时触发 `CheckBoundaries`
- 节流：正常 200ms (`Pacing`)，网络异常 3s (`NetworkFaultThrottle`)
- 防雪崩：`_isFetching` 互斥 + 左右墙锁 + 数据长度纪元侦测（"业务谎报有数据但实际未扩容"也会被拦下）
- 墙状态变化时通过 `AvailabilityPort` 写入新的 `DataAvailability(LeftExhausted, RightExhausted)`，供 `HistoryAwareZoomStrategy` 等下游消费
- 详细行为见 [DataPagingFeature.cs](Features/DataPagingFeature.cs) 的 `FireRequestAsync`

**与交互层的解耦**：交互层不持有任何分页字段，只在 `HandleZoom` 通过 `board.Read(AvailabilityPort)` 读墙状态。`AvailabilityPort` 由 DSL 装配时统一创建并注入两个 Feature（与 `PointerHitPort` 模式一致）；非分页 schema（不传 `OnRequireDataAsync`）端口为 null，零开销。

## H. 业务装配 DSL

### H.1 标准装配（推荐）

```csharp
canvas.Interactions(interactions =>
{
    interactions.EnableStandard(TimePort, xAxisMeta, new InteractionOptions<DateTime>
    {
        Modes = ChartInteractionMode.Hover | ChartInteractionMode.Pan | ChartInteractionMode.Zoom | ChartInteractionMode.Keyboard,
        SnapMode = PointerOutOfBoundsStrategy.SnapToValidData,
        HitPort = sharedHitPort,        // 跨图共享时传，否则省略
        ZoomStrategy = new SmartAdaptiveZoomStrategy(),
        ValidCountPort = ValidDataCountPort,
        OnRequireDataAsync = (anchor, size) => LoadMore(anchor, size)
    });
});
```

`EnableStandard` 一次性挂载 3 个 Feature：`ChartInteractionFeature` + `CrosshairFeature` + `TooltipWidgetFeature`。

### H.2 拆分装配（高级）

```csharp
canvas.Interactions(i =>
{
    i.EnableStandardPointer(hitPort, modes: ChartInteractionMode.Hover, snapMode: ..., zoomStrategy: ...);
    i.AddCrosshair(hitPort, TimePort, xAxisMeta, displayMode: ..., yRangePort: ...);
    i.AddTooltip(hitPort, TimePort, xAxisMeta);
});
```

适用场景：只要 Hover 不要 Crosshair（如 MarketStrength 顶部 banner-only）；或自定义渲染层替代 Crosshair / Tooltip。

### H.3 模式开关：`ChartInteractionMode` flags

```csharp
[Flags] public enum ChartInteractionMode { None=0, Hover=1, Pan=2, Zoom=4, Keyboard=8, All, TimeShareDefault=Hover, Default=Hover|Keyboard }
```

每个事件订阅在分发前都会 `if (!SupportedModes.HasFlag(...)) return`。模式可在运行时改吗？目前为 `init`-only，运行时变更需重建 Feature（走 `Transact`）。

## I. 扩展指南

### I.1 加新 IZoomStrategy

1. 实现 `IZoomStrategy.Calculate(in ZoomContext ctx)`：
   - 调用 `ZoomMath.ClampSpan(ctx.RawTargetSpan, ctx.Limits)` 处理 Span（除非有意忽略）
   - 借用 `ZoomMath.AnchoredZoom` / `HitAnchoredZoom` 或自由构造 `RealRange`
2. 通过 `InteractionOptions.ZoomStrategy = new YourStrategy()` 注入
3. 单例无状态友好（0-GC）：构造一次，永驻内存

### I.2 加新交互模式（如双指捏合）

新模式属于"手势层"：必须在 `ChartInteractionFeature.OnCompose` 里加事件订阅。规范：
- 在 `ChartInteractionMode` 加 flag
- 订阅后立即 `if (!SupportedModes.HasFlag(...)) return`
- 把手势翻译成 `RawTargetSpan` / 平移意图，**调用现有策略**而非新写算法
- 锁顺序：`UpdateScope` 读 → `WriteScope` 写

### I.3 加新下游 Feature（自定义十字光标 / 标记线）

新 Feature 不该感知 WPF 事件，只读黑板：
- `ctx.UsePort(HitPort)` → 拿命中状态
- `ctx.UsePort(Viewport.ActiveRange)` → 拿当前视口
- 在 `OnProject` 中读 + 渲染；**不写黑板**（写入归属交互层 / 数据流）

### I.4 加新 Pan 算法（如惯性 Pan）

当前 Pan 直接写视口，无策略层。如果有真实需求，建议引入 `IPanStrategy` 接口，与 `IZoomStrategy` 同级，沿用相同分层（策略产意图、视图层 clamp）。

## J. 数据流闭环图

```
                ┌──────────────────────────┐
                │   WPF UI Element 事件     │
                └────────────┬─────────────┘
                             │
                             ▼
   ┌──────────────────────────────────────────────────────────┐
   │   ChartInteractionFeature  (Phase = PreLayout)           │
   │ ──────────────────────────────────────────────────────── │
   │ Pan        → 直接写 UserRange                              │
   │ Zoom       → IZoomStrategy.Calculate → UserRange           │
   │              （读 ViewportSpanLimitsTrait + AvailabilityPort）│
   │ Keyboard   → 写 UserRange + PointerHitPort                │
   │ Hover      → UpdatePointerStateFromMouse → PointerHitPort │
   │ Leave/Down → 清空 PointerHitPort                           │
   │ Watch ActiveRange → 仅刷新 PointerHit（不再做分页）          │
```

## K. 不变量速查

| 不变量 | 责任方 |
|---|---|
| ChartCell 上唯一的 WPF 输入入口;一次输入依次走 捕获者 → 区域 → 行为链 → 旁听 | 指针路由器（`PointerRouterFeature` + `WpfPointerAdapter`，每个图表 schema 自动一份） |
| 没有任何指针区域时，路由器不标 Handled、不抓鼠标、不设光标、不写手势端口，图表自带交互行为不变 | `PointerRouterFeature` |
| 唯一写 `Pointer.GesturePort` 的 | 指针路由器（Watch 回调里写它会抛） |
| 手势端口不进联动镜像：副图收不到主图的手势 | `LinkedChartContext` 只镜像登记过的端口 |
| 区域认领的按下照样停惯性、武装 hover，并就地投影一次十字光标；认领的按下不计入双击复原 | 路由器把认领的按下也交给行为链(标明已认领),`PointerStateBehavior` 处理 |
| 唯一写 `Viewport.UserRange` 的 Feature | `ChartInteractionFeature`(它装的行为) |
| 唯一写 `Viewport.ActiveRange` 的 Feature | `ViewportManagerFeature` |
| 唯一写 `PointerHitPort` 的 Feature | `ChartInteractionFeature`(它装的行为) |
| 唯一写 `AvailabilityPort` 的 Feature | `DataPagingFeature` |
| 数据流不再切片 —— 端口持有全量 `ReadOnlyMemory<T>`；**世界索引 == 数组下标** | 数据管线（删除 LinkSoAViewportStream / Viewport.Offset 后 ）|
| Feature 同步机制 = DataPort + board lock；渲染层数据共享 = Trait（两套正交） | 框架纪律 |
| `ActiveRange` 永远是合法范围（Span ∈ Limits、两端 ∈ 数据范围或按 Overscroll 留白） | `ViewportManagerFeature` |
| Zoom 锚点在极限处不被 ViewportManager 重新对称破坏 | 策略层提前 clamp（`ZoomMath.ClampSpan`） |
| Pan 不感知 limits、不调策略 | `PanBehavior` 实现 |
| 分页请求不会雪崩、不会重复消费、不会因业务返回假数据死循环 | `DataPagingFeature` 的 `_isFetching` + 双墙锁 + length-epoch 防线 |
| 交互层不持有任何分页字段 | 拆分后由 `DataPagingFeature` 持有；交互层仅通过 trait 消费墙状态 |

## M. 指针区域：业务交互 Feature 的写法

画线、拖价格线、测量这类"点中图上某样东西再拖"的交互，不再自己订鼠标事件抢 `ChartInteractionFeature`，而是：

1. **`OnProject` 里发布区域**：`ctx.Pointer().Publish(new PointerRegion { Shape = PointerShape.HLine(y, left, right), Accepts = PointerAccepts.Drag, Cursor = PointerCursor.SizeNS })`。语义同 Trait：跟图层 Trait 同一帧提交，命中用的位置就是这一帧画的位置；本帧第一次 Publish 换掉本 Feature 的整张表，同一帧再 Publish 追加；`Clear()` 撤掉。能不能点只看发不发布区域，没有"拒绝"。
2. **`OnCompose` 里接手势**：`flow.WatchPointer(this, (board, g, later) => { ... })`，或者直接 `flow.Watch(new object[] { Pointer.GesturePort }, ...)` 再用 `g.IsFor(this)` 过滤。回调在路由器写端口的写锁里同步执行（不慢一帧）：只读手势、写端口；调业务、发请求、弹窗放 `later(...)`，在锁外、本次分发结束后执行。
3. **屏幕 ↔ 值**：`OnProject` 里 `var (proj, changed) = ctx.UseProjection(YRange)` 存成字段，回调里 `proj.ScreenToValue(g.Position.Y)` / `ScreenToDomain(x)`。

路由器怎么裁决：按下时筛出命中的区域（线类按距离 ≤ 容差，面类按包含；按键、修饰键、`Accepts` 都要对上），再比 `Priority`（模态 > 手柄 > 对象）→ 所属图层的 `ChartLayerType` → 离指针的距离；没有候选就交给本文 C 节的行为链(平移 / 框选 / 双击复原)。一次拖动是 `Press → Begin → Move… → End`；没过阈值（默认 4 DIP，`InteractionOptions.DragThreshold`）松开是 `Click`，同一区域快速第二次是 `DoubleClick`；Esc、丢失捕获、按另一个键、Feature 被 `Transact` 拔掉、图表暂停、业务 `Pointer.RequestCancel(board)` 都发 `Cancel`（带原因），收到就回滚。只接受双击的区域第一次按下不认领（照常平移）。捕获、Esc、光标、热拔都由框架负责。

写屏幕的人通常不写这些，直接用内置的：`i.AddDraggableLine(pricePort, yRange, new DraggableLineOptions { OnCommitted = ... })`（委托价、止损线）、`i.AddMeasure(yRange)`（Ctrl + 拖测量）。业务画线工具的骨架见 `Hevo.Charting.Tests/DocSamples/Pointer/LineDrawingFeature.cs`（点两下 / 按住拖画线，Esc 退出，模态区域压过价格线）。

`ElementPlotFeatureBase`（散点、箭头、文字标记）的悬停 / 双击也改成了发布区域，`ElementHovered` / `ElementDoubleClicked` 照旧；`DoubleClickClaimsPress = true` 时元素双击不再同时触发图表的双击复原（默认 false，两者都触发，跟原来一样）。

自己 `this.OnMouse(...)` 订鼠标的旧写法已标 `[Obsolete]`:它不参与路由——被区域认领的那一次按下 / 松开收不到(Preview 里被标了 Handled),它标 Handled 也挡不住行为链的平移(路由器的处理器挂得更早)。要抢在平移之前就发布区域。进出图表改读 `Pointer.IsPointerOver` 端口。
