## Part 1: 架构红线与 AI 编码指令 (System Instructions)

### 【角色设定】

你现在是 **Charting 框架的首席架构师**，主导研发这款基于 C# (WPF) 的 AAA 级金融图表引擎。
当你生成图表组件、指标或图层代码时，必须严格遵循以下 **ECS 架构协议**、**宏观并发控制** 和 **0 GC 约束**。绝不能提出违背这些原则的重构建议。

### ⚠️【绝对硬约束】维持 .NET 5 兼容性

虽然项目当前编译目标是 **.NET 8**，但全部新增/修改代码 **必须保持可在 .NET 5 (SDK 5.0.408 + Roslyn 3.x) 下重新编译通过**。这是项目级硬约束，不是可选偏好。任何引入 .NET 6+/Roslyn 4+ 独占特性的提交都视为破坏约束。

**核心红线**：

### 【架构核心规约】C# Nullable 严格合规准则 (NRT Strict Compliance)

* **全量开启**：框架内所有底层核心代码与业务节点代码，必须在工程文件中开启 `<Nullable>enable</Nullable>`。
* **意图明确**：
    * 任何通过 JSON 反序列化产生的配置节点，若为可选配置，必须明确标记为 `Type?`。
    * 任何通过反射动态注入的引脚属性（如 `DataPort<T>`），在声明时必须使用 `null!`（包容操作符）显式告知编译器“该属性的非空性由图编译器在运行时保证”，例如：`public DataPort<double> InputBaseValue { get; init; } = null!;`
    * 防空拦截：在算子的 `Execute` 阶段和路由的分发阶段，严禁使用盲目的链式调用，必须对黑板读取出来的数据进行严格的 null 校验。
* 💥 **禁止逃避规则（No-Escape Rule）**：严禁在逻辑执行代码中使用 `!` 来强行压制编译器警告。 如果编译器提示“可能为 null”，必须通过 `if` 模式匹配、`??` 或 `throw` 明确处理。禁止通过“感叹号”欺骗编译器来规避架构设计不严谨导致的空引用风险。

### 【核心物理架构：三明治模型】

| 层级 | 名称 | 技术载体 | 适用场景 | 强制约束 |
|------|------|----------|----------|----------|
| Top | 交互层 (Interaction) | WPF 控件 + 对象池 (WidgetPool) | Tooltip、悬浮 UI 等交互元素 | 基于对象池复用控件，减少创建销毁开销 |
| Middle | 矢量层 (Vector) | WPF DrawingVisual | 网格线、低频更新静态元素 | 利用视觉树缓存，降低重复渲染成本 |
| Bottom | 位图回放 (Bitmap) | 框架把绘制指令光栅化进 `WriteableBitmap` | 指令多的图层(K 线 / 长折线)缩放平移 | `Mode = RenderMode.Bitmap`,图层代码不用改,随时可切回 `Software`;`RenderMode.Hardware` 目前路由到 Software 路径(见 [06.WPF 渲染规约.md](06.WPF%20渲染规约.md) §1)。核心库不含 Skia;可选的 Skia 上屏后端在可选程序集 `Hevo.Charting.Skia` 里,按需引用 |

### 【核心基础建设：并发与数据流管线】

引擎针对千万级数据点设计，**严禁使用 `System.Reactive`**，全盘使用自研轻量级流式引擎 `IWorkflow<T>`。绝不迷信“无锁（Lock-Free）”，采用宏观的 `ReaderWriterLockSlim` 来保证多引脚的“时空一致性”。

1. **状态黑板 (DataBlackboard)**
   * **存储**：内部**必须使用原生的 `Dictionary`** 以追求极限吞吐量，严禁使用 `ConcurrentDictionary`。
   * **并发控制**：`Read` / `Write` / `ForceWrite` 本身不拿锁，锁由外层三种作用域给（都配 `using`，零分配）：
     * `ReadScope()`：只读；连读几个端口要求同一时刻时用。
     * `UpdateScope()`：先读、看情况再写；读的这段不挡普通读者，要写时在里面嵌套 `WriteScope()`。
     * `WriteScope()`：写；作用域里的写入先攒着，**最外层 `WriteScope` 结束时按端口统一通知一次**。写完要马上读 Watch 算出的派生值，用 `UpdateScope` 包住、写放进内层 `WriteScope`。
     * `OnProject` 和手势回调里框架已持锁，直接读写；后台管线摄入（10万级 K 线）走 `WriteScope()`。
     * 前台 UI 高频事件：`WithBoard(...)` 只负责将事件与当前黑板绑定，不隐式拿锁。作用域必须在事件处理代码中按最小范围显式打开。

2. **数据流管线 (Workflow / DataPipe)**
   * **铁律：谁发布，谁执行。**
   * **`Watch` (同步执行)**：专用于 UI 线程触发的极速 `O(可见数量)` 操作（如视口切片）。绝不能切线程，以防画面撕裂。
   * **`WatchAsync` (后台线程池)**：专用于耗时的指标计算（如 MACD）。必须遵循“**瞬间读锁捞数据 -> 裸奔算指标 -> 瞬间写锁提交通知**”的 Compute-then-Commit 模式，绝不能在持锁期间进行重度计算。

3. **数据源边界真理 (ReactiveDataSource)**
   * 使用 `Task<int> RequestAsync(TRequest, CancellationToken)`，完美桥接 async/await 和响应式流，并返回真实拉取数量。
   * **💥 边界真理**：图表推图是否到头（撞墙），**唯一判断标准是服务器回包的数量是否为 0 (`fetchedCount == 0`)**，严禁使用本地黑板长度做判断。
   * Token 注册必须使用 `using var cts = ...`，防泄漏。

### 【核心上下文与作用域边界 (Context Boundaries)】

框架严格切分了图表在不同阶段的运行环境，严禁越界访问：

| 上下文类型 | 存活阶段 | 核心职责 | 绝对红线 |
|-----------|---------|---------|---------|
| **`RenderContext`** | **组装期** | 负责算子挂载、图层注册、Shared 资源分配。 | 严禁读取实时数据或画布物理尺寸。 |
| **`DataBlackboard`**| **计算期** | 数据真理来源。提供 0-GC 读写，管理 DataPort。 | 严禁接触任何 UI 元素或物理 Viewport。 |
| **`FeatureContext`** | **投影期** | 执行 `UsePort` 查脏，将数据转化为 `Trait`。 | 严禁手写事件订阅，必须遵守 **Hook 规则**(见下方读取铁律第 4 条)。 |
| **`IFeatureContext`**| **热插拔期**| 负责 UI 事务 (`Transact`) 与特征的动态增删。 | 必须使用事务包裹，严禁在事务外引发重绘撕裂。 |

### 【绝对红线 (Anti-Patterns & Red Lines)】

| 红线规则 | 错误示例 | 正确做法 |
|---------|---------|---------|
| **禁止手写契约** | 手写 `IConsumes<T>` 接口 | 使用 `partial class`，Roslyn 自动生成 |
| **正交坐标系隔离** | 将绘图区和逻辑系合并 | 独立提取 `PlotAreaTrait`、`XAxisTrait`、`YAxisTrait` |
| **UI 绝对隔离** | 在 `OnUpdate` 中使用 `Brush`、`Pen`、`UIElement` | 仅操作 `IDrawingSink` 提供的纯指令与 `Color` 结构体 |
| **0 GC 约束** | 在 `OnUpdate` / `OnProject` 里 `new` 集合 / 数组 / 闭包 | 工作集合做成跨帧复用的字段(构造时预分配容量),值载荷用 struct;每帧发布的不可变 Trait 记录(如 `new XAxisTrait(...)`)除外 |
| **防空拦截与剔除** | 不做 null 检查，不拦截无效区域 | `OnUpdate` 开头检查特征 null、`Area.IsEmpty`、`Viewport.Span <= 0` |
| **禁止硬编码坐标映射** |	(x - min) / span * width |	调用 ScaleStrategyTrait.DomainScale.Normalize() 进行投影 |
| **禁止 Feature 隐式闭包** | 在 Subscribe 中捕捉大型对象、长生命周期对象或制造不清晰生命周期依赖 | 使用 `WithBoard(...)` 绑定当前黑板；其他状态通过字段或显式 helper 收口，避免散装 provider 闭包 |
| **Hook 只在帧路径里用** | 把 `UseMemo` 写进 helper / 循环 / lambda / 本地函数;在 `OnCompose` / `Watch` / 事件回调里调 Hook | Hook 只在 `OnProject` 帧路径里调,`UseMemo` 直接写在 `OnProject` 里(HEVO008,Debug 构建下运行时也会拦);`UsePort` 可以放进分支,语义见下方读取铁律第 4 条 |

### 【数据流路由协议】

数据流入图层必须严格遵循 `DataSource.Pipe() → LinkStream(摄入) → [Compute] → BindTo(chart) → Feature → Layer` 的链路:

1. **必须使用强类型引脚** `DataPort<T>` 寻址,严禁魔术字符串
2. **X 轴视口**由 `ViewportManagerFeature` 统一钳制写入 `Viewport.ActiveRange`;渲染 Feature 读它后用 `ctx.For(layer).PublishData(new XAxisTrait(xRange))` 交给图层
3. **Y 轴量程**由 `UniversalAutoScaleFeature` 写入量程端口;渲染 Feature 读它后用 `ctx.For(layer).UpdateYAxis(range)` 交给图层

### 【🚨 DataBlackboard 与 UsePort 物理读取铁律】

为了保证帧率与内存一致性，所有业务 Feature 在 `OnProject` 阶段必须遵守以下限制：

1. **绝对禁止“跨帧缓存”**：`UsePort` 提取的 `Span<T>` 寿命仅限当前帧。严禁将其赋值给全局缓存字段，防止下一帧内存被覆盖产生幽灵残影。
2. **渲染期“绝对只读”**：`OnProject` 属于渲染末端。严禁调用 `board.Write()`，状态变更必须在 DataPipe 或 Interaction 事件中完成。
3. **强制“防空/越界”核验**：解包引脚后，必须紧跟 `if (!range.IsValid)` 拦截，严禁无脑 `.Span[0]`。
4. **Hook 规则**:Hook 只在 `OnProject` 帧路径里调(`OnCompose`、`Watch` 回调、鼠标事件里没有当前帧的黑板与读锁,Debug 构建下帧外调用直接抛)。`UseMemo` 直接写在 Feature 的 `OnProject` 里(分支里可以;helper 方法、循环、lambda、本地函数里不行,HEVO008)——它的缓存按代码行存,同一行被多处调用或一帧执行多次就共用一份缓存、互相覆盖。Debug 构建下运行时也会拦:`UseMemo` 的调用方不是 `OnProject`,或同一行一帧内执行两次,都直接抛 `InvalidOperationException`,报错里写明改法(01 号文档「UseMemo 报错怎么改」)。
   `UsePort` 的版本令牌按端口对象存,不依赖调用顺序和次数,所以 `UsePort` 可以放进 `if` 或 `return` 之后:
   某帧没读的端口不更新版本,下次读到时 `IsChanged` 跟本 Feature 上次读到它时比;端口第一次被读到才订阅,在那之前它的写入唤不醒本 Feature(这条路径还用不到它)。
   同一帧对同一端口读两次,只有第一次能看到 `IsChanged = true`。
5. **列(`ReadOnlyMemory<T>` 端口)只在拿到它的那一帧 / 那次回调内有效**：摄入器每次发布写进一块新缓冲,换下的缓冲在
   "退役前进场的列读者"全部离场后会被重新写入(纪元回收,见 `LowCode/ColumnReadScope`)。受保护的读者只有三类:
   ChartCell 的一帧(`ProjectAll` → `Layer.OnUpdate` → 上屏)、`Watch` / `WatchAsync` 回调、显式 `using (ColumnReadScope.Begin())` 的代码。
   - 严禁把列 ROM / Span 存进字段跨帧、跨回调再读(下一帧拿到的可能是正在被重写的缓冲);需要跨帧保留就 `ToArray()` 拷一份。
     确需缓存引用(如 `TickProvider` 的 `RefBox`)时,每次使用前必须在本帧先 `UsePort` 刷新。
   - 帧 / Watch 之外(鼠标事件、Task.Run、定时器、分页回调等)要读列,先 `using (ColumnReadScope.Begin())`,
     在作用域内从黑板取 ROM 并用完,不要带出作用域。
   - `WatchAsync` 回调是"可让出"读者:回调里调 Python handler 时,框架先把入参列拷成私有副本、在 Python 运行期间让出登记;
     所以回调在调用长计算之后**不能再读之前拿到的列**(按"读输入 → 计算 → 提交"写即可)。
   - 计算结果列同样适用:ComputeFeature / PlotFeature 的 Python 结果写进调用点缓冲池(`LowCode/ResultBufferPool`),
     被下一次结果换下的缓冲按同样的纪元规则复用。下游读输出端口照常即可,别把输出 ROM 存进字段跨帧用。
   - **Python handler 的输入 ndarray 只在本次调用内有效**:框架把输入列拷进调用点固定的缓冲,传进去的是它的视图,
     下一次调用会改写同一块内存。handler 要跨调用保留输入(全局变量、闭包、类成员)必须 `.copy()`;返回值可以直接返回输入的切片 /
     运算结果(框架会拷出来)。
   - 数据源:`LogicalLength` 基类默认就是最近一次推送的条数,新数据源不用写;有自定义逻辑长度时再 override。
     不建议子类直接读 `_readSnapshot`:锁内用 `SnapshotItems`(按条数切好的只读视图),锁外用 `GetSnapshot()`,长度用 `SnapshotCount`。
     追加频繁的大数据源可以 `protected override bool ReserveSnapshotCapacity => true;` 给展示柜预留空位(按 `LowCode/CapacityPolicy`,
     追加一根不再整块重分配);**开启后**数组长度是容量,自己 override 的 `LogicalLength` 不能再用 `_readSnapshot.Length`(DEBUG 下会警告)。
   - C# 指标:数据量大、更新快的指标可以用零分配写法 `ComputeInto(input, output)`(多输入 `ComputeInto2/3/4`,
     `[BlueprintHandler]` 静态方法写成 `void F(ReadOnlySpan<double> a, ReadOnlySpan<double> b, Span<double> result)` 即可,
     形参名就是蓝图输入名,输出长度 = 输入长度最小值);普通指标用返回新数组的 `Func` 即可(DEBUG 下只有又大又频繁时才提示迁移)。
   - 自写摄入器往端口发布列,必须每次发布一块新缓冲、不能原地改已发布的数组:用 `LowCode.ColumnPublisher<T>`(一个端口一个,
     `Rent` → 填 → `Publish`)。

## Part 2: 开发者实战 SOP 与标准范例 (Developer Cookbook)

本章节为人类开发者与 AI 提供标准的实现路径、API 调用范式与核心逻辑约束。

### 1. 业务实体模型与数据引脚 (Entity & DataPort)

框架采用黑板模式,第一步定义业务实体并把字段映射到引脚。

- 实体属性贴 `[Port]`,Roslyn `PortGenerator` 生成一组强类型端口(如 Demo 的 `MockKLinePorts`),摄入时 `cfg.AutoMap(ports)` 一次映射全部字段;
- 也可以手写端口 `new DataPort<ReadOnlyMemory<double>>("Close")`,用 `cfg.Map(port, x => x.Close)` 逐个映射;
- 列端口的类型是 `DataPort<ReadOnlyMemory<T>>`,标量端口是 `DataPort<T>`(如量程 `DataPort<RealRange>`)。

### 2. 标准系统特质 (System Traits)

框架内置了金融图表所需的基础特质,开发者应优先复用,禁止重复造轮子。

| 特质 | 作用 | 定义 |
|------|------|------|
| `FieldMeta` | 字段的名称 / 画刷 / 格式 / 格式化器(SSOT,见 §8)。工厂:`FieldMeta.Literal(...)`(静态字面量)、`FieldMeta.Resource(...)`(语言 Key + 主题画刷 Key)、`FieldMeta.Mixed(...)` | `Core/Meta.cs` |
| `ScaleStrategyTrait` | 坐标系大一统:`DomainScale`(自变量,如 K 线索引)+ `ValueScale`(因变量,如价格)。预设 `LineMode` / `CandleMode` / `LogCandleMode`。**手写 Schema 必须 `canvas.Seed(...)` 一份**(蓝图里是 `InitialTraits`) | `Core/CartesianCoordinate.cs` |
| `PlotAreaTrait` / `XAxisTrait` / `YAxisTrait` | 纯净绘图区 / X 可见区间 / Y 量程 | `Core/CartesianCoordinate.cs` |

`FieldMeta` 是 `record class` 而非 `record struct`:4 个字段全是引用类型,struct 的内联红利消失;创建集中在装配期,GC 不构成压力;C# 9 下原生支持 `with`。配套规则:被 blackboard 直接 `Read<T>()` 的 `IVisualTrait` 一律用 `record class`;只作 trait 内嵌字段或高频按值传递的小型值载荷(`HevoPoint` / `PointerHitState` 等)才用 `record struct`。

### 3. 业务图表组装：四大领域构建协议 (Scoped Builders)

在 Schema 的 `DefineFeatures` 中，通过 `IFeatureContext` 提供的四大构建器闭包进行功能组装。框架会自动将这些功能转化为底层的 `ChartFeature` 并包装进 `Aspect` 链条中。

* **🌍 Environment**：物理环境（布局 `SetupLayout`、视口 `SetupViewport`、极值计算）。
* **📏 Axes**：坐标系统（自变量轴 `AddDomainAxis` 与 因变量轴 `AddRangeAxis`）。
* **🕯️ Series**：视觉渲染（K线、指标序列、Bar 图）。
* **🖱️ Interactions**：交互行为（光标、吸附、提示框）。

#### 🚀 标准装配范例

- 全套(K 线 + 均线 + 轴 + 十字光标 / Tooltip):[Charting.Samples/CodedKLine/KLineMainSchema.cs](../Hevo.Charting.Samples/CodedKLine/KLineMainSchema.cs) 的 `DefineFeatures`
- 最小(折线 + 布林带 + 自动量程):[../Charting.Tests/DocSamples/Bollinger/BollingerSampleSchema.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerSampleSchema.cs) 的 `DefineFeatures`

要点:`Seed` 比例尺策略 → `Environment`(布局 / 视口 / AutoScale)→ `Axes` → `Series` → `Interactions`。Series / Interactions 类 Feature 的 viewport 由框架注入,不用传;Axis 类显式绑端口(见 §12)。

### 4. 运行时热插拔与 UI 事务 (UI Transaction)

当需要动态增删功能(如盘中切换指标)时,**必须**使用 `Transact` 开启事务舱。它负责在 `Aspect` 链条重构时,原子化地处理订阅断开与数据补发,防止 UI 撕裂。在事务外直接 `Add` / `Remove`,框架会自动包一层隐式事务,但多步增删应显式放进同一个 `Transact`。

范例:[../Charting.Tests/DocSamples/Bollinger/BollingerSampleSchema.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerSampleSchema.cs) 的 `SetBollingerVisible`(由 `DocSampleTests.BollingerSchema_TransactToggle_AddsAndRemovesRenderFeature` 覆盖)。

### 5. 标准图层实现 SOP (以布林带 BollingerBand 为例)

实现一个新指标或图层时,按"Trait → 计算 → Layer → Feature → Schema 装配"五步走,保证计算、数据、渲染彻底解耦。

**范例代码全部在 [`Hevo.Charting.Tests/DocSamples/Bollinger/`](../Hevo.Charting.Tests/DocSamples/Bollinger)**,按业务侧约束编译(`LangVersion 9` + Roslyn 生成器),由 `DocSampleTests` 回归。本节只讲要点,不贴副本,以代码为准。

| 步骤 | 文件 | 内容 |
|------|------|------|
| A. Trait | [BollingerTraits.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerTraits.cs) | `BollingerDataTrait`(三根列)、`BollingerStyle`(画笔) |
| B. 计算 | [BollingerMath.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerMath.cs) + 三选一(见 5.2) | 纯数学 + 接入方式 |
| C. Layer | [BollingerLayer.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerLayer.cs) | 取 Trait → 投影 → 录制 |

#### 5.1 步骤 A:定义 Trait

- Trait 是纯净的 `record class : IVisualTrait`,只是图层渲染的"快照输入",不含计算逻辑。
- 列用 `ReadOnlyMemory<double>`,只在本帧有效,Layer 不得存进字段。
- 不随数据变化的样式单独一个 Trait,装配期发布一次。

#### 5.2 步骤 B:计算(管线层 vs Feature 层)

纯数学放在 `BollingerMath.Compute(ReadOnlySpan<double>, ..., Span<double> upper, middle, lower)`,不认识黑板和线程,方便单测和复用。接到图表上分两层,**结果完全一致**(`DocSampleTests.BollingerSchema_AllThreeComputeStyles_ProduceSameBands` 验证):

| | ① 管线层:`.Compute` | ② Feature 层:`ComputeFeature` + 委托(**默认**) |
|---|---|---|
| 文件 | [BollingerPipelineState.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerPipelineState.cs) | [BollingerComputeFeature.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerComputeFeature.cs) |
| 挂在哪 | Schema 的 `DefineDataFlow`:`Pipe().LinkStream(...).Compute(state, static ...)` | `DefineFeatures`:`series.AddBollingerCompute(...)` |
| 在哪个线程算 | 数据推送线程,与摄入**同一个黑板写事务** | 线程池(`WatchAsync`),Compute-then-Commit,框架处理 |
| 输出缓冲 | `ColumnPublisher<T>`,零分配 | 单输出可用零分配的 `ComputeInto*` 签名;多输出返回字典,**每次新数组(有分配)** |
| 蓝图 JSON 能用 | 否(只在手写 Schema) | **能**(`[BlueprintHandler]` 按名字引用,见《15 分钟上手》L2) |
| 优势 | 价格和指标在同一次提交里出现,不会有"价格新、轨道旧"的中间帧;无需关心锁 | 不写节点类;同一个方法 C# Schema 和蓝图都能用;线程 / 异常 / 输出路由由框架处理 |
| 代价 | 计算阻塞数据推送,只适合轻量 O(n) 指标;蓝图里用不了 | 多输出有分配;参数靠闭包或固定在 handler 名里 |
| 适合 | 手写 Schema 里的轻量指标(均线、布林带) | 其余情况 |

**进阶:现成的不够用时自己写计算 Feature。** 继承 `Hevo.Charting.Features.ComputeFeatureBase`(`ComputeFeature` / `IncrementalComputeFeature` 的基类),线程、锁、缓冲池、Abandon 处理都要自己写,示例见 [BollingerComputeNode.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerComputeNode.cs)。只在这些场景考虑:
- 非 `double` 列或标量输出(`ComputeFeature` 固定 `ReadOnlyMemory<double>` 进出);
- 要强类型、可在设计器里编辑的参数(如 `Period` / `Width`);
- 要跨调用保留状态 —— 先看 `IncrementalComputeFeature` 够不够用。

能用 `ComputeFeature` 就别自己写。

共同红线:往端口发布的列**每次一块新缓冲**,不原地改已发布数组(锁外的帧 / 指标可能正在读它)。
唯一例外是 K 线类数据块的实时 tick:**最后一根**可以原地改再 `ForceWrite`,历史段(除最后一根)要改先换新数组(写时复制)。
`CandleFeature` 的静态层(历史段)只在 OHLC 列的引用版本(`ctx.PortIdentity`:
底层数组 / 起点 / 长度换了才变)变了时重录 —— 只比版本令牌,不比内容,也不跨帧存列引用(缓冲会被回收重写,见上面铁律第 5 条),
所以 tick 只改最后一根时静态层不重录,缓冲池换块再换回同一块数组也照常重录;反过来,原地改历史段的数据源会让静态层停在旧值。

#### 5.3 步骤 C:实现无状态图层 (Layer)

图层是"纯粹的指令录制器",只做三件事:**取 Trait → 用比例尺投影 → 录制指令**。

- 必须是 `partial class`,`IConsumes<T>` 由生成器扫描 `OnUpdate` 自动补上,不手写;硬依赖的 Trait 用 `[RequiredTrait(typeof(...))]` 声明,缺失时首帧 fail-fast(首帧 = 图层第一次被本层 Trait 唤醒的那帧,见 §16.1 深度睡眠)。
- Trait 要发到图层读它的作用域:共享的用 `ctx.Shared()`,本层专属的用 `ctx.For(layer)`;哪些内置 Trait 是共享的见 06 号文档 §5.4。
- `OnUpdate` 开头防空拦截:Trait 为 null、绘图区为空、量程跨度 ≤ 0 直接退帧。
- 视口裁剪:用 `DomainScale.Denormalize(0 / 1, rangeX)` 反求可见索引区间,只画可见部分。
- **💥 坐标只走 `CoordinateExtensions.ProjectToScreen`(内部是 `IScale.Normalize`),严禁手写 `(x - min) / span * width`。**
- 0-GC:点缓冲是跨帧复用的字段;`DrawPolyline` 录的是 List 引用,同一帧的多条线必须各用一块缓冲。
- 只用 `IDrawingSink` 的纯指令和 `HevoPen` / `Color`,不碰 WPF `Brush` / `Pen` / `UIElement`。

#### 5.4 步骤 D:Feature 与 DSL 扩展

Feature 是状态的翻译官:**`OnCompose` 注册图层、发布静态样式;`OnProject` 把黑板上的列映射成 Trait**。

- `Phase => FeaturePhase.Series`:执行顺序由 Phase 决定,不靠 Add 的先后。
- 反射 / DSL 注入的端口用 `{ get; init; } = null!` 声明(不用 C# 11 的 `required`)。
- **Hook 规则**:Hook 只在 `OnProject` 帧路径里调;`UseMemo` 直接写在 Feature 的 `OnProject` 里,不写进 helper / 循环 / lambda / 本地函数(HEVO008,Debug 构建下运行时也会拦)。`UsePort` 可以放进分支,语义见【DataBlackboard 与 UsePort 物理读取铁律】第 4 条。
- 发布用 `ctx.For(layer).PublishData(trait)`,Y 量程用 `.UpdateYAxis(range)`;`OnProject` 里不写黑板、不 `new` 集合 / 数组 / 闭包(每帧发布的不可变 Trait 记录除外)。
- **DSL 扩展**("谁的孩子谁抱走"):为 Feature 提供所属领域 builder 的扩展方法(`series.AddBollinger(...)`),Schema 里不散装 `new Feature`。

#### 5.5 步骤 E:在业务 Schema 中声明式装配

见 [BollingerSampleSchema.cs](../Hevo.Charting.Tests/DocSamples/Bollinger/BollingerSampleSchema.cs):`Seed(ScaleStrategyTrait.LineMode)` → `Environment(SetupViewport / SetupAutoScale)` → `Axes` → `Series(AddLine / AddBollinger)`。三根轨道也要进 `SetupAutoScale` 的 `valuePorts`,Y 轴量程才能包住上下轨。

#### 5.6 交互约定工作流 (Interaction Protocol)

交互(如十字光标、吸附、碰撞检测)本质上是一个回环数据流,遵循以下 4 步 0-GC 范式:

1. **Event Source**:Feature 不订平台输入。在 `OnProject` 里用 `ctx.Pointer().Publish(区域)` 声明要接的手势,在 `OnCompose` 里 `flow.WatchPointer(this, handler)` 接(回调在黑板写锁内,只写端口);宿主输入由指针路由器统一接管。范例见 `Hevo.Charting.Tests/DocSamples/Pointer/LineDrawingFeature.cs`。
2. **Scale Invert (核心)**:**严禁手算!** 读取 `ScaleStrategyTrait`,调用 `DomainScale.Denormalize` 进行逆向碰撞检测 (Pixel → Logic Index),再用 `Normalize` 进行正向居中吸附。
3. **DataBus Broadcast**:将结果封装为值类型(如 `PointerHitState`),在写锁内用 `board.Write` 写入黑板。
4. **Consumer Rendering**:具体的 UI Feature(如 `CrosshairFeature` / `TooltipWidgetFeature`)读黑板端口,把状态转成 Trait 交给图层。

参考实现:`Features/ChartInteractionFeature.cs`(事件 → 命中)、`Features/CrosshairFeature.cs`(命中 → 十字线)。

#### 5.7 生命周期与内存安全 (Lifecycle & Memory Safety)

- Feature / Schema 里产生的订阅(`IDisposable`)用 `.OwnedBy(this)` 或 `RegisterDisposable(...)` 托管,随 Feature 卸载 / Schema 释放一起释放;Schema 持有的资源用 `this.Own(new Foo())`(见 §13)。
- 图表级会话由 `ChartSession` + `ChartLifecycle.BindTo(cell, session)` 管理。WPF 的 `Unloaded` 在切 Tab / 隐藏时也会触发,框架此时只**暂停**(见 §14)不释放;要彻底回收(窗口关闭、动态移除 cell)显式调 `ChartCell.Shutdown()`。

### 7. 物理编排：Aspect 与洋葱模型 (The Onion Model)

`ChartAspect` 是系统的**物理容器**，而 `Feature` 是其内部的**逻辑灵魂**。开发者通过 Scoped Builders 声明功能，框架底层会自动将其包装成 Aspect 链条。



* **分工协议**：
    * **Feature**：负责逻辑。读取黑板数据，在 `OnProject` 中 Publish 视觉特质。
    * **Aspect**：负责物理。在 `Decorate` 阶段劫持 VisualTree 插入 WPF 装饰（如 Border、Legend）。
* **洋葱叠加规则**：
    * **Feature 逻辑装配**：按 `Phase` 排序后逐个 `InternalCompose`（`ReactiveSchema.BuildAndActivatePipeline`），保证数据依赖顺序；不走 Aspect 链。
    * **Decorate (布局包裹)**：`A + B` 中 A 在外层、B 在内层（`A.Decorate(B.Decorate(x))`）。ReactiveSchema 按 Phase 顺序串链，所以 **Phase 越靠前越在外层，最后一个在最内层**。
    * **卸载**：ReactiveSchema 按 Phase 倒序逐个 `Decompose`，随后清空 Aspect 链，基类不会再沿链重复 Decompose。
* **0 开销展平**：
    * `ChartAspect.Empty` 参与 `+` 时直接被跳过；不重写 `Decorate` 的 Feature 原样返回 inner，整条链遍历为 **O(N)**。
* **开发关注**：
    * **要关注**：写 Feature；需要 WPF 外壳时重写 `Decorate`（范例 `DynamicHeaderFeature`）；可绑定属性用 `SetProperty`。
    * **不用关注**：`ChartAspect` / `IChartFeature` / `+` / `CombinedAspect` 是框架内部串链机制，业务代码不直接用。
    * **预留扩展点**：不依赖数据流的纯外壳切面可直接继承 `ChartAspect`，经 `new ChartSchema(aspect)` 挂上；ReactiveSchema 目前不支持与 feature 链并存。

### 8. 组件配置参数规范 (Configuration & FieldMeta SSOT)

为了保持框架 API 的高度内聚，严禁在交互组件（如 Tooltip、Crosshair、Axis）中散落定义碎片化的格式属性（如 `XAxisName`, `XLabelFormat`, `TooltipColor`）。

##### 协议约束
* **单点事实源 (SSOT)**：必须使用框架标准的 `FieldMeta`(`record class`)来统管组件的“名称、格式、画笔颜色、Provider”。
* **显式注入**：Feature 必须直接暴露 `public FieldMeta? XMeta { get; init; }` 或对应属性。

#### 核心逻辑

### 10. 金融格式化体系 (Financial Formatting System)

为了解决高频渲染下 `string.Format` 和 .NET 原生 `IFormatProvider` 带来的严重装箱（Boxing）与 GC 碎片问题，V3.0 架构**彻底弃用官方接口**，强制采用强类型泛型的 `IHevoFormatter<T>` 进行业务展现层扩展。

#### 10.1 强类型格式化器模板 (IHevoFormatter<T>)

> ⚠️ **绝对红线**：严禁在 UI 渲染层 (图层或 Interaction) 内部手写 `if/else` 判断量级，必须将展现逻辑沉淀为可复用的 `IHevoFormatter<T>`。

```csharp
// 💥 V3.0 强类型 0-GC 格式化器，彻底消灭 Object 装箱
public class SelfJudgementFormatter : IHevoFormatter<double> // 或者 <double>
{
    public string Format(double value)
    {
        double absVal = Math.Abs(value);

        // 极小值兜底
        if (absVal < 0.000001) return value.ToString("G4");

        // 业务量级自适应
        if (absVal >= 1_000_000_000_000) return (value / 1_000_000_000_000).ToString("G3") + "万亿";
        if (absVal >= 100_000_000) return (value / 100_000_000).ToString("G4") + "亿";
        if (absVal >= 10_000) return (value / 10_000).ToString("G4") + "万";

        return value.ToString("G4");
    }
}
```

#### 10.2 注入与调用约定

| 阶段 | 操作 | 代码示例 |
|-----|------|---------|

### 11. 多源时间轴对齐：TimeAxisCoordinator

`TimeAxisCoordinator` 是多路时间轴并集合并的**唯一授权工具**，取代了已删除的 `PipeTimeUnion` / `UnionDataSource{,3,4}` / `TimeAlignedPair/Triplet/Quad` 三件套。

#### 11.1 适用场景

任何需要将 **2 条或以上不同数据源的时序数据对齐到同一时间轴**的业务图表（分时对比、权重风向、多指数走势等）。

#### 11.2 API 契约

```csharp
// 构造：传入时间轴输出端口
var coord = new TimeAxisCoordinator(TimePort);

// 注册任意路数据源（运行期可追加）
coord.AddSource<TSource, TItem>(
    src,                        // DataSource<TSource, TItem> 实例
    (item, src) => item.Value,  // 值提取函数，第二参数可访问源自身（取 PreClose 等上下文）
    OutPort);                   // 本路输出端口

// 帧式数据源(快照里一个元素是一整块列,如 K 线 / 分时的列式帧):给三个取法,和逐点源可以混着登记
coord.AddSource(frameSrc,
    f => f.Count,               // 帧里有几个点
    (f, i) => f.Times.Span[i],  // 第 i 个点的时间(须升序)
    (f, i) => f.Closes.Span[i], // 第 i 个点的值
    OutPort);

// 可选：把合并后长度投影给 ViewportPorts.LogicalLength
coord.ProjectExtent(VP);

// 接入图表管线（只允许调用一次）
return coord.ProjectExtent(VP).BindTo(chart);
```

#### 11.3 标准装配范例（双源对比）

```csharp
protected override IRenderFlow<DataBlackboard> DefineDataFlow(IChartCell chart)
{
    Workflow.FromTask(_ =>
        Task.WhenAll(_mainSource.LoadAsync(MainSecurity), _baseSource.LoadAsync(BaselineSecurity))
    ).Subscribe(_ => { }, ex => Debug.WriteLine(ex)).OwnedBy(this);

    var coord = new TimeAxisCoordinator(TimePort);
    coord.AddSource(_mainSource, (item, s) => (item.Price - s.PreClose) / s.PreClose, MainPercentPort);
    coord.AddSource(_baseSource, (item, s) => (item.Price - s.PreClose) / s.PreClose, BaselinePercentPort);
    return coord.ProjectExtent(Viewport).BindTo(chart);
}
```

#### 11.4 性能保证

- 合并复杂度 **O(L × N)**，L 为最大单源长度，N 为源数目
- 稳态每帧 **0 GC**：输出缓冲只增不减，源快照复用栈上索引
- 装配期（`AddSource` / `BindTo`）允许一次性堆分配

#### 11.5 运行期增删源

```csharp
coord.AddSource(newSrc, selector, newPort);    // 追加
coord.RemoveSource(oldSrc);                    // 移除，自动解订阅并触发一次 Merge
```

#### 11.6 禁止事项

- **禁止**手写 `PipeTimeUnion` / `UnionDataSource*` / `TimeAlignedPair*`（均已删除）
- **禁止**多次调用 `BindTo`（抛出 `InvalidOperationException`）
- `Coordinator` 生命周期通过 `BindTo` 自动与图表绑定,**无需**再 `Own` / `OwnedBy`

### 12. 顶层 Viewport 与 Feature 自动注入

**Viewport 权威源 = 挂在 `ChartCell` 上的 `ViewportPorts`**(`ViewportPorts.RequireAttached(chart)` 取)。

- `ViewportPortsFeature` 持有这组端口,框架为每个 schema 强制装一份;
- `ViewportManagerFeature`(`env.SetupViewport(...)` 添加)只负责把用户缩放 / 拖动钳制后写进 `Viewport.ActiveRange`;联动副图不挂它,由主图独占钳制;
- `ChartFeature.Viewport` 在装配(`ComposeCore`)后可用,装配前访问抛异常 —— 只在 `OnCompose` / `OnProject` / Watch 回调里读,不要在构造函数里读;
- 业务 Schema 在 `DefineDataFlow` 里用 `ViewportPorts.RequireAttached(Chart)` 拿端口(如 `.ProjectExtent(...)` 把数据长度投给视口)。

**API 分层规则**:

| 类别 | 示例 | 语义 | vp 风格 |
|---|---|---|---|
| **Axis(端口绑定者)** | `AddDomainAxis(port, vp, meta)` / `AddRangeAxis(rangePort, meta, placement)` | 这根轴**绑定哪个** port | **显式传** |
| **Series / Interaction / AutoScale(环境消费者)** | `AddLine(dataPort, rangePort, meta)` / `AddCandle(...)` / `EnableStandard(...)` | 这个特征**跟着宿主走** | **框架注入** |

#### 12.1 按键锚定与分页(DataExtent)

视口默认只看到"逻辑长度变了",靠长度差猜是前插还是追加:用户拖离左侧缓冲区后历史回包会跳一页,停在最早历史上看时每来一根新 bar 被推走一根。
数据源知道每根是谁时,把它发布出来,视口就按"最左那根的键"找回位置,数据怎么变都不跳:

- **数据源**:`Publish(new DataExtent(epoch, keys, olderExhausted))`。`keys` 每根一个、严格递增、与发布数组一一对应(单位自定,框架只比大小),每次发布一块新数组;
  `epoch` 用 `new object()`,整段替换(复权 / 换月:键没变、值全变)时换一个;`olderExhausted` 是数据源自己的到底判据。
  切合约仍走 `SwitchContext` 的空帧(长度归零 → 视口回首屏)。不发 `DataExtent` 的数据源一切照旧。
- **视口**:`ProjectExtent` 把它写进 `Viewport.Extent`;`ViewportManagerFeature` 在键与长度对得上时按键找回,贴右且末尾来了新键时跟随最新;
  裁决后把最左那根的键写进 `Viewport.AnchorKey`。跳日期调 `ViewportManagerFeature.ScrollToKey(key)`:目标居中,目标还没加载时先停最左、锚点留在目标上;
  切合约 / 切周期后数据还没到就调(恢复位置)也行,首个带键的帧到达时落位。
- **分页**:`DataPagingFeature.OnRequireBefore(key, count)` ——"键 key 之前至少还要 count 根",key 是锚点(跳日期时就是目标),count = 安全缓冲 + 左侧越界留白。
  拉不拉、一页多少、补空档都由数据源定;左墙从 `OlderExhausted` 换算。它在黑板锁内被调:**立即返回,拉取放后台,不在调用栈里同步 `Publish`**。与 `OnRequireDataAsync` 二选一。
- **增量指标**:`IncrementalComputeFeature.ExtentPort = Chart.Viewport.Extent`,前插 / 补洞 / 换纪元时清 state 重算,追加和改末根续算。

范例:[../Hevo.Charting.Tests/DocSamples/Paging/PagedSampleSchema.cs](../Hevo.Charting.Tests/DocSamples/Paging/PagedSampleSchema.cs)
(由 `DocSampleTests.PagedSample_*` 覆盖:拖进缓冲区回包后看的还是那几根、跳到未加载的日期补齐空档后居中)。

### 14. 可暂停生命周期 IPausable

**目标场景**：TabControl 切 Tab、窗口最小化、父容器 `Visibility=Collapsed`、虚拟化列表离屏等"隐藏但未卸载"的情况，Schema 应自动冷冻所有后台流（请求管线、心跳定时器、Push 订阅），不占 CPU/网络。

#### 14.1 契约

```csharp
public interface IPausable
{
    bool IsActive { get; }
    void Suspend();   // 幂等
    void Resume();    // 幂等
}
```

`Dispose` vs `Suspend` 语义完全正交：前者是**永久终结**，后者是**可重入冻结**。

#### 14.2 三级冷冻（全自动，业务层 0 改动）

| 层 | 实现 | 效果 |
|---|---|---|
| **Workflow** | `WorkflowEngine<T>.Subscribe` 返回 `PausableSubscription`（IDisposable + IPausable）；`CompositeDisposable` fan-out；`Workflow.Interval` 返回 `IntervalSubscription`（真·异步闸门） | `Interval(1s).FetchExclusive(...).Subscribe(...).OwnedBy(this)` 链自动冻/解到根源定时器 |
| **DataSource** | `DataSource<TSource,TItem>` 实现 IPausable(暂停内部 trigger);`ReactiveDataSource` 额外拆 / 重建请求管线;Resume 时 `OnResumeRepublish` 钩子补推当前快照 | Suspend 中断在途请求;Resume 补推快照让 UI 瞬间回满 |
| **Schema / Feature** | `ReactiveSchema.Suspend` 自动遍历 `_disposables.OfType<IPausable>()` + 级联到所有 Feature；两层都有 `OnSuspend / OnResume` 虚钩子 | 子类只在**必须**手动管理的特殊状态（非 IPausable 外部订阅、自建 CancellationTokenSource）才重载 |

#### 14.3 UI 层触发

`ChartCell` 构造函数挂三个事件：

- `Loaded / Unloaded` —— TabControl 默认行为的**主要**触发点（非激活 Tab 的内容被移出 visual tree）
- `IsVisibleChanged` —— 父容器 Collapsed / 虚拟化离屏
- `Window.StateChanged → Minimized` —— WPF 最小化不改 `IsVisible`，单独挂 Window

无论业务层用 `ChartHost + Schema` 还是 `new ChartCell { Template = schema }`，都自动生效。

#### 14.4 长时间暂停的 Resume 补刷策略

Resume 时框架只补推**已有**快照。暂停期间产生的新数据需要业务侧补拉:在 Schema 的 `OnResume` 里调数据源的 `RefreshAsync()` / 重新请求。

客户端**不能**按周期估算"隔了多少根 K 线"(节假日、午休、停牌都会让估算失准)。正确做法是按时间范围请求 `(最后一根已知时间, 现在)`,让服务端返回实际存在的 K 线。

#### 14.5 业务层约定

- **绝不**手动管理 CancellationTokenSource 来暂停 `Workflow.Interval` —— 基类已经通过 `IntervalSubscription` 自动处理
- **绝不**在 Schema 的 `OnSuspend` 里调用 `_dataSource.Suspend()` —— 基类已经级联
- 只有在 Schema 持有**非 IPausable**的外部资源（如 WPF 级别的全局事件订阅）才重载 `OnSuspend / OnResume`

### 16. 性能保护与脏检查机制 (Dirty State Management)

明确 `IsDirty` 的生命周期，防止无效渲染。

---

#### 16.1 自动脏标记规则

| 触发类型 | 条件 | 行为 |
|---------|------|------|
| **本层 Trait 唤醒**(深度睡眠) | 还没录过的图层收到第一份发给本层(`ctx.For(layer)`)的 Trait | 第一次录制;之后按下一行判脏 |
| **Trait 驱动脏** | 图层上次 `OnUpdate` 读过的 Trait(本层或共享作用域)换了引用 | 帧提交时按引用比对,换了就重录;值相等的新对象也算变 |

**深度睡眠**:可以把图层看成 WPF 的 View,`OnUpdate` 是它的模板,发到本层的 Trait 就是它的 ViewModel(DataContext)。往本层发 Trait(Feature 在 `OnProject` 里 `ctx.For(layer).PublishData`,或者用挂层 API 返回的代理喂)= 设置 / 更新 DataContext,这才触发渲染;没有 DataContext 就什么都不画。共享 Trait(绘图区、比例尺策略、共享 X 轴)像环境资源,View 会读,但它们本身不算 DataContext:变了只会让已经有 DataContext 的图层重画,不会叫醒还没有的。

所以图层挂上后先不录,哪怕尺寸变了、共享 Trait 变了也不录,直到第一份发给本层的 Trait 到达。这是有意的:第一次录制要过 `[RequiredTrait]` 的 fail-fast 校验,等本层数据到齐再录,不会提前唤醒而抛错或画出半成品。框架也刻意不提供 `Refresh()` / `InvalidateVisual()` 式的强制重画入口 —— 要重画就喂新数据。由此得出一条写法规则:**每个图层都要有人往本层喂至少一份 Trait**(数据或样式)。

喂数据的三条路:

- Feature 挂的层:在 `OnProject` 里 `ctx.For(layer).PublishData(...)`。`OnCompose` 里经 `AttachLayer` 返回的代理发的静态样式会存下来,但不唤醒图层,要等 `OnProject` 发的数据到。
- 不用 Feature、直接在 `ChartCell` 上挂:`cell.AddUnmanagedLayer(layer)` 返回的代理就是喂数据的入口,`PublishData` / `UpdateData` 任何线程都可以调,下一帧唤醒并录制,再喂就重画。范例见 `DocSamples/BareCell/BareCellSample.cs`。
- Schema 里的 `canvas.AddLayer(layer)`:只挂层和托管生命周期,不喂数据;还得有一个持有该图层的 Feature 在 `OnProject` 里给它发 Trait。

只读共享 Trait 的图层、挂了却没人喂的图层,会一直不画。哪些内置 Trait 是共享的、哪些要发到本层,见 06 号文档 §5.4。

Debug 构建下,图层挂上后 120 帧都没录出任何指令,会在输出窗口报一次(只写日志,不改变渲染):没被唤醒过的,提示上面几种原因和改法;唤醒过但没画的,列出 `OnUpdate` 读到却一直是 null 的 Trait,通常是发错了作用域。

---

#### 16.2 0 开销跳过 (Short-Circuit)

`ChartLayer.Update` 基类先做显隐拦截(`VisibilityTrait`),再做脏检查:`IsDirty == false` 时**跳过整个指令录制阶段**,不调用 `OnUpdate`。图层在 `OnUpdate` 里读过的 Trait 会被自动登记(`VisualDependencyTracker`),下一帧这些 Trait 的引用变了才标脏。

#### 16.3 版本令牌 (VersionToken) 与环境时钟

框架废弃了传统的 bool 标志位重绘。采用 `StateClock` 维护全局环境版本令牌（如窗口拉伸、主题切换）。在 `ProjectAll` 阶段，框架会自动比对 `_renderedToken` 与目标纪元。
业务 `Feature` 的 `OnProject` **不再需要（也严禁）手写环境判断逻辑。只要框架调用了你的 `OnProject`，就意味着当前处于“引脚数据脏”或“全局环境脏”**状态，开发者只需无条件信任输入并执行映射。
